# 顶层编辑流水线

世界级编辑的工作不是把每句话写漂亮，而是确保作者、事实、论证、读者和发布场景在终稿中形成同一条价值链。本文件定义新写或完整改写的顶层节点；`quick` 可合并节点，`standard` 执行主链，`deep` 执行全部适用节点。

进入 Node 0 前先完成 `intent-routing.md` 的四轴 route，并加载 `article-workflows.md` 中唯一主 family。顶层节点提供共同治理，family workflow 提供不同的生产主轴；发生冲突时，事实/权限门禁优先，随后由 family 的 reader job 决定结构。

## 总原则

```text
高质量文章 = 值得回答的问题
             x 可辨认的作者判断
             x 可追溯材料
             x 成立的论证与结构
             x 对目标读者有效的表达
             x 改写后仍保持的事实与伦理边界
```

任何一项为零，文句再流畅也不能补偿。后段发现错误时返回拥有该错误的节点，不用润色遮掩。

## 0. 委托与权限

确认 route、operation、depth、主 article family、交付物、文件写权限、发布/外部发送权限和最终决策者。`audit` 冻结为只读。用户要求成稿不等于授权发布、安装工具、修改个人档案或写入项目指令。

退出：任务边界、允许动作和完成定义明确。

## 1. 编辑 brief

确认体裁、渠道、作者意图、目标读者已有认知与真实阻塞、期望改变、作者立场、语气、字数/格式、时间、来源政策、个人素材和禁止项。把事实、有来源解释、作者判断、个人经历和待核实内容分开。

退出：能用一句话回答「谁要因这篇文章，在什么问题上发生什么改变」。

## 2. 选题与价值验证（按需）

仅当题目未定、需要比较方向或发布价值重要时执行。比较：读者问题是否真实、作者是否有独特材料或判断、证据是否可得、现有内容缺什么、为什么现在写、失败代价是什么。

热点、讨论量和模型评分只能作线索；拿不到可核查数据时定性描述。不要用“爆款概率”冒充事实。

退出：选题有明确 reader problem、作者优势、证据可行性与差异化；否则收窄或停止。

## 3. 上下文与作者素材

收集作者真实经历、观察、已有草稿、讨论记录、约束和授权声音样本。个人素材原样登记，不自动修饰。无个人素材时允许继续，但禁止虚构第一人称经历。

需要长期声音时走 `voice/train-voice`；用户可以跳过。未经验证的声音档案只作为低置信度方向参考。

退出：已知作者真正拥有的材料和不能声称的内容。

## 4. 主问题、立场与边界

把主题改写为可回答的问题，提出一句能被聪明人反驳的 thesis。明确理由、利害关系、最强反方、限定条件、不适用场景和明确不写的角度。立场用于形成选择，不用于制造敌人、虚构误解或情绪操纵。

退出：thesis 有信息量、有代价、有边界，并能承受最强反方。

## 5. 调研计划与证据账本

先列支撑或推翻 thesis 所需的问题，再检索。优先一手、当前和可定位来源；打开正文，不把搜索摘要当证据。记录成功、未找到和受阻的检索尝试，保留冲突证据。

每条可核查 claim 记录：ID、原子主张、类别、来源、发布日期/事件日期/访问日期、准确摘录或位置、可靠性、能支持什么、不能支持什么、状态。没有证据的内容降级为作者判断、观察或待核实标记。

退出：支撑核心论点的事实均已 verified、disputed、unsupported 或 stale，不存在隐性“研究表明”。

## 6. 分析与综合

区分材料和结论。为每个理由写出 warrant，判断证据是否真的支持结论；比较竞争解释、因果与相关、典型与个案、机制与表象。保留时间性、领域性和本质性矛盾，不强行调和。

输出 argument map：thesis、reader tension、reasons、evidence IDs、warrants、qualifiers、最强反方、回应策略、未知和排除项。

退出：论证不是来源堆砌，且结论强度不超过证据。

## 7. 编辑概念与读者承诺

确定文章给读者的核心承诺、独特角度和阅读后的价值：理解、决策、情绪命名、行动、讨论或工具。设计必要的情绪曲线和记忆锚点，但不得用虚构痛点、恐惧、低智读者或假故事换取注意力。

退出：每项“读者价值”都能指向真实内容，不是传播术语。

## 8. 结构与素材编排

每节定义读者任务、section claim、证据、warrant、与上一节的依赖、节奏功能和不重复内容。安排事实、场景、解释、反方与结尾；运行段落交换测试，消除可随意换序的平行摘要。

结构应服务思想：允许叙事、论证、对话、列表、短段和长段混合，但不为“反模板”制造随机性。删除有趣但不服务主线的材料。

退出：大纲能证明 thesis、兑现读者承诺，并清楚知道舍弃什么。

## 9. 标题与开头

在 thesis、证据和结构稳定后再设计。候选必须改变真实角度而非替换形容词。标题中的数字、人物、时间和结果必须来自证据账本；开头可以用判断、事实、真实场景、问题或冲突，但不得编造钩子。

`quick` 可直接选 1 个可信方案；`standard` 给 2-3 个；`deep` 可做候选赛，但用户或明确 owner 锁定最终选择。记录标题承诺与正文兑现位置。

退出：标题、分发文案、首屏和正文是同一个承诺。

## 10. 起草

从 argument map、结构和账本起草。未知内容保留 `[需要来源：...]`，不边写边静默补事实。每段完成可识别动作：主张、证据、解释、限定、转折、场景或后果。作者素材优先进入关键位置，但不为“个性”强塞所有材料。

草稿正文与内部备注分开。记录事实使用映射，保护引语、代码、术语和 evidence ID。

退出：形成可进行发展编辑的完整稿，不要求句子已精修。

## 11. 分层编辑

严格按顺序：

1. **事实预审：**拦截捏造、来源错配、过时信息和超出证据的标题。
2. **发展编辑：**主问题、thesis、论证、结构、遗漏、重复、节奏和结尾。
3. **读者编辑：**隐含上下文、术语、认知跳步、反方公平性和行动可用性。
4. **品味编辑：**选择、密度、具体性、张力、记忆点、克制与原创组织；读取 `editorial-taste.md`。
5. **声音与 line edit：**对齐授权样本，改句子和段落，不改变事实含义。
6. **copy/proof：**语法、术语、数字格式、引用、链接、排版和无障碍。

阶段记录使用以下 owner ID：`fact_review`、`development_edit`、`reader_review`、`taste_voice`、`copy_proof`。中文标题可以另列，但不改变 owner ID。

finding 必须有文本证据、影响、修复动作和 owning node。仅审查时到此停止；要求修改时只修获授权范围。

## 12. 去模板与事实回归

Humanizer 先诊断、后删除、再定点改写；检测分数不参与质量放行。改写前冻结数字、日期、姓名、URL、引语、代码、术语、范围、确定程度和因果关系。文件存在时，使用当前已加载 Skill 根目录的绝对路径运行 `"$EVIDENCE_FIRST_WRITING_SKILL_DIR/scripts/check_factual_invariants.py"`；根目录不可确定时记录 `factual_invariant_check: not_run`，然后人工检查脚本不能判断的语义漂移。

此节点不可与 Node 11 的事实预审合并。所有正文修改结束后，流程计划和运行记录必须显式包含：

```yaml
factual_regression:
  status: passed | findings_returned | not_run
  before_file: ""
  after_file: ""
  mechanical_check: passed | changed | not_run
  semantic_check: passed | findings_returned | not_run
  reason: ""
```

`passed` 需要机械变化已逐项解释，且确定程度、范围、主体、时间和因果关系完成人工语义核对。没有前后版本、Skill 路径或审查能力时只能写 `not_run`，不能由法务审查、copy edit 或起草前核验代替。

退出：没有实质模板簇，继续修改只会损伤事实、论证或声音；最终事实状态绑定当前标题和正文，而不是旧版本。

## 13. 读者、平台与发布包

用目标读者会提出的问题测试理解、可信度、最早弃读点、记忆点和行动入口。真正隔离的新审查者才称为独立读者测试。按公众号、知乎、Newsletter、技术文档等渠道调整标题、摘要、段落和格式，但不改变主张。

代理测试只定位风险，不预测 CTR、完读率或分享率。发布、外发、配图、HTML 和平台操作需要用户明确授权。

退出：正文、标题、摘要、引用和交付格式相互一致，未执行检查已披露。

## Deep 独立审查状态

`deep` 不自动等于已完成独立审查。只有在用户授权、宿主具备隔离 reviewer 能力，且 reviewer 只收到终稿、目标读者、任务问题和必要 rubric，而没有作者会话、推理过程、预期结论或已有 finding 时，才可执行独立审查。

记录以下状态之一：

```yaml
independent_review:
  status: passed | findings_returned | not_run | author_side_simulation
  reviewer_context: isolated | same_agent | unavailable
  reason: ""
  artifacts: []
```

- `passed`：隔离 reviewer 没有发现阻塞性问题，且结果产物可追溯。
- `findings_returned`：隔离 reviewer 返回问题；回到拥有该问题的节点修复。
- `not_run`：没有授权、能力、时间或必要材料；不能宣称已独立验证。
- `author_side_simulation`：同一 Agent 根据读者问题自检；只可作为内部辅助。

独立 reviewer 只审目标授权范围，不能获得额外写权限、外部发送权限或私人档案。审查失败不允许由 Humanizer 直接掩盖。

## 14. 复盘与学习（按需）

先比较初稿与终稿，提炼真实修改产生的规则；无差异就记录无可学内容，不自评分。发布后只记录与具体标题/正文/封面版本绑定的真实指标，区分观察、假设与规则候选。

单篇表现不能证明因果。复盘记录必须显式给出稳定的规则写入决策：

```yaml
stable_rule_update:
  status: none | hypothesis | candidate | promoted
  replications: 0        # 可比项目独立复现次数
  comparable_runs: 0     # 满足可比控制的项目数
  counterexamples_checked: false
  ledger: append_only
```

`status: promoted` 需要同时满足：`replications >= 2`、`comparable_runs >= 2`、`counterexamples_checked: true`。不满足时只能写 `none` 或 `hypothesis`，不得把规则写进稳定声音档案或标题公式，也不得承诺下次沿用。原始指标使用 append-only 账本，允许追加但不得覆盖历史版本。

`post-publish` 默认只分析，不持久写入。单篇结果只登记为 `observation` 与 `hypothesis`；没有曝光量时打开率标记 `not_available`。未获得明确写入授权和目标路径时，`persistence: not_run`，不得写入声音档案、记忆或项目文件。

## 深度裁剪表

| 节点 | quick | standard | deep |
|---|---|---|---|
| 委托、brief、权限 | 必须 | 必须 | 必须 |
| 选题验证 | 跳过/轻量 | 按需 | 完整 |
| 作者素材与声音训练 | 按需 | 按需 | 按需且验证状态明确 |
| 立场、证据、分析、结构 | 合并且风险优先 | 完整主链 | 完整并保留中间产物 |
| 标题/开头候选 | 0-1 轮 | 2-3 个 | 候选赛与 owner 锁定 |
| 分层编辑与事实回归 | 合并执行 | 分层执行 | 独立 reviewer 资格检查；不可执行时显式降级 |
| 平台测试、发布包、复盘 | 按需 | 发布时执行 | 完整且设计真实指标闭环 |

`quick` 不是低质量，它只在低风险时合并节点。任何事实密集、高影响或不可逆发布任务自动升级相应门禁。
