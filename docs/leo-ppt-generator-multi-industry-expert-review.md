# leo-ppt-generator 多行业专家评审：优化点分析

- 日期：2026-08-29
- 方法：10 位 PPT 顶尖专家画像（5 组并行评审 agent，各组直读 skill 源文件），覆盖商业咨询、金融路演、科技发布会、设计系统/品牌 VI、学术答辩、教学设计、政务党政、医疗制药、制造工程、AI 生成工作流架构
- 产出：58 条发现（P1×22 / P2×25 / P3×13），去重归类为八大主题；本文是汇总分析，未改动任何行为
- 与既有工作的关系：与质量回路优化（母版/波及复查/三级标注/多轮协议）和模版推荐计划（2026-08-28-001）互补不重叠——前者已解决"审查与修复回路"，本文聚焦"行业内容正确性"这一尚未建立的能力轴

## 一、行业内容规范轴缺失（六位专家共同命中，最大缺口）

风格库的 46 份行业文件**只有视觉身份，没有内容规范**——术语表、禁用词、必标项、表述惯例完全依赖模型自觉：

- 金融：无监管合规表述语料（前瞻性陈述免责、静默期、过往业绩声明）
- 政务：无党政表述规范（机关称谓、会议全称、领导排序、禁用词）
- 医疗：无疗效宣称红线（根治/治愈率/安全无风险）与获批/研究性四档用语区分
- 咨询：论证模式（金字塔等 5 种）只在选风格时用一次，逐页 prompt 不携带该页的论证角色（argument_role）
- 学术：无术语首现全称、引用规范约束

**统一解法**：行业风格文件增设 `content_rules` 节（术语表 + 禁词表 + 必标项 + 表述惯例），风格路由命中行业域即强制注入内容合同；`style render` 相应扩展内容规范注入。先做五个代表行业（金融/政务/医疗/学术/咨询）验证模式。

## 二、数字元数据合同（三级标注的深化）

三级标注（引用/估算/示意）只管来源等级，不管**数字的结构化元数据**。各行业命中：

- 金融：期间 + 货币单位 + 口径三件套缺一即失效；同比/环比无基准期间即编造（建议 `comparison_baseline` 属性）
- 政务：发布机关 + 数据年份 + 可比口径
- 医疗：p 值 / 置信区间 / 样本量 / 试验阶段（证据元数据），缺失禁止使用数据版式
- 学术：误差线 / n / 显著性标注的图表 schema
- 工程：SI 词头、千分位、有效位数、公差写法、同物理量全 deck 单位一致

**统一解法**：引用级数字绑定结构化元数据（来源/口径/期间/单位/证据等级），任何维度缺失降级 unknown 求证；对统计图建立硬性字段契约。

## 三、敏感数据与行业合规门（输入侧与成稿侧各缺一环）

- 输入侧：敏感拦截只覆盖凭据密钥；未公开经济数据、涉密统计、患者可识别信息（姓名/病历号/人脸影像）可直接进入冻结合同并上版。建议内容合同前加 `data_classification` 分级门（公开/内部/涉密）与 PHI 识别门，新 reason code 承接阻断。
- 成稿侧：五层质量门"内容事实"层不审行业表述合规。建议 visual-qa 对抗清单新增"违禁表述/监管用语"镜头（进多轮协议镜头池）：敏感词、领导排序错误、疗效宣称越档、伪造公文图元（红头/公章/文号列为 hard-forbidden）。

## 四、品牌 VI 与防漂移链路

- `style render` 无 `--brand` 参数，10_品牌身份 20 份文件（主色/强调/字体/语气）完全没接进确定性注入链；`deck_spec` 无 `brand_assets` 契约块承载真实 logo/HEX/授权字体及其用法规则（位置/最小尺寸/深底反白）。建议补 brand 注入与契约块，并复用 save_style 通道支持用户企业 VI 保存（`${LEO_PPT_HOME}/brands/`）。
- 防漂移只有"每 worker 附 1 张样张"，无量化拦截：建议 style render 固化"风格锚附录"（HEX token/字族/纹理逐字节注入），视觉门增加全 deck 末尾跨页一致性轮检（页 vs 样张 + 相邻页成对比较）；长 deck 每 5–8 页切换再锚定源（原样张 + 最近 accepted 同角色页）。
- 暗场全深色 deck（发布会场景）无系统支持：建议 `dark-deck` 预设变体（palette 推导规则 + 深底 ≥4.5:1 复检）。
- 可访问性全部后置人工 QA：建议 compose 阶段程序化对比度计算（不过即 fail-fast），图表轴注入色盲安全序列。

## 五、内容骨架确定性（"content render"）

质量回路已把母版立为内容真值工件，但母版仍是自由文本：容器清单/落位声明是否完备靠 worker 视觉自查。对应补全：

- 母版定义 JSON schema，派发前由工具校验"无点无家、无空容器"（落位检查从视觉自检前移为合同校验）
- 行动标题质检闭环（标题是断言还是话题词进 visual-qa）+ **标题连读稿**工件（全部标题连读=故事线，不成线打回母版）
- slide job 注入全 deck 术语表（canonical 实体名）与前后页标题摘要，assemble 增加跨页术语一致性检查
- 备注（speaker notes）扩为固定子字段：口播稿 + 预期听众疑问 + 互动/停顿指令 + 预计用时

## 六、版式与图型的行业深化

24 个版式对行业高频页型覆盖不足，专家组点名缺位（按频率）：

- 章节隔页（发布会节奏的骨架，现由 P1 封面兼任）、单一大数字冲击页、低数据 hero（0–1 个数据的一图流）
- 参数表 / BOM / 公差表版式（密集表格恰是图片模型最弱项，建议超过 N 行强制走 editable 原生表格）
- 瀑布/桥图（咨询与财务核心图形，语法与版式双缺）、2×2 矩阵版式、财务基本图形（柱/折线）
- 参考文献页型（学术）、免责声明固定页（医药/品牌）
- 教学三件套：学习目标页 / 小结回顾页 / 练习检测页（页面语义 20 类整体缺位）；先备知识清单与难度阶梯作为教学类合同必填
- 答辩 Q&A：预判问答页 + backup slides 机制（附录页不占正式页码）
- 发布会节奏序列模板（隔页→hero→特性→对比→数据冲击→recap）与路演 storyline 预设（市场→模式→财务→估值→风险→募资）

## 七、技术图与表格保真（工程行业专项）

- 工艺流程/架构/接线图靠图片模型徒手画，箭头标签错误率高且无兜底：建议确定性 `diagram render` 工具把 Mermaid/节点边 JSON 渲染为 strict input asset（通道已存在），图片模型只做风格化合成
- 单位制规范检查器（内容合同冻结步骤）；测试条件/边界工况纳入不可杜撰项；"图上无来源支撑的曲线"进对抗清单
- 高密度数据页（12+ 数据点）肉眼比对易漏：生成可机读期望值清单，OCR hints 回读逐格比对

## 八、评测与 backend 智能

- 现有评测全部是流程合同类，无"行业内容正确性"评测：建议补行业域评测集（流程图节点边完全性、表格逐格比对、单位一致性、表述合规各建 fixture），并纳入双评审官 rubric 的非视觉维度
- backend 选择只按 capability 过滤，无"任务类型 × backend 强弱"路由：按页型（图表/文字密集/图像）统计各 backend QA 一次通过率形成推荐表；prompt 按 backend 生成方言变体（长结构化 prompt 服从度差异）；image record 增加 token/重试计量支撑路线成本决策

## 优先级路线（建议三波）

- **第一波（多行业质量的杠杆最大）**：主题一（content_rules 先做 5 行业）+ 主题二（数字元数据合同）+ 主题三（敏感分级与合规门）——解决"内容对不对"
- **第二波（生成质量与确定性）**：主题五（content render/标题连读/术语表）+ 主题四（brand 链路与防漂移）+ 主题六核心版式（隔页/表格/文献/教学三件套/桥图）
- **第三波（工程与评测深化）**：主题七（diagram render/表格机读比对）+ 主题八（行业评测集/backend 路由/成本计量）
