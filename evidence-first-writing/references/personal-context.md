# 长期个人说明书

用于让 AI 在长期任务中了解用户稳定背景与协作偏好。它与 `soul.md` 不同：个人说明书保存长期背景、目标、价值观和协作规则；`soul.md` 只保存跨渠道表达特征。两者可互相引用，但不能混为一份无边界的私人数据集合。

## 访谈生成

先说明目标文件、用途、读取者和隐私边界。一次只问一个问题，围绕：基本信息与角色、当前工作、长期目标、代表性经历、价值观与判断习惯、稳定偏好、协作方式、敏感或禁止事项、喜欢和反感的表达。用户可以跳过任何问题，也可以随时停止。

只记录长期稳定且对协作有用的信息。今天的情绪、无关隐私、凭据和不必要的身份数据不进入说明书。不从外部账户或目录主动搜集。

建议结构：

```markdown
# 个人说明书
## 适用范围与更新时间
## 我的角色与当前重点
## 长期目标
## 代表性经历与已确认事实
## 价值观和判断习惯
## 工作与协作偏好
## 写作和沟通偏好
## 我不希望 AI 做什么
## 敏感边界
## 待确认与可能过期信息
```

生成后让用户审阅；用户确认前不得声称档案准确。说明书需要随真实反馈迭代，不从一次回答推导永久人格。

## 配置到不同宿主

- ChatGPT、Claude、豆包等聊天产品：提供适合其当前自定义指令/记忆界面的精简版本。涉及在线写入时使用对应官方能力并获得用户授权；不同产品之间不假定记忆互通。
- Codex 项目：仅在用户明确要求时，从说明书提炼与当前仓库相关的协作规则写入或更新 `AGENTS.md`。先读取现有文件，保留项目规则，不能用个人档案覆盖仓库事实。
- Claude Code 项目：同理写入或更新 `CLAUDE.md`，先读取现有文件并限制在当前项目。
- 普通写作目录：保留 `个人说明书.md`、`soul.md` 与渠道档案，并在项目说明中用明确相对路径引用。

写入前展示目标文件、将写入的字段和不会写入的隐私；获得用户明确授权后再执行。不得把完整私人说明书复制进公开仓库，优先引用本地私有路径或写入最小必要摘要。

## 验证与维护

新会话中用 3-5 个问题检查 AI 是否正确理解角色、目标、禁区和协作偏好。答错时修正文档，不靠在对话中重复补丁。记录更新时间；对可能变化的信息标注日期。长期未使用或维护成本大于收益时，缩减或停用，而不是继续堆积字段。
