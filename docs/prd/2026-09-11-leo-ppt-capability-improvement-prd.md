## 1. 背景

用户反复验证后指出：风格目录很多，但流程不能充分理解章节和页面内容、选择合适模板并生成高质量图文 PPT。核心成功标准是“内容被正确表达、模板确实适配、整册视觉一致、最终产物可用”。三层职责划分用于支撑这些结果。

本次选择**重建整套风格库的资产合同、分类索引和消费链，分批替换设计内容**：盘点覆盖全库，首批先交付高频场景的完整路径。现有源码、索引、主题和模板中能复用的能力继续使用；是否搬目录、合并或退役某个旧风格，以盘点证据和兼容要求决定。

## 2. 全局目标与非目标

### 2.1 用户与核心场景

主要用户是委托 Agent 制作管理汇报、晋升答辩、技术方案和教学演示的人。用户提供材料、受众、目标及可选的品牌/参考风格；系统先组织整册叙事和单页论点，再推荐视觉方案。用户可点名风格、纠正章节理解或修改某页，已有授权与协作方式持续有效，不新增逐页确认门。

### 2.2 目标与结果度量

成功路径：**材料与任务 → 整册叙事 → 章节内容模型 → 单页表达合同 → 合格风格/版式候选 → 唯一绑定 → 预览与样张 → 生成 → QA 与交付收据**。

| 结果层 | 需要证明的结果 | 指标与边界 | 属主 |
| --- | --- | --- | --- |
| 资产与执行正确性 | 推荐命中的是实际可用资产，执行没有换模板 | 全量库存归类率、首批场景覆盖率、无资格推荐数＝0、绑定一致率＝100% | R-85 |
| 内容与推荐适配 | 论点、证据和关系结构得到合适表达 | 冻结留出集上的合格候选召回、内容保留、语义错配；允许多个正确方案 | R-85、R-74、R-84 |
| 最终视觉质量 | 阅读层次、图文关系和整册节奏可用 | 真实导出页的盲评与缺陷协议，和工程检查分别报告；模型分数不能替代人工结果 | R-85、R-70、R-71 |
| 用户与资源收益 | 授权后少返工，费用与等待可预期 | 真实反馈—修订—再呈现周期、授权前后时长、完整收费调用成本；无观测报告 `not_yet_observed` | R-77 |

三层职责为执行分工：确定性工具保证身份、容量、绑定和事实；AI 提出内容理解与视觉表达；用户的实际选择或委托决定推进。**北极星＝约定生成授权后用户可见返工轮次**，免费路线使用相同生产授权边界；不得通过移动授权时点制造改善。R-77 波 1 先采集最小事件，真实收益在足够的可比较运行后单独验证。

### 2.3 方案取舍与交付范围

| 方案 | 最强理由 | 主要代价 | 本版裁定 |
| --- | --- | --- | --- |
| 只补提示词、别名和推荐文案 | 见效快，能复用现有大量资产 | 不能保证候选有实现，也不能防止预览与生成选择分叉 | 作为局部补充 |
| 全库一次性删除重做 | 能彻底统一设计语言和元数据 | 旧 run/用户引用失效，验证规模大，容易先重建大量未用资产 | 不作为切换方式 |

## 4. P0 需求

### R-70 组合页型转正（composite，分三子阶段）

**目标**：文字层与 `required_text` 白名单逐字一致，减少渲染转录错字；内容事实正确性仍由内容合同与数据账本负责。组合页适用于确有需要的数据/文本密集页，氛围/概念/封面可继续使用整页图像；视觉整体性和完整成本分别验收。

**先决（R-70 专属，不阻塞 R-85a）**：

1. R-77 完整 TF/成本基线支持投入决定；TF 很少或成本收益不足时登记缩围/关闭，不为已写合同强推 composite。
2. **统计协议预登记**：TF 和视觉分别计算样本量；TF 使用页级二元触发指标及配对/聚类方法，视觉使用成对评分差值，不能共用一个 N。同一 deck 内页相关，以 deck 为聚类单位，双判官不是两份独立样本；独立 deck 过少时报告证据不足。区间全文使用双侧 95% CI，目标效力、分层和权重在开始评测前冻结。
3. **视觉输入 spike**：验证当前宿主实际可调用的图片输入能力及备用通道，不用某 CLI 名称或安装状态证明可用。准备健康页与单缺陷副本组成的 `defect-controls` 校准集，登记源页/缺陷/哈希/预期判定。外部调用依照具体测试授权执行。
4. 冻结材料、受众、主题、事实和质量要求；生产方法为处理变量，对照基线 image/render 与 composite，并按基线 lane 分层。记录其他混杂因素和完整成本范围，确认 R-85 绑定与主题合同、R-71 预览和 U8 新鲜度接口。

**分阶段范围**：

- **R-70a 最小组合路径**：扩展现有 overlay 机制，接入离线字体、effective_theme 及对比度，支持明确的密集文本换行/锚点规则；TF-2 与正常 composite 分别登记。通过本阶段验收可独立交付，不宣称全册默认转正。
- **R-70b 模板级文字层**：3 类版式×2 主题的文字层/背景层合成，透明文字层输出、双 provenance 子记录；复用 R-85 中通过资格的资产，不再笼统称全部“资产从零”。合成产物全部进入既有指纹与内容绑定；手改文字层必须被拒绝。record 显式使用匹配 render receipt 的 backend。
- **R-70c 路由转正**：在已有 `page_type_regime` 上增加 composite 资格，扩展 worker brief、交付披露和默认路由；内容分类不增加 `render`。R-85 只在新能力验证后晋升对应组合，R-74 再比较成本；版本戳与消费方引用一起更新。

**合同修订面**：image-deck-workflow、SKILL.md、execution-contract、render-contract、sources-manifest schema、reason-codes、visual-qa 及收据。保留既有 SAMPLE-GATE，不废弃纯图像页，不建设 HTML-to-PPTX 编辑器；按阶段保持可独立恢复。

**验收**：

1. 【单测＋实际渲染】白名单逐字一致；3 版式×2 主题无超界、拉伸或丢字段；错误文字和手改任一合成层应被拒绝；数值/单位/口径由数据账本独立校验。
2. 【判官-fixture＋人工-协议】同内容成对比较，`差值＝新方案评分−对照评分`，以 deck 聚类的平均差值 95% CI 下界 ≥−0.5 才支持非劣；融合度均分 ≥3/5，任一判官该项 ≤2 或人工发现严重缺陷即否决。覆盖文本密集至少两层和氛围对照一层，规模由视觉效力设计确定；缺独立样本不能用重复打分补足。校准失败的 VLM 不作主判。
3. 【run-留痕】a 门＝构造性正确、阶段视觉验收、同内容每页/整册总成本不高于基线；成本使用 `cost-caliber-v2`，含收费失败与重试，不计算 `attempts × 已累计 tokens`。b 门＝全量组合回归及视觉验收；c 门＝默认路由、兼容与下列效果度量。
4. 【回放集-proxy 或真实对照，分别标注】`RR＝新方案 TF 触发率/基线触发率`。本版目标为下降至少 80%，支持该声明需 RR 的 95% CI **上界 ≤0.2**；上界仅 <1 只能称存在下降，不能称下降 80%。双方均零只称未观测到事件；基线为零时相对降幅不可识别，另报绝对风险；观测不全或样本不足时度量门不通过。构造性文字正确可独立验收，不能据此宣称比例收益。
5. 【真实用户观测】样张重确认与用户返工按 `rework-caliber-v1` 观察；回放只验证事件计算，不能验收用户感受。无可比真实数据报告 `not_yet_observed`，不包装为“授权后返工下降”。
6. 【单测＋run-留痕】旧 run 恢复与 U8 `verify_design_freshness` 消费通过；绑定或主题变化使相关产物失效。阶段耗时实测并在进入下一阶段前冻结预算。

**止损**：依 §3 和 §9.1 执行；a 未通过即为未通过，不能因已投入成本保留“通过”状态。

### R-71 全册确定性预览（样张门同轮；波 1 排序 3）

**目标**：SAMPLE-GATE 同轮提供全册零 token 预览，分页/版式/密度类返工在付费授权前暴露；审阅负担有预算、**首屏 30 秒内可得决策要点**；授权后此类返工不上升。

**范围**：母版→全册预览批量编排 CLI。**缺口六项**：①编排 CLI 命令 ②消费 R-85 已持久化的有效绑定及其摘要，不再重选模板③`<run>/previews/` 目录约定 ④增量重渲集成 ⑤U3 契约版本入 sidecar ⑥**批量渲染性能路径**（render_page 每页独立起字体服务＋启停 chromium，实测 1.26–1.30s/页，40 页顺序≈51s 叠加 40×42 候选资格检查后 ≤60s 无余量；需编排级浏览器/字体服务复用＋失败重试与部分成功语义＝新组件工作）。未选定绑定页先由 R-85 产生合格默认绑定（D-3），预览缓存按该绑定与内容 hash 命中；不得改用另一个更便宜的模板；"低精度骨架"标注＋骨架 vs 成品对照页（锚点覆盖默认绑定页）；材料预算与渐进披露（首屏缩略总览＋风险页标注，逐页下钻可选；预览与样张并行生成）；移动端形态（响应式单文件，联系表 PDF 可选导出）；**路径三分收敛口径（v1.6 定）**：`reports|final/render-preview/**`＝成品渲染预览（**在** `render_previews` 指纹内）；`<run>/previews/`＝骨架预览（**不在**任何指纹类内）；`<run>/diffs/`＝R-78 拼图（**不在**）；composite 页显示"背景占位＋文字层"。

**非目标**：预览不冒充成品保真；不做预览编辑器（修订走母版通道＋R-76 回显波及面）；不要求单独"已看过"确认（同轮呈现＋授权即视为已呈现）。

**验收标准**：
1. 【单测】三档母版成册 ≤60s——**40 页性能 spike 为开工门**（不可达则先做性能路径或调整阈值并留痕，禁止直接调大）；零**外部** API 调用（localhost 字体服务豁免）；页集合＝母版页集合（按各自目录命名空间断言）；改 1 页仅受影响页重渲；同 `design_digest`；
2. 【单测】首屏材料预算（缩略总览＋风险页标注缺失＝FAIL）；**首屏生成 ≤30s**（超出如实标注并披露）；骨架标注与对照页存在；
3. 【evals-proxy＋run-留痕】同轮语义（未呈现即派发＝FAIL；因预览多问一轮＝FAIL）；
4. **【回放集-proxy】**验证冻结母版的容量/版式错配是否被预览暴露并记录页级证据；**【真实用户观测】**授权后修订轮次按 R-77 固定窗口另行对照，无数据时 `not_yet_observed`，回放不能替代用户收益；
5. 【人工-协议】移动端可用性抽查（**协议落盘路径随本条交付**）。

**依赖与触点**：R-85 有效绑定及母版 schema、canonical 模板/dashi U3、compute_impact；与 R-70 串行；R-71 只拥有预览产物 schema，控制台 serve 入口见 §7。

**预期用户影响**：付费生成前可查看全册布局风险；实际理解改善、等待与返工变化须通过观测确认，并行生成本身不保证等待不增。

### R-85 内容驱动的风格库重建（R-85a 首批闭环 / R-85b 全库迁移）

**目标**：让同一份材料得到清楚的章节论证、合适的单页表达和真实可执行的设计。整册默认保持一个主风格；章节与页面选择内容表达、版式和组件变体。用户明确要求的章节风格差异作为已授权例外记录，不能由系统任意换主风格。所有新字段/产物均为需求，除 §1.5 明确核验者外不声明已实装。

**R-85a 首批交付范围**：

1. **全量盘点、按职责重新组织**。读取 canonical 与当前 catalog/resolver 的真实覆盖，登记原始资产数、唯一身份数、别名、重复、冲突、来源不明、缺模板和缺 token 的数量及分母。区分视觉风格、版式、renderer 模板、组件、行业约束、场景预设和示例资产；用引用组合，避免同一配色换标题就算新风格。已有混合 brief 可兼容读取，但不直接进入自动池。
2. **内容分析合同**。整册记录受众、目标、主张、叙事顺序、主风格和品牌限制；章节记录 `chapter_id`、论证任务、关键结论、证据及来源、前后承接；页面记录 `page_id`、一个主论点、`required_text`/数据账本引用、语义结构、图文作用、容量需求、置信层级和依据。基于内容结构理解“比较/趋势/因果/流程/证据”，关键词仅作补充；信息不足标 `undecided`，不得虚构数据或关系。
3. **可执行设计合同**。沿现有 brief/schema 增量扩展，必须可解析到稳定身份、scope、版本、source/path/hash、palette、语义字阶、字体与 fallback、间距/网格、组件变体、适用与禁用场景，以及版本化 layout/template 或 image recipe 引用。容量仍由布局真源提供，runtime 资格仍由 renderer/provider 提供，风格索引只引用和验证。render 方向验证 effective_theme 被消费；image 方向验证 prompt 投影和真实样张，不能要求每个 image 风格都绑定 HTML。首批 image recipe 必须提供确定性骨架投影所需的布局/槽位声明；预览从同一绑定生成占位图文，不重选布局。缺此能力标 `preview_unsupported`，不得计入 R-71 全册覆盖。
4. **索引和状态管理**。从 canonical 生成唯一 catalog generation；名称/别名用于查找，受众/场景/密度/表达结构/能力分面用于候选检索。状态互斥：`unknown`＝无法核实；`legacy`＝可解释但未满足新自动池合同；`executable`＝至少一个明确版本组合已通过准入；`retired`＝退出新任务选取、仅保留旧版本回放。状态按资产标记，推荐资格按 `(style version, layout/template 或 recipe, lane, 内容边界)` 验证；“某风格有一个可用示例”不能推出它的所有页型都可用。
5. **联合选择与实际执行一致**。先解析实际作用域和用户覆盖，再过滤来源、能力、容量及明确禁止项，随后排序内容适配、场景/审美和整册节奏；复用 `suggest_layout`/`layout_selection` 的现有能力形成同一排名契约。局部 top2/top3 与整册优化结果可以不同，但最终 trace 要记录全局配额、相邻重复等导致的调整。并列允许存在，稳定 tie-break 不等于语义更优；不依赖 ID 序冒充推荐分数。
6. **有效绑定与变更**。每页持久化 `effective_binding`（style/layout/template 或 recipe/lane/版本/内容与主题 hash、selection_mode），供预览、生成、QA 和收据消费；该 run 主动采纳新 generation、应用用户风格修订或修改内容时，计算影响并使相关旧绑定失效；仅发布新版不改变已冻结 run。旧资产字节被手改或不可读取时拒用失效绑定，不静默换新版。默认展示最多 3 个合格方向，不足时不凑数；无合格候选报 unsupported 并给具体缺口及保留内容的替代建议。委托模式在已有授权内选择并留痕，不把低置信强制变成新增确认门。
7. **首批可用资产矩阵**。本版建议首批 3 个主风格族（克制商务、技术图解、教学叙事）×10 类任务：封面、章节过渡、论点/并列、KPI、比较、趋势、流程/架构、证据、表格、收束。每格至少一个已验证实现或 recipe，可复用模板与组件；并不要求新建 30 个模板。每格登记典型/容量边界输入、真实渲染示例、来源 hash、可用 lane 和验证结果。30 格全部闭合才称首批覆盖完成；无法覆盖须显式修订范围，不能从分母删除。整页 image 和 render:html 的结果分层报告，未验证的 lane 不得宣传可用。

**R-85b 全库迁移范围**：每个旧风格都要有“保留并升级/合并为别名/退出新任务/仍待核实”的可追踪处置；重写的重点是设计资产与示例质量，数量可减少。按使用场景和缺口分批发布 catalog generation，不覆盖旧 generation 和用户目录；合并别名有唯一去向，冲突需要消歧。新 run 选新 generation，旧 run 固定旧版本；同时保留索引和其引用的资产字节/可核验快照，批次失败可切回旧 generation。盘点完成＝100% 旧身份有记录；迁移完成＝每项已升级、已合并或已明确退出新任务。`unknown`/仍待核实必须标为迁移未完成，不阻塞已通过批次或 R-85a；新加入资产不得自动继承验证等级。

**质量与事实边界**：

- 点名/参考风格优先于审美推荐，不能越过缺实现、容量或来源等事实约束；同名 user 覆盖优先，必须核对实际 `source/path/hash`，不得用 builtin 摘要替代。
- 分离工程样例、视觉参考和已按协议验证的展示样例。哈希锁定只证明内容未漂移；schema/lint/溢出检查通过只证明工程条件，不能自动晋升视觉等级。
- 视觉评审检查标题与支撑层级、图表字号和标签、对齐和留白、信息密度、图片是否支持论点、全册节奏。空白率是诊断量，不能以“填满”通过验收。
- 数据页必须保留单位和统计口径；不同单位（应用数/CPU 核/内存 GB）不能直接共用量纲不明的比较轴。可以分面或显式归一化，同时保留精确值；图像不得充当无来源的事实证据。

**验收（以下数值为本版建议目标，实施评测前冻结）**：

1. **资产与资格**【单测＋本地渲染】：全量清单逐字节可重建，唯一 ID/来源/状态可核验；首批矩阵 30/30 有版本化证据。缺 token 消费、坏 hash、无实现、用户同名覆盖、重复别名和未知 lane 的负例全部阻断错误自动推荐。`legacy/unknown/retired` 自动入池数＝0。
2. **内容与推荐**【回放集-proxy＋人工-协议】：冻结至少 60 页、6 个独立整册案例，覆盖 10 类任务且每类至少 4 页；设计样例与留出案例按 deck 分开。人工标注的是可接受表达集合与禁止项，允许多种正确版式，不以旧推荐器输出当真值。支持域留出正例的有解覆盖率 ≥90%；在有解页中 top3 命中可接受集合 ≥90%，被选方案语义合格率 ≥85%，三门同时满足。必须同时报告全目标页的有解覆盖率、拒答率及各类结果；无解负例使用独立分母，不得把推荐失败事后改标域外/无解。无解/证据不足负例须显式解释，不得静默缩字号、删关键事实或套列表。
3. **整册质量**【人工-协议＋判官-fixture 辅助】：固定同一材料、受众、品牌约束与 lane，比较旧链路和新链路的最终导出页及整册缩略图，顺序匿名化。至少 3 册，每册 10–14 页；内容主张/数值/单位/来源无新增错误，截断/重叠/不可读图表等严重缺陷为 0。人工按内容适配、阅读层次、图文有效性、整册一致性四维 1–5 分评判，每册四维均 ≥4，至少两维优于旧链路；若旧链路已全维 ≥4，要求四维不退化并满足新增场景覆盖。保留页面证据和判读理由；单人结果仅称协议内验收，不外推普遍偏好，VLM 分数单列。
4. **实际消费**【单测＋run-留痕】：上述至少 3 册贯通实际 resolver、生成和导出；R-71 接入后覆盖预览→生成→QA→收据。同页有效绑定一致率 100%；至少覆盖一条 render:html 与一条实际 image 路径，缺任一路径仅报告该路径未验证，不能验收双 lane 覆盖。手改绑定源字节须被拒绝；run 主动应用新主题/用户风格、内容变更或调整全局配额只重算受影响范围。单独发布新版资产不得改变固定旧版本的 run，必须验证其仍可恢复。
5. **迁移兼容**【单测＋run-留痕】：新索引发布、旧 run 恢复、别名冲突、批次回滚、用户覆盖不被改写均有正负例；R-85b 每个批次通过同类验证。未通过新准入的旧资产仅在原版本上下文恢复，不自动获得新任务推荐资格。

**例：晋升答辩量化成果页**。章节任务是证明收益，而非堆积指标；主风格沿用整册。可接受表达包括 KPI＋分面比较＋口径说明，也包括强调同一结论的表格＋图解。必须保留“直接节省”和“净节省”的不同口径与不可相加关系；不能因模板只有三个槽删掉说明，也不能为了多卡视觉把无关图片塞进数据页。

**依赖与验收拆分**：R-85a 先独立验收内容、推荐和实际生成；与 R-71 的联合回归在 R-71 交付时完成，避免循环开工依赖。R-85b 不阻塞首批闭环，R-77 负责统计，R-84 后续补充图表构思评测。视觉材料生成与真实 provider 调用按具体运行授权执行，本次 PRD 优化不包含这些调用。

## 5. P1 需求

### R-73 required_text ↔ OCR 对齐硬门

**目标**：文字错误在 `image record` 前机械拦截；visual-qa 逐字对齐职责移交（合同同步修订）。

**先决**：**generate 页图 OCR 探测通道一条龙**（复用 `paddle_text_hints.submit_and_fetch`（接受任意页图路径）＋`text_blocks_to_lines`（可独立调用）→ `lines[].text` 拼接 → 落 OCR_DIRS `page_<N>.txt`；约 100–150 行＋token/网络/超时/成本披露）。**builtin-ink 为纯几何检测不能读字，不可作对齐数据源**；**无 token 环境**：门显式 not_run/skip 并披露，校准集用离线 fixture 替代。scope 门：图像 lane 实质文字页占比 <15%（或以实测分位裁定）⇒ 范围降级或关闭并留档。

**范围**：适用页集＝仅图像 lane 整页生成页（composite 文字层由 R-70 构造性断言保证，不做 OCR 重复校验）；门作用域由 provenance sidecar 判定（禁用路由启发式判域）；对齐断言（阈值可配）＋豁免清单；新 reason code；校准集在 R-70c 后按届时页型采集（盖 regime 版本戳）；**blocked 页三口径统一**（随本条写侧契约修复——债8）。

**非目标**：不替代 visual-qa 语义判读；不适用 editable 与 composite 文字层。

**验收标准**：
1. 【人工-协议→单测】校准集（干净页 ≥60／红例 ≥30；未达如实报实测与 CI；校准/验收分集；页图＋OCR 输出冻结 fixture）；红例 100% 拦截、误报 ≤5% 达标才 WARN→阻断；
2. 【单测】阈值/豁免红绿；旧 run 恢复兼容；控制台页态推断回归用例（含 blocked 口径统一断言）；
3. 【run-留痕】误报复检在交付披露标注；WARN 期 OCR 算力成本入披露汇总；
4. 【单测】职责移交判据：visual-qa 对应清单同步修订（逐字对齐从目视职责中移除）。

**与 R-70 对冲**：转正越成功适用域越小——scope 门即对冲显式化。

**用户净影响**：错字更早拦截；误报有披露不黑盒。

### R-74 页型路由优化器（双轴）

**目标**：按"文字密度 × 视觉权重"输出 lane 方案（含 composite lane）与成本对比。

**状态**：`page_type_regime` v1 与脚本意图路由已有实现（§1.5）；本条扩展 composite lane、费用维度和评测。R-85 负责内容适配和联合选择，本条只在其合格集合内比较 lane 方案，不复制语义排名器。

**范围**：可解释路由扩展，消费 R-85 的联合排序和有效绑定；lane 成本对比（**新增能力**——`estimate_run_cost` 现不读 backend，per_type_stats 扩 lane 维度）；backend 生产记录去 `"fixture"` 缺省；内容分类与 lane 正交，和 R-77 协同；呈现经 R-76（推荐默认＋一句理由；冷启动置信分层——ground truth 未达阈值前用"规则建议（未经本地数据验证）"措辞，规则先在回放集离线验证）；evals 翻转用例登记；氛围页守护规则（视觉权重高档页默认图像 lane，成本对比不得以该类页改道）；图表容器经 3a 分发语义不回退断言；**排序保真断言**：归一化或 clamp 不得抹平原有语义偏好；构造其他条件相同、明确首选优于回退的 fixture，要求序关系保留。真实等价候选允许同分，不能把所有 tie 都判成缺陷。

**非目标**：不自动切换冻结 backend；运行中变更必须走已有修订通道，更新页级 provenance 和绑定，并重新计算样张失效范围。

**验收标准**：
1. 【单测】路由确定性；图表分发语义断言；**去饱和红例（明确不等价候选被 clamp 抹平成同分 ⇒ FAIL），等价候选同分允许**；
2. **【回放集-proxy】**ground truth：(a) 新建 lane 标注集或 (b) 历史回放（登记幸存者偏差声明）；与独立标注的可接受 lane 集合一致率 ≥70%，且资格/事实硬约束违规＝0；未达阈值为 not_passed，逐条归因不能替代通过。fixture 可重跑，声明样本覆盖、拒答分母、R-85 排序及 regime 版本；旧推荐器仅作对照，不作为 ground truth；
3. 【单测】成本对比与 backend report 对账口径一致（**口径版本号写入 `references/metrics-registry.md` 与 `estimate_run_cost` 的 `--caliber` 输出字段，双向引用**）；【evals-proxy】呈现验收（简报缺"推荐默认/规则建议＋理由"＝FAIL；R-76 延后时降级 CLI 报告并声明）。

**用户净影响**：一句话可采纳；成本更可预期。

### R-75 版式重排提案

**目标**：容量硬超时给出带依据的"候选版式＋要点减法"菜单（≤3 候选），人做选择。**剩余定位**：R-71 成功后本条价值收窄为"运行中新发现/残余 overflow"；建议器输出兼作 R-71 风险页标注的"为何 risky"解释（一份基建两用）。

**范围**：容量档位建议器（overflow 数据 → 候选清单＋减法方案含字数测算）；候选 ≤3、每项一句话代价（减多少字/版式怎么变/对叙事影响）、默认标注首选；经 R-76 呈现（R-76 延后时降级 CLI 报告形态并声明）；**提案落点字段须在母版 schema 冻结前提交（§7）**。

**非目标**：不自动应用（应用走母版修订＋post-confirm）；不缩字号（既有红线）。

**验收**：
1. 【单测】注入 overflow fixture 全给出 ≥1 可行方案，且闭环断言：应用提案后 `check_deck_geometry --capacity` 复检通过；无可行方案时如实报告并给替代路线建议（硬凑不可行方案＝FAIL）；
2. 【单测】提案确定性（同输入同输出）；候选 ≤3＋一句话代价＋首选标注（缺失＝FAIL）；
3. 【evals-proxy】呈现验收：存在待决 overflow 时决策简报缺提案字段＝FAIL。

**用户净影响**：决策从开放式变菜单式（≤3 选项＋代价一句话），理解成本受控。

### R-76 决策简报（变更—代价视图）＋呈现/披露合同属主

**目标**：六个推进节点（合同/大纲/母版/视觉方向＋样张/PARTIAL-GATE/DELIVERY-GATE）向人呈现三行固定摘要——①变了什么②影响什么③需要决定什么；**非技术用户可读**；并作为全批呈现/披露合同的单一来源。

**范围**：节点模板；**用户语言强制项**——术语白名单/通俗改写规则（如"失效工件"→"之前确认过的样张需要重新确认"）、单行长度上限、清单字段强制"计数＋页码区间"（"第 3、7、12–18 页，共 9 页"，完整清单按需下钻）。**呈现合同属主**：统一材料预算、渐进披露规则、披露工件 schema（拼图/alt 清单/拦截标注等不进五类指纹）、"呈现层缺席→生产者降级 CLI 报告"通用规则——R-74/75/78/79 只断言内容字段存在与正确，格式类 FAIL 统一挂本条。一期由 Agent 按模板成文，二期脚本化聚合（依赖 R-70/R-74 合同修订落地顺序）。

**非目标**：不代人决策；不把简报变成新工件门；不新增确认轮次。

**验收**：
1. 【evals-proxy】六节点三要素齐全（缺任一＝FAIL）；违反用户语言强制项（超行/裸清单/白名单外术语）＝FAIL；
2. 【单测】不许编造：波及页数/失效结论与 `compute_impact.py` 及合同规则一致（负例：数字不符＝FAIL）；
3. 【人工-协议】理解性抽查：非技术读者读完能正确说出决策点与代价（**协议落盘路径随本条交付**）；
4. 【evals-proxy】豁免场景（委托执行）简报仍生成、仅呈现被豁免（user-delegated 留痕口径）。

**用户净影响**：每节点少读（计数＋区间）、读得懂（白名单）、决策点唯一。

### R-77 运行质量记分卡与指标注册表（波 1 最小度量）

**目标**：提供同源、可对账的质量、成本和返工观测，分开“机制可用/数据充分/效果达标”。不把历史缺采集当作没有失败，不以度量基建阻塞不依赖该指标的内容优化。

**交付物**：`scripts/run_quality_scorecard.py <run>` 默认只读输入并向 stdout 输出 JSON；显式 `--out` 可写 `<run>/scorecard/quality-scorecard.json`，不得写入 `reports/` 或交付输入。指标真源为 `references/metrics-registry.md`，每项记录 `metric_id/formula/source/caliber_version/consumer/missing_policy/observation_window/evidence_level`。backend report 和控制台复用同一聚合，或通过同源 fixture 严格对账。

**波 1 最小范围（四项）**：①TF、收费调用与返工事件的最小采集 schema；②注册表和聚合器；③固定内容/回放资产及基线报告；④旧 ledger 混合行容错（债5）。推荐排序和绑定持久化由 R-85 负责；学习建议、长期趋势等属波 2。

**统一口径**：

- **TF（`tf-caliber-v2`）**：`generation_method=image|render|composite` 与 TF-1/TF-2 纠错事件独立；正常 composite 不是 TF-2，触发 TF-1 后成功也不能抹去事件。采集由既有写方扩展加性 sidecar，记录稳定事件 ID、page、阶段、观测窗口与来源，不手补 canonical entry。
- **缺失与分母**：在选 lane 前冻结目标页集。K＝已触发至少一次的页，N＝完整窗口确认未触发页，U＝观测不足页；页级去重触发率 `K/(K+N)`，同时报覆盖率 `(K+N)/(K+N+U)` 和全目标范围 `[K/T,(K+U)/T]`（T＝K＋N＋U）。事件次数另列。T＝0 时为 `not_applicable`；没有完整观测证据不能登记 N。manifest 的 `source_class` 只佐证生产方式，不能单独证明 TF 事件；核心前后比较覆盖不完整时度量门不通过。
- **成本（`cost-caliber-v2`）**：实测成本按稳定真实调用标识去重，累加可核验收费记录，包含收费的失败调用与重试；估算成本另列。token 换算必须区分输入/输出/缓存/图像等计费类型和单价版本、币种、单位；已有总用量不得再乘 `attempts`。现有 sidecar 缺真实调用唯一 ID，需增量扩展；历史记录只有能回查唯一调用时才参与实测，不按时间相近或同页猜测去重。跨页调用按预登记规则分摊，逐页和＝整册和；零外部调用的 render 页可报 API 费用 0，但本地耗时/算力另列。
- **成本缺失**：缺用量、计费类别、价格或调用身份，报告已知费用、覆盖率和 unknown 项；不得把 unknown 算成 0。必须费用记录不全则成本门 `blocked`。所有方案使用相同费用范围；生产必需 OCR/重试不可漏计，开发期盲评费用单列。`estimate_run_cost` 只提供估算区间，不冒充账单；R-70 页级成本与 R-74 lane 比较均引用本口径。
- **返工（`rework-caliber-v1`，波 1 即采集）**：一次真实反馈→修订→重新呈现计一轮，同一反馈涉及多页仍是一轮，波及页数和内容/风格/版式/错字原因另记。内部重试、自动 QA 修正和模型代审不计用户返工；记录生产授权前后阶段与固定窗口。未完成、取消、没有反馈、观测未结束分别报告，不能自动算零。仅采集必要事件身份/原因枚举和内容摘要 hash，不复制业务正文。
- **回放集**：固定母版、required_text/数据账本、章节/页表达标注、原始页图和有来源的事件记录，登记各项 sha256；来源为构造的事件明确标 synthetic。R-77 首次交付只含独立可构造的材料、原始页图、已有事件和聚合 fixture，不等待后置模块。R-85/R-71/R-70 完成时分别追加适配标注/预览缺陷/降级对照的新版本；消费者固定引用对应 hash，不回写已冻结基线。冻结图像和构造事件仅验证聚合/识别，不能凭回放推断用户会更少返工。
- **完整范围**：记录样张接受、预览拦截、绑定变更、图表 QA、恢复、调度告警及同内容重复 run；推荐 tie 比例仅为诊断，不以无 tie 代表质量。缺失写 `unknown/not_recorded`，不自动回写配置或训练权重。

**验收**：

1. 【单测】入口可被既有运行器发现；默认运行前后输入目录及五类指纹完全不变；显式输出只新增允许文件，`receipt verify` 仍有效。空 run、中断 run、混合 ledger 行有可观察回归。
2. 【单测】10 页正常 composite 不能得到 TF＝100%；历史无事件字段不能得到 0%；TF-1 后成功仍计触发。K/N/U、重复事件与空分母按公式计算。
3. 【单测】同一调用重复登记不重复收费；已记录总 tokens 不再乘 attempts；收费重试、混合 backend/币种/价格版本、跨页分摊和缺记录均有对账例。注册表八字段缺任一即 FAIL。
4. 【run-留痕】至少一个实际运行验证采集与聚合；历史证据不足时允许使用后续获授权的真实运行，不伪造历史补登。分别报告实现验收和每项指标覆盖；R-70 的 TF/成本否决门只接受完整可比较证据，数据不足标 blocked；R-85/R-71 的机制验收仍可独立推进。
5. 【回放集-proxy】冻结输入的聚合与绑定关联可重跑，回放 hash 被消费者引用；真实用户收益须另有可比较的真实观测。没有足够观测时报告 `not_yet_observed`，不能称“返工下降”。

### R-84 图表构思质量基线（波 2）

**目标**：为"AI 自行结合材料思考生成合适图表"补可评测能力承诺。

**范围**：①图表构思 evals 用例集：三维度（图型选择/数据引用可回溯/叙事匹配）各 ≥5 例含 ≥2 负例；**负例**（图型错配/不可回溯/脱节＝FAIL）用现成否定感知 judge 模式；**正例**（恰当/匹配）是语义判定，走判读协议或 L1 双判官范式，成本另计；生成型 case 显式大 timeout（默认 300s 已证实超时）；②图表三路径语义统一成文并入 3a 与 R-74 路由表（新家族 case 不触 content-quality 冻结协议）；③R-77 图表两指标驱动迭代。

**非目标**：不做原生 chart XML；不新建渲染方言。

**验收**：
1. 【evals-proxy】用例集落盘（三维度覆盖＋负例判官）；
2. 【单测】三路径语义成文且 R-74 路由表引用（缺＝FAIL）；
3. 【run-留痕】首个真实 run 图表页 QA 漂移数据入 R-77（建基线）。

**用户净影响**：图表更贴材料与叙事。
