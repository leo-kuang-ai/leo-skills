## 一、测评设计

### 第一轮：20 行业 ×6 项检查（4 agent ×5）

行业覆盖 02_行业内容域全部 12 组。每行业一个典型请求语，六项检查：
C1 路由可见性（风格路由.md 可达且对味）→ C2 索引正确性（_INDEX 行+文件）→
C3 真实可加载（CLI style list）→ C4 内容匹配（brief best_for/适用场景）→
C5 端到端注入（CLI style render → ready/style_rendered）→ C6 配对锚
（视觉风格配对.md 有锚且不违和）。合计 120 项。

### 第二轮：50 行业 ×双场景（5 agent ×10）

- A 场景（行业主场景）：同六项检查；另设 3 个无专属风格对照组
  （农业/传媒出版/航空航天）验证优雅降级（D1 不误导/D2 无虚构/D3 降级
  指引/D4 降落风格 render）。
- B 场景（晋升述职）：每行业请求"XX 行业从业者年度晋升述职"，检查述职
  链路 B1-B6（路由可达晋升述职风/成果汇报风、索引、CLI、述职结构定位、
  render、行业×场景正交指引）。
- 合计约 110 项检查 + 55 次真实 render（命令间 sleep 1s）。

## 四、登记关闭的观察项

- **style_store_error 连发瞬态**：排查结论——`load_style` 全链只读无锁
  （styles.py 无共享写），本机串行 6 连发 + 5 并发均无法复现；判定为
  多 agent 并行期的系统资源瞬态（fail-closed 设计内行为），重试即恢复。
- **CLI 输出裸控制字符**：实现上不可能——CLI 输出统一走
  `json.dumps(ensure_ascii=False)`（必转义控制字符），全库 318 brief
  扫描无裸控制字符；判定为当时 agent 管道自身损耗，关闭。
- **tests/installer prune 漂移**：现 14/14 稳定 OK（测试文件已随进货程序
  落盘为 prune_backups 新 API）；早前 6 errors 为陈旧 __pycache__，关闭。
