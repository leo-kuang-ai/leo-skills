Grounding Context（代码库上下文）

体系现状。leo-ppt-generator 的风格模版体系由四类构件组成：资产库（references/styles/，273 个可加载风格 + 197 份分节轴规范）、合同层（references 根的 style-library / style-presets / style-candidates / style-continuity / style-recommendation / layout-dispatch 等）、编译面（style render 确定性合并五轴注入 deck_spec，字节红线）与治理面（lint_style_briefs / lint_layout_grid / style_hard_rules / audit_style_families / 金样板回归等治理 lint）。

目录层级的实际形态。16 个编号目录 + 顶层混合了四种本体：轴规范（06_论证模式～13_页面语义，8 个）、风格资产（01_通用母版 13 审美家族 110 份、02_行业内容域 12 行业 59 份、03_场景用途结构 7 场景 40 份、顶层 11 套内置）、来源矿（04_guizang / 05_awesome / 15_officecli / 16_slides-grab）与参考池（14_参考池_gpt-image2 色池+清单对）。00_索引/设计体系.md §四 的「现有库→六轴映射」表自认这是中间态：02 标注「待与品牌 VI 合并为身份轴」、03 标注「论证模式轴的用途场景细化」、04/05 标注「来源参考」。编号（00-16）编码的是到达顺序而非本体——14/15/16 均为后补来源。

解析优先级链。颜色维度已机器化：三层 token（通用设计规范护栏 → brief color_palette 角色默认（HEX 为可覆盖锚点）→ --color/--brand deck 覆盖）+ 对比度硬校验，11 套内置已定型，126 份参考风格 lint 白名单渐进迁移。但「上位护栏 > brief」在排印/密度等维度仍是口头约定（2026-08-29 十专家评审在案：字号数值曾散落三处）；明度×饱和度六分组第二维度明载「无专用 schema 键」，纯散文标注。

消费链与命名空间。P 码（36 版式）在至少三处手工同步：00_索引/版式内容Schema.md 定义表、每风格 .layouts.json routing sidecar、style-presets.md 预设版式集。本轮实测发现 12_版式库/ 同目录双命名约定并存（P23_Section_Divider.md～P29_Quiz.md 带 P 前缀，其余 01-22 / 30-36 无前缀）；.layouts.json 同扩展名双语义（12_版式库 36 份真值 sidecar vs 顶层 11 份薄路由视图）。R3-2.5 风格体系批（R-61 硬规则 / R-62 跨家族多样性 / R-63 别名 / R-65 金样板 / R-66 家族合并 / R-68 插画配对 / R-67 场景预设）正在落地中，工作树有大量未提交修改。

关键约束。R3 PRD（2026-08-31-005）域 H 明确 owner 决策：ppt-github 设计链的「五层资产+编译面+治理面」架构与 leo 现状方向一致，「本域只补 leo 真缺的拼图，不重构既有体系」。任何层级优化方案必须与此对齐，而不是另起炉灶重排目录。

证据口径与局限：外部对标复用仓内两份调研工件——十设计师风格评审（docs/leo-ppt-generator/reviews/style-review.md，含 2025-2026 业界调研来源）与 R3 PRD 域 H（126 个 AI-PPT 项目设计链结论），本轮未做新一轮外部检索。direct 证据均为本轮对仓库文件的直接读取实测。本轮为内联串行执行（无独立子代理验证），批判环节为 orchestrator 自查，此局限如实记录。

1. 风格资产清单单一真值层（Style Manifest）

不移动任何文件，在 references/styles/ 增加机读清单（如 00_索引/_manifest.json 或将 _INDEX.md 机读化）：每条资产登记所属轴、R-66 家族、tier（builtin / reference / source / pool）、行业/场景标签、variant_of、aliases、渲染配对、渲染能力（确定性路径 or prompt-only）。目录编号退化为物理事实，认知层级与一切机器消费面走清单：style list 枚举、R-61 硬规则、R-62 家族配额、R-63 别名检索、R-65 金样板挂钩、audit_style_families、R-60 doctor 能力清单共享同一真值，并配「清单 ⇄ 目录 ⇄ brief 字段」一致性 lint 防二次漂移。

Axis
A · 目录本体与资产分类（兼 E）
Basis
direct：style-library.md 的规模计数靠手工算术注释维护；variant_of / aliases / 明度档位已散落在各 brief 内；R-61～R-66 与 doctor 各自解析目录；设计体系 §四映射表是 prose 中间态。external：R3 PRD 域 H owner 决策「只补真缺的拼图，不重构既有体系」。
Rationale
层级问题的根源不是目录摆错了，而是分类学活在目录树与 prose 里、机器消费面各自解析。清单层把两者解耦：零迁移即可让六个能力共享真值，与「不重构」红线兼容，且为后续任何物理重排提供安全网。
Downsides

2. P 码注册表 + 全库引用图 lint

为 36 个版式建机读注册表（可由 12_版式库/ 现有 36 份 .layouts.json 聚合生成），作为 P 码唯一真值；版式内容Schema.md、每风格 routing sidecar、style-presets.md 版式集全部以注册表为准。lint 新增三类断言：① 所有被引用的 P 码必须存在于注册表；② 版式文件命名约定唯一化（当前同目录双约定：P23-P29 带 P 前缀、其余无前缀）；③ markdown/JSON 内 styles 相对引用可解析（防 data-journalism 式悬空）。

Axis
C · 编译与消费链（兼 D）
Basis
direct：本轮实测 12_版式库 双命名并存（P23_Section_Divider.md vs 01_Cover.md）；P 码三处手工同步（Schema 定义表、routing sidecar、presets 版式集）。external：2026-08-29 评审 P0 在案同类缺陷——data-journalism 被 14 个文件引用而目标不存在、P23/P24 当时缺失。
Rationale
悬空引用与命名分裂是同一类病：命名空间无单一真值。注册表 + 引用图 lint 把这类缺陷从「评审人工 grep 发现」变为「提交即拦截」，与 lint 白名单只缩不涨的既有收敛纪律同构。
Downsides
lint 需解析 markdown 内引用形态（别名/相对路径），规则面要防误报；P 前缀统一属文件移动，需与引用同批更新。

3. Token 层级补完：护栏数值机读化 + override 台账

把颜色三层 token 已验证的形态推广到全维度：① 将 通用设计规范.md 的铁律数值（字号下限、对比度体系、密度档、行高阶梯）抽为机读 guardrails token，style render 合并时显式执行「护栏 > brief」优先序并输出 override 台账——brief 值被护栏覆盖时逐条列出；② 排印 token（全局中西文 fallback 字体栈 + 行高阶梯）进 schema，风格文件只能在 schema 内 override；③ 明度×饱和度六分组档位从散文升级为可选 schema 键。R-27 的 token sidecar 是现成挂载点。

Axis
B · 解析优先级与级联
Basis
direct：设计体系 §2 三层颜色 token 已落地（11 内置 HEX 锚点 + --color 覆盖 + 对比度硬校验），证明形态可行；style-library.md 明载明度×饱和度「无专用 schema 键」。external：十专家评审 §二.1/§二.10——排印 token 缺失、字号数值曾散落三处靠「上位护栏优先」口头约定防冲突（P1 在案）。
Rationale

5. 面向用户的层级坍缩：产品单位 vs 构造单位

认知重构而非目录重构：对外表面（SKILL.md、README、advise 豁免、风格画廊、推荐呈现）只暴露两级产品单位——「完整风格」（11 内置 + 家族主风格）与「场景预设」（R-67）；六轴、P 码、渲染配对、参考池、来源矿全部降为内部构造单位，只在 style render --list-templates 与治理面出现。_INDEX / 风格路由按「家族 → 风格」两级导航重组，为库存增长到数百上千风格预架构。

Axis
E · 检索与导航（兼 A）
Basis
direct：SKILL.md advise 豁免已只读 _INDEX 按风格名应答（用户语言是风格名而非轴名）；R-67 预设已是场景产品单位且明确「非 brief、schema 不动」；13_页面语义 自我声明「只是排序信号」（构造单位自认）；设计体系 §一 心智模型「风格是正交轴组合」从未在导航层兑现。

6. 层级优化拆「零迁移批」与「物理重排批」

过程性原则：本轮所有层级改动先做零迁移形态——新增 manifest、注册表、lint、schema 键、文档层级合同，不动任何既有文件路径；物理重排（去编号化、目录归并、内置搬迁、P 前缀统一）集中为后置批，在 R3-2.5 落定、工作树干净后一次性执行，以「清单 + 引用图 lint 全绿」为出口判据。

Axis
D · 扩展与治理
Basis
direct：工作树当前有大量 R3-2.5 未提交修改；git log 显示该库的既有收敛史就是渐进批次（warning 371→319→294→286→177→清零，分目录分批）；R3 PRD owner 明确「不重构既有体系」。reasoned：迁移与进行中批次合并是层级改造最大工程风险，拆批使其归零。
Rationale
零迁移先行让认知层级收益立即兑现且零冲突；物理重排变成可选、有 lint 保护的低风险动作，而非豪赌。即使后置批永远不做，零迁移形态已拿到大部分收益。
Downsides
一段时期内「认知层级（清单）与物理层级（目录）并存」，需明确以清单为准；两阶段纪律本身需要 owner 认可。

Rejection Summary（否决清单）

#被否想法否决理由（一句话）
1全面去编号化、按本体重排目录（axes/styles/sources/pools）与 R3 owner「不重构既有体系」决策直接冲突，收益主要是美学；方向 1 以零成本达成同一认知目标。
2立即合并 02_行业/03_场景 入轴（身份轴/论证细化）设计体系 §四已记录该方向且 R-66 家族合并轨道在做；manifest 打标签后物理合并失去必要性（重复更强方向）。
3routing sidecar 与 presets 版式集全生成化方向 2 的注册表+lint 校验拿到约八成收益；全生成化引入模板系统复杂度，时机应在 manifest 之后。
4brief 全面 schema 化为六节 markdown设计体系已声明为长期演进方向；273 份重写与 R3-2.5 进行中工作冲突，短期价值低于 token/manifest（成本过高）。
5明度×饱和度档位独立立项加 schema 键真实但过细，作为方向 3 的字段级子项吸收（重复更强方向）。
600_索引 10 份文档分「入口/真值/扩展」三档纯文档分档无机器断言；价值被 manifest 的角色字段吸收（低于立项门槛）。
7「每条层级规则都 lint 化」作为独立方向是原则不是可讨论的具体方向；已由方向 2/3/6 共同体现（过于宽泛）。
8风格扩展模板（R-29）随层级演进对齐依赖其他方案落地后的后续动作，非独立方向（不可独立行动）。
9W3C Design Tokens 三级分层类比作为方向外部先例是方向 3 的证据与设计语言，本身非可执行方向（重复更强方向）。
10fallback 链统一为全局层级原语（用户>内置、品牌>默认、预设降级）价值真实但分散，作为方向 3 的设计原则记录而非独立交付（重复）。
11BI 星型模式：routing/presets 视图全部派生不落盘理想态成本高；lint 校验先行的理由与 #3 相同（重复更强方向）。
12家族卡片两级导航（family card）好想法但应作为方向 1 manifest 的导航面交付，单独立项过细（低于门槛）。
13「每层声明没有它会坏什么」存在理由测试方法论抽象、无落地判据（过于宽泛）。
14「风格库冻结只许增字段」极端推演思想实验；其实质（层级外置到元数据层）已被方向 1 形态吸收（重复）。
15护栏机读化（原独立候选）并入方向 3 作为子项①（合并去重）。
16目录本体分层/合同资产分层（原独立候选）并入方向 1 与方向 5（合并去重）。
17全库引用图 lint（原独立候选）并入方向 2 作为断言③（合并去重）。
