# leo-ppt-generator 能力提升评估（对照业界最佳实践）

日期：2026-09-11。适用对象：`leo-ppt-generator` 的维护者与方案评审者。输入依据：`SKILL.md` 与 `references/{image-deck-workflow, editable-workflow, execution-contract, render-contract, manifest-schema}.md` 现状梳理（流程全景图见 `ppt-flow-diagram-workspace/leo-ppt-generator-flow.svg`）。

本文以三条设计原则为评估基准——**流程稳定执行 · AI 发挥创造力和判断力 · 人来决策推进节点**——做能力差距评估与优先级建议，不是开发方案；每条建议标注现状触点、基建缺口与落地前需核实的边界。未标注验证的内容均为待验证建议，不构成已实现能力。

**需求化落点**：本文 14 项建议已转为正式需求条目 R-70 ~ R-83（每项含目标 / 范围含非目标 / 验收标准 / 依赖），见 [PRD](../prd/2026-09-11-leo-ppt-capability-improvement-prd.md)；本文保留为背景与差距分析，后续以 PRD 为准。

## 1. 结论

当前流程在**治理与可追溯**层面已领先业界同类工具：五类 sha256 指纹收据门、内容包 CAS 冻结、三层容错协议、对抗式三段质检、四级数字标注、样张收据与反演——Gamma / Plus AI / Copilot 等产品普遍没有等价机制，这部分是差异化优势，应保留。

按三层原则重新审视后，提升空间的性质也更清楚了：**不是加功能，而是把三类职责放回各自的层**。文字保真这类"可机判的正确性"目前占用 AI 的目视判断与付费重试预算，应下沉到确定性层；分页、版式这类最贵决策目前缺少确定性证据支撑，应补给人决策节点；AI 的品味判断与人的决策结论尚未沉淀复用。共 14 项建议：9 项服务流程稳定性（把机械正确性下沉到确定性层），3 项增强人决策证据，2 项增强 AI 判断的可用与可复用性。

## 2. 设计原则与三层职责边界

### 2.1 原则

> **流程稳定执行 · AI 发挥创造力和判断力 · 人来决策推进节点。**

分工判据（本文用于逐条评审建议）：

1. **凡是可机判的**（状态、指纹、几何、容量、对齐、账本）→ 归确定性层；
2. **凡是无对错标准、依赖品味与情境的**（叙事、视觉方向、风格适配、质量判读）→ 归 AI；
3. **凡是改变承诺、费用与验收结论的**（信任、基线、授权、接受 partial、最终验收）→ 归人。

### 2.2 现状对照

SKILL.md 已显式声明分工（"顶层 Agent 拥有意图、确认、live host capability、worker 派发和交付判断；`leo-ppt` 只拥有确定性准备、状态、验证和组装"）。按三层展开：

| 层 | 职责 | 现状机制（证据） |
| --- | --- | --- |
| 确定性（流程稳定执行） | 状态机与门禁、冻结与指纹、几何/容量/来源校验、容错与账本 | CLI versioned JSON 真值红线、Gate 0 与 CLI preflight、CAS 内容包冻结（dashi K4）、五类指纹收据 `create/verify`、`check_deck_geometry` / `check_sources_manifest --strict` / `compute_impact` / `check_worker_brief`、worker 三层容错与清扫、`run-ledger` / `rendered-ledger` / `backend_stats` |
| AI（创造力与判断力） | 叙事与内容生成、风格与视觉方向判断、质量审查中的语义判读 | `one_thing` / 哇点 / 反方登记、减法审计、风格候选带归因推荐与错配一次劝阻、样张反演三组判读、QA 三段（worker 自查 → 父 Agent 独立复核 → 对抗式审查）、材料缺失时的研究问题清单 |
| 人（推进节点决策） | 信任、内容基线、付费授权、partial 接受、最终验收 | Gate 0 信任确认、内容合同 / 大纲 / 母版确认（`confirmation` 状态与 `decision_source` 留痕）、🔶 SAMPLE-GATE、加样与双生成本授权、🔴 PARTIAL-GATE、🔴 DELIVERY-GATE 人工验收 |

**已对齐的范例**：样张决策 = AI 反演三组判读（判断）+ 样张收据六字段（确定性）+ 用户认可（人决策）三者同轮闭环——这正是三层原则的样板，其余节点可按此形态对齐。

### 2.3 与原则的差距

**差距 1：AI 判断被机械工作挤占。** 文字保真（错字/漏字/白名单外文字）是机械正确性问题，当前由 AI 目视 QA 发现、TF-1 内容减法、TF-2 贴字、反复重生成承担；图像模型随机性使成功率不可控，失败代价是付费重试与样张重确认。这类工作消耗 AI 的判断预算，且不会因 AI 更聪明而变好——应下沉到确定性层（§3.1、§4.2）。

**差距 2：人决策点证据不足。** 🔶 SAMPLE-GATE 是全册付费前唯一默认人工节点，但呈给决策者的证据只有 1 张样张；分页、版式、密度这类最贵的错误在人多已授权后才暴露。应把确定性预览补到同一节点（§3.2），不新增确认轮次。

**差距 3：可机判事项仍靠 AI 判读兜底。** `build_rendered_ledger.py` 已能聚合每页 OCR 事实却只是台账；`required_text` 逐字对齐靠目视；overflow 已由容量预检机判，但处置建议（改内容还是换版式）靠人脑列举（§4.2、§6.1）。

**差距 4：AI 判断结果未沉淀。** 样张决策收据、反演判读、成本与重试分布、QA 缺陷分布分散在各 run 工件中，未聚合反哺推荐质量与评测用例（§7.1、§7.2）。

**差距 5：人节点缺"变更—代价"视图。** 决策者需要知道"改这个要付什么"——哪些页重建、样张是否失效、是否须建新 run、费用增量。材料已备（`compute_impact.py` 波及面清单、指纹收据漂移处置规则、backend/generation method 变更触发的样张失效规则、`estimate_run_cost.py`），但未按节点成文呈现（§6.3）。

## 3. 结构性杠杆（P0）

### 3.1 混合页型转正

- **现状触点**：`image-deck-workflow.md`「文字保真降级链」。TF-2（留白底图 + `overlay_text.py` 确定性贴字）目前是异常兜底，属 `sample_generation_method` 变更，须样张重确认（整链未获确认即禁用）。
- **建议**：把"背景图（图像 lane）+ 前景文字（render lane 确定性渲染）"组合页提升为一等页型。AI 只画氛围/背景，前景文字与图表由确定性渲染产出。
- **基建已备**：render lane 模板合同、离线字体、`data-leo-ready` 就绪门、`render page` 整页渲染、provenance sidecar、`image record --render-receipt` 消费链。
- **缺口**：①"背景图 + 前景文字层"组合模板与合成脚本；②组合页 QA 判据（文字部分机械断言，背景部分按氛围页判据）；③**文字层必须作为一等视觉元素设计**（由排版系统保证美感），而不是"贴上去"——否则文字正确但版面廉价，反而损伤生成式路线的视觉整体性；④TF-2 语义从"须重确认的方法变更"降级为常规页型，需同步修订 execution-contract 与 visual-qa 对应条款。
- **收益**：文字错误结构性消失；AI 从拼字工作中解放，创造力集中到背景、氛围、视觉方向；图像 token 成本显著下降；样张确认粒度变轻。
- **服务层**：确定性（机械正确性下沉）＋释放 AI 创造预算。

### 3.2 全册确定性预览（样张门同轮）

- **现状触点**：`image-deck-workflow.md` STEP 6 🔶 SAMPLE-GATE。用户在只见过 1 张样张的前提下授权全册付费生成；分页/版式这类最贵错误的反馈最晚。
- **建议**：样张门同轮增加"全册 skeleton 预览"——render lane 按母版 + 版式把每页低精度确定性渲染（零 token），用户一次看全分页、版式、文字密度，确认后进入付费精化。
- **基建已备**：canonical 模板与版式 profile、`capability_manifest --template-library`、母版四段结构已含渲染所需全部字段；dashi 集成已实现"按同一绑定物化 HTML data"（U3/K2-K3）。
- **缺口**：①"母版 → 全册 HTML 预览"批量编排入口；②增量重渲（母版修订后只重渲受影响页，复用 `compute_impact.py` 波及面推导）。
- **收益**：最贵的纠错（改分页、换版式、调密度）前移到零成本阶段；人决策点证据从 1 张样张变为全册形态；**不新增确认轮次**（与样张同轮呈现，遵守既有"同轮呈现、修订只展示差异"口径）。
- **服务层**：人决策（增强节点证据）。

## 4. 质量与保真

### 4.1 原生图表嵌入（P1，即 manifest-schema 自划的 M2）

> **[2026-09-11 更新]** 本建议已按用户决策从 PRD 移除（v1.2）：不做原生 chart XML 嵌入，`charts[]` 保持预留。图表方向调整为 **AI 自行结合材料内容思考生成合适的图表**——构思与设计归 AI 判断层（母版视觉行 + 图表样式规范 + 材料三级标注数据），产出走既有生成链（3a 路由 → render chart 确定性渲染 / 图像 lane）。下文保留为历史分析。

- **现状触点**：`manifest-schema.md` `charts[]` 段"预留，未实现（M2 范围）"；`page-worker.md` 当前用原生形状重建图表，数据正确性靠 QA 断言（数值/单位/标签/排序漂移即失败）。
- **建议（已移除）**：实现 PowerPoint 原生 chart XML 产出（python-pptx / pptxgenjs 均支持，随对象附数据表）。
- **收益（已移除）**：兑现"可编辑"承诺中价值最高的一块；图表 QA 从"断言像不像"变为"数据即真值"；数据更新场景不再重出图。
- **边界**：需与 3a 数据密度路由（≥6 数据点改走原生图表）统一口径，避免两条"原生图表"语义并存。
- **服务层**：确定性（数据真值化）。

### 4.2 required_text ↔ OCR 对齐硬门（P1）

- **现状触点**：`build_rendered_ledger.py` 已聚合每页 OCR 文本摘要，但它是台账不是门；视觉 QA 靠父 Agent 复核图面。
- **建议**：把"页图 OCR 与 `required_text` 白名单的逐字对齐"做成 `image record` 前的阻断断言（编辑距离阈值可配、白名单外文字计失败）。
- **收益**：文字问题从"事后视觉 QA 发现"提前到"record 时机械拦截"；AI 的目视判断不再用于可机械判定的对齐问题；TF 链触发更早，重试更省。
- **边界**：OCR 本身有误读率，需按仓库既有 negative-aware 匹配纪律先做阈值红绿校准，避免误报。
- **服务层**：确定性（机械拦截前移）。

### 4.3 视觉回归 diff（P2）

- **现状触点**：artifact revision 变更后要求"重新组装、渲染并复验"，但人侧无新旧对比证据。
- **建议**：revision 变更时自动生成"旧 vs 新"页图缩略拼图，附入交付报告；配合 `compute_impact.py` 波及面清单逐页标注。
- **服务层**：人决策（复核证据）。

### 4.4 无障碍升级（P2）

- **现状触点**：`style-recommendation.md` 已有浅底对比度 <4.5:1 报错；视觉质量门要求"关键信息不得只靠颜色区分"。
- **建议**：①色觉模拟（deuteranopia/protanopia）下重跑"仅靠颜色"断言；②图片页 alt 文本清单进交付收据与披露。
- **服务层**：确定性。

## 5. 成本与性能

### 5.1 页型路由优化器（P1）

- **现状触点**：`image-deck-workflow.md` STEP 3a 数据密度路由为单轴（数据点数 ≥6 → 原生图表）。
- **建议**：推广为"文字密度 × 视觉权重"双轴路由：文字密集/结构页（封面除外）默认 render lane，氛围/概念页走图像 lane；`estimate_run_cost.py` 顺势输出"lane 组合方案 vs 成本对比"供确认。
- **收益**：配合 §3.1 后图像调用量可预测地下降；成本预估从"区间猜测"变为"由路由结果推导"。
- **服务层**：确定性（成本确定性）。

### 5.2 素材语义缓存（P2）

- **现状触点**：`library-schema.md` 已有 sha256 登记与出处追溯。
- **建议**：加 embedding 检索层，氛围类配图"先检索复用、后付费生成"；跨 run 去重同一素材。
- **服务层**：确定性。

### 5.3 QA 与派发流水线重叠（P2，需先核实现状）

- **现状触点**：三层容错协议定义每页 `prompt → backend → QA` 三阶段，未明确 QA 与后续页派发是否并行。
- **待验证**：若当前实现为"全册派发完 → 统一 QA"，可改为已完成页 QA 与未完成页派发并行（重试预算不变），全册时延近似减半。落地前先核实调度现状。
- **服务层**：确定性（时延）。

## 6. 交互与交付

### 6.1 版式自动重排提案（P1）

- **现状触点**：容量预检硬超时"只能改内容或换版式"（`layout-dispatch.md`）；`check_deck_geometry.py --capacity` 已能机判 overflow。
- **建议**：把 overflow 数据喂给确定性建议器，按容量档位输出：候选版式清单 + 母版要点减法方案（带字数测算），让"改哪边"从开放决策变为带依据的选择菜单。
- **基建已备**：P 码版式表、容量档位参考（`template-library/governance/rules/layouts/00_容量档位参考.md`）、禅档位要点上限。
- **服务层**：AI 判断（提案生成）+ 人决策（选择）。

### 6.2 讲稿时长校准（P2）

- **现状触点**：`export_speaker_notes.py` 已导出讲稿；叙事三查③要求 Σ预计用时 vs 合同预算。
- **建议**：补每页"预算时长 vs 讲稿字数（语速模型）"对照与超时页标注，把三查③自动化。
- **边界**：预计时长不是试讲证据（SKILL.md 既有口径），自动化只作提示不阻断。
- **服务层**：确定性（advisory）。

### 6.3 决策简报：变更—代价视图（P1，本轮新增）

- **现状触点**：`compute_impact.py` 波及面清单、指纹收据漂移处置规则、样张失效规则（backend / generation method 变更使旧样张继承失效）、`estimate_run_cost.py` 费用区间。
- **建议**：每个推进节点（合同 / 大纲 / 母版 / 视觉方向+样张 / PARTIAL-GATE / DELIVERY-GATE）向人呈现三行固定摘要——① 相对上一基线**变了什么**（diff 摘要）；② **影响什么**（波及页清单、失效工件、须重做项）；③ **需要决定什么**（唯一决策点与选项）。材料均已存在，先由 Agent 按节点模板成文，逐步脚本化。
- **收益**：人决策从"看结果"变为"看变化与代价"，直接服务"人来决策推进节点"；与既有"修订只展示差异"（共创模式）口径统一并推广到委托模式。
- **服务层**：人决策（决策质量）。

## 7. 数据飞轮

### 7.1 运行质量记分卡（P1）

- **现状触点**：原料齐备——`run-ledger.jsonl`（阶段账本）、`backend_stats`（成本/重试）、`rendered-ledger.json`（呈现事实）、`sample-decision.json`（样张决策）、reason-codes 分布。
- **建议**：聚合每 run 的 P0/P1 缺陷数、重试分布、TF 触发率、成本 vs 预估偏差、lane 占比为 scorecard；用线上分布反哺 `evals/` 用例权重（skill-up 评测体系已在仓库）。
- **服务层**：确定性（数据反哺）。

### 7.2 样张偏好先验（P2）

- **现状触点**：`${LEO_PPT_HOME}/profiles/` 交付档案只存静态偏好字段；执行合同要求"绝不存业务数据"。
- **建议**：从 sample-decision 收据累积个人接受/打回记录与风格指纹，作为风格推荐的先验输入（合同信号 + 历史偏好）。动态偏好层与档案静态层分文件，保持"偏好非事实"边界。
- **服务层**：AI 判断（推荐增强）。
