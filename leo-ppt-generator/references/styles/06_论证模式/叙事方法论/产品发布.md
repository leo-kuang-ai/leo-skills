# 叙事方法论：产品发布（product-launch）

> **叙事层**条目：管「怎么说」——页序骨架与节奏；「怎么证」由论证模式轴承接（配对见第 4 节），
> RST 关系管同页/拆页（[`../../../rst-paging.md`](../../../rst-paging.md)）——三层正交。
> 拍选配仅白名单（第 5 节，源 [`../叙事拍库.md`](../叙事拍库.md)）。

一句话：价值先行的发布叙事——**每个能力主张先被一个可演示的时刻挣得，
然后才被命名**；从受众正身处的张力开场，收在下一步。

## 1. 适用场景

新品/新版本发布会、功能发布、平台 capability 发布、 GTM 启动会。

## 2. 页序骨架

节位序列（能力拍的数量与顺序随**实际发布内容**自适应，不填固定揭晓模板；
同页/拆页按 RST 关系）：

| 节位 | 页角色（原文） | 沟通任务 |
|---|---|---|
| 张力 | 开场张力（Opening tension） | 受众已经生活在其里的痛点/别扭 |
| 定位 | 定位主张（Positioning claim） | 产品是什么、为谁、替代什么 |
| 揭晓 | 能力揭晓（Capability reveal） | 一个能力一次揭晓，标题写受众得到什么 |
| 演示 | 演示时刻（Demonstration moment） | 可演示的真实时刻——主张的凭据 |
| 对照 | 前后对照（Before and after） | 有它/没它的直接对照 |
| 凭据 | 证明点（Proof point） | 性能/结果数字（挂计量口径与客户） |
| 全景 | 能力全景（Capability landscape） | 已发布能力的整体图景 |
| 可得 | 可得性与入口（Availability and access） | 何时、何地、如何拿到 |
| 收束 | 下一步（Next step） | 受众此刻能做的一件事 |

## 3. 节奏要点

- 每页**一个能力、一个收益或一个时刻**；演示占据页面，要点列表不顶替演示；
  为省页把两个揭晓合到一页是禁止项。
- 标题写**受众得到什么**，不写功能名。
- 已发布、预览中、规划中**三态视觉分明**——路线图项绝不借用 demo 的确定性；
  性能与结果数字挂计量或客户，抽样/代表性结果如实标注，对比给口径与日期。
- 张力开场后立即进入「能力如何消解它」，再放宽到它使什么成为可能。

## 4. 与论证模式轴的关系（正交声明）

- 本条管发布叙事的**页序与节奏**；论证形态由论证模式承接——推荐配对：
  **视觉展示**（源声明 Preferred Mode: showcase；图/演示主导、揭晓结构）。
- 不重叠：视觉展示定「怎么证——以演示为证据的展示论证」；本条定「张力→揭晓
  →放宽的发布页序、先演示后命名的节奏与三态主张分级」。

## 5. 拍库白名单（选配组件，非自由组合）

- 白名单拍：方案（solution）、增长牵引（traction）、图示注解（annotated）
- 节奏签名：短断言+视觉证据（punchy-claim+visual-proof）、
  控制台+头条数字（console-with-headline-stat）
