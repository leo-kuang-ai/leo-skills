# Evidence-first Writing Skill 技术方案

## 结论

本 Skill 采用四轴入口与自适应编辑状态机：`lifecycle_intent × article_family × evidence_risk × collaboration_modifier` 生成 route，operation 决定从哪里进入，`quick/standard/deep` 决定做多深，文章 family 决定生产主轴。15 个顶层节点提供共同治理。Humanizer 是末端节点，不拥有全文质量。

## 第一重审视：定义关键问题与领域

表层需求是补齐写作流程，深层目标是稳定地产出「问题值得回答、作者判断可辨、材料可追溯、论证成立、读者有效、改写不失真」的文章。真正问题不是模型会不会写句子，而是每种质量错误由谁负责、何时拦截、后续变换如何不破坏上游真值。

相关领域包括信息检索与证据治理、论证设计、认知写作过程、编辑审查、作者声音、营销文案、技术传播和软件工作流设计。边界覆盖文章明确介绍的六类能力；学术代写、伪造个人经历及未经授权采集私人文本仍不在范围内。

这一重审视改变了什么：把「生成一篇自然文章」改写为「先识别读者任务和真值基础，再完成一次有作者、有证据、有读者结果且可审计的编辑委托」。

## 第二重审视：理论体系与判断主轴

方案采用四个成熟判断主轴：

- Flower-Hayes 写作过程模型：计划、表达和审阅是递归过程，不是一次性线性生成。因此允许后段失败返回证据、分析或结构阶段。
- Toulmin 论证模型与《The Craft of Research》的 claim-reason-evidence-warrant 思路：证据本身不会自动证明结论，必须显式检查论证桥梁、限定条件和反方。
- 信息素养与横向核验：搜索结果摘要不是证据，主张必须落到已打开的原始来源、时间和具体位置。
- 读者测试与「知识诅咒」控制：作者拥有的上下文不等于读者拥有，必须检查隐含前提和跳步。
- 发展编辑、line edit、copy edit、proofreading 的职业分层：先解决作品为什么成立和如何组织，再改句子，最后处理机械正确性；低层润色不能补偿高层失败。

关键矛盾是效率与作者控制之间的张力；主要方面不是增加更多生成规则，而是把不可逆的事实和判断选择锁在上游，把可逆的语言调整留在下游。

这一重审视改变了什么：阶段不再按「先后步骤」划分，而按「谁拥有哪类错误、失败该退回哪里」划分。

## 第三重审视：关键事实与综合模型

两篇文章与 9 个固定 commit、1,016 个 tracked 文件形成一致事实链：万能提示词难以兼顾多目标；研究、结构、声音、平台和核验需要不同所有者；代表性样本和陌生主题盲测比口头禅更能描述风格；检测器只提供分布线索；去模板改写会产生事实漂移风险；真实发布数据必须绑定具体版本且跨样本后才可学习。完整范围与测试见 `references/upstream-source-audit.md`。

同时出现一个重要校准：文章对 Humanizer 规则数量分别写成 53 和 43，当前上游源码是 55。规则库会漂移，数字分数也会误杀。因此技术方案不复制某个固定规则全集，不将「AI 分数低于阈值」设为验收条件。

综合模型升级为：

```text
委托/权限 -> brief -> 选题价值(按需) -> 作者素材/声音
-> 主问题/立场 -> 调研账本 -> 分析综合 -> 读者承诺
-> 结构 -> 标题/开头 -> 草稿
-> 事实预审 -> 发展编辑 -> 读者编辑 -> 品味编辑
-> 声音/line/copy edit -> 去模板 -> 最终事实回归
-> 平台交付 -> diff/真实发布数据学习(按需)
```

任一门禁失败，都返回错误所有者，而不是靠润色掩盖。例如因果主张缺证据返回调研阶段，段落可随意交换返回结构阶段，声音不像作者返回样本与声音阶段。

这一重审视改变了什么：将文章经验转成了可执行的数据合同与回退机制，并删除了易漂移的规则数量依赖。

## 第四重审视：反方压力与方案竞争

竞争方案有四种：

1. 一个超长全能提示词：部署最简单，但事实、结构和风格相互污染。
2. 固定 19 阶段流水线：证据最完整，但短任务成本高，容易流程官僚主义。
3. 工具拼盘：专业能力多，但版本、许可证、上下文与权限难治理。
4. 自适应编辑状态机：operation 分工、depth 裁剪、风险升级，核心合同自给自足。

最强反方是：自适应路由可能因模型判断错误而漏掉关键门禁，或把同一 Agent 自审误称为独立审查。对应约束是“最轻但能控制风险”：事实密集、高影响、不可逆发布、私人档案写入和外部行动自动升级对应门禁；quick 只能合并低风险节点，不能省略事实、授权和 owner 决策；独立审查必须有隔离 reviewer 与可追溯状态。检测只作诊断，不以分数证明作者身份。

另一个关键前提是声音样本具有代表性。该前提无法自动保证，因此没有样本时只能称「临时语域」，不能声称学会了作者风格；样本必须属于用户或得到授权，避免对无关在世作者进行欺骗性模仿。

这一重审视改变了什么：增加了按需裁剪、误杀保护、声音授权和停止条件，防止流程与去味本身成为新的模板。

## 第五重审视：全貌理解与可验证收束

最终架构由五个层次组成：

- 意图层：生命周期、文章 family、证据风险、协作 modifier 四轴识别。
- 入口层：operation 与 `quick/standard/deep` 组合路由。
- 生产层：15 节点顶层编辑流水线和文章类型专用合同。
- 门禁层：权限、事实、论证、结构、读者、品味、声音、平台和交付按错误所有权排序。
- 学习层：事实不变量脚本、diff 复盘、版本绑定发布指标和跨样本规则升级。

成功信号不是「读起来顺」或「AI 分数低」，而是关键事实可追溯，论点与证据匹配，反方得到真实处理，目标读者无需作者隐藏上下文，声音来自授权样本，最终改写没有改变事实不变量。失败信号包括引用只支持主题不支持主张、虚构读者误解、段落可任意交换、声音仅靠口头禅、以及去味后数字或因果程度发生变化。

这一重审视改变了什么：把验收从主观流畅度升级为可观察行为，并明确了未运行独立读者测试时必须降级披露。

## 验证与演进

验证分四个不可补偿的 evidence axis：`structure_contract`、`behavior_quality`、`runtime_cost`、`field_outcome`。结构合法不能补偿行为失败，token 更少不能补偿事实漂移，模型盲评不能补偿真实读者结果。真实价值观察作者修改量、事实缺陷率、读者理解、采用率和版本绑定发布数据。

转向条件：若多数任务只使用单一阶段，应拆成独立 Skill；若跨阶段上下文丢失成为主要失败，应增加机器可读中间产物；若规则增长但误报率升高，应删规则并回到真实失败样本，而不是继续扩充禁词表。

## 最终判断

推荐实现 operation+depth 双路由的自适应编辑状态机，而不是万能写作 Prompt、固定重流水线或外部 Skill 强绑定。它以文章价值链为主干，以证据账本、论证图、错误所有权、编辑品味、事实回归和跨样本学习形成闭环；Humanizer 和外部工具只作为按需执行器。
