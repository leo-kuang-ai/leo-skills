# 模版推荐与用户选择（generate 路线）

> 本文档是 `image-deck-workflow.md` 步骤 4「模版推荐与选择」的执行合同：推荐是
> 信号驱动的默认项，选择是低摩擦的 override。全部交互寄生在既有"视觉方向确认"
> 点与样张里程碑内，不新增确认门；样张里程碑按 SKILL.md 协作方式为 🔶 SAMPLE-GATE
> 默认人工呈现点（显式豁免可免呈现，不免生成与质检），本文档不改变该默认。

## 一、信号映射（推荐由合同字段驱动，不靠即兴）

执行期先按 [风格索引](../template-library/governance/authoring/index/_INDEX.md) 找名称范围与分面摘要，再用
`style list --summary --filter <名称或别名>` 和 `style load <load_name> --summary`
核对实际文件。索引过期或缺失时，按 resolver 的 canonical 只读降级查询，不读取退役的
`generated/` 快照，也不修改安装目录。
所有调用使用同一 home，user 同名优先；候选显示必须基于实际 scope，不能复制同名 builtin 的摘要。
摘要字段 suitable_for/visual_character/density/layout_hint 是源字段的有界摘录，截断处必须披露，
缺字段为未记录；不把摘要当渲染正文，也不臆造语义排名分数。

进入视觉方向确认时，先从已冻结的内容合同提取推荐信号，再查
[`../template-library/governance/authoring/index/风格路由.md`](../template-library/governance/authoring/index/风格路由.md)：

| 信号 | 来源 | 用途 |
|---|---|---|
| 受众保守度 | 合同"受众" | 风险偏好轴（保守→稳重商务系；年轻→波普/蒸汽波系） |
| 使用场景 | 合同"使用场景" | 路由表"内容/任务"行的主匹配键 |
| 数据密度 | 母版图表页占比 | 高密度→克制配色+图表语法轴 |
| 行业域 | 合同主题/素材 | `template-library/canonical/styles/` 的 taxonomy + `template-library/governance/rules/domains/`（含 content_rules 挂接） |
| 自定义风格 | `${LEO_PPT_HOME}/template-library/canonical/styles/` | 存在同场景保存风格时**优先列为候选**并标注"你保存过" |

**候补源矿落空词参考**（R-55 点名落空登记用，非自动路由；来源词整理自
baoyu-skills，详见 [`style-candidates.md`](style-candidates.md) 登记行）：
"双语 / bilingual / 中英对照" → 候补「双语技术简报风」；"组装 / 说明书 /
how-to / 步骤图" → 候补「说明书图解风」；"编目 / 清单 / 工具目录 / 技能矩阵" →
候补「周期表语法」（版式轴）；"saas / 看板 / 产品 demo" → 既有 SaaS介绍风 +
notion 品牌版式语言层。命中落空词时按 R-55 通道记录，作为候补补货信号，不在
推荐面内虚构在库条目。

### 硬规则前置（R-61）

语义推荐前先过 [`scripts/style_hard_rules.py`](../scripts/style_hard_rules.py)
`--check-brief`（输入上表合同信号）：输出排除/锁定/偏好家族与触发规则 id——
学术答辩排除蒸汽波/波普系、党政语境锁定党政红系、儿童受众排除高攻击系、
投资人路演×科技偏好科技暗色系（加分不锁定）。用户点名（`named_style`）
bypass 全部规则，并在 style 合同记录用户选择依据（与 AE5 同源）。

## 二、候选呈现（通常 2–3 个合格方向，每方向四行）

### 风格与页面内容的衔接

整稿风格只决定视觉系统的候选范围，不直接替代逐页版式判断。进入母版后，页面
先经 `page_intent` 归一到版本化 `page-type-regime`（例如 `comparison`、`trend`、
`process`、`kpi`、`evidence`、`table`、`text_list`），再由
`scripts/suggest_layout.py` 将该页型与风格的 `layout_routes`、内容容量和实际
`renderer_support` 合并排序。这样同一风格可以承载多种页面意图，同时避免只因为
选中了“咨询/金融/科技”风格就把所有章节页套成同一张列表骨架。

页面显式的 `content_shape` 或 `structures` 优先于标题关键词；语义不足时推荐器
返回 `undecided` 并保留两个真实候选，不把低置信推断伪装成自动决定。风格主题、
页面语义、版式几何和渲染 lane 仍各自只有一个真值源。

用户询问某个风格“能不能做”时，候选回复必须把**在库命中**和**可执行能力**分开：
有 renderability 证据才写“可以做/可渲染”；只有名称或家族摘要时写“可进入样张验证，
尚未完成视觉验证”。不得把在库、摘要覆盖或家族归类说成已经渲染成功，也不得承诺
立即出图。

```text
视觉方向 A（默认推荐）：<风格名>
- 为什么：<一句信号归因，如"投资人路演+数据密集 → 结论先行+克制配色">
- 长什么样：<网格/主色/图表占比一句话>
- 换它的代价：换风格＝重过样张（成本见 S9 论证：1 vs N）
```

候选清单末行统一换法指路：

> 回一个字母确认方向；或点名风格（数量以当前 catalog registry 为准，可按家族/场景浏览摘要）；
> 或贴一张参考图“照图做”；或说“跟上次一样”。

方向确认后完整 load 并以 `style render <load_name> --expected-selection <selection_fingerprint>`
组合；指纹不一致停止旧选择，回本确认点核对。其后仍须样张确认；“选择指纹有效”不能替代样张验收。

**默认推荐 tie-break 判据**（并列时依序）：场景匹配 > 受众风险偏好 > 数据密度 >
自定义风格复用。默认推荐**必须**带归因句（AE1）。

### 跨家族多样性（R-62）

先形成满足硬约束的可行集合，再在其中优先呈现跨家族差异；多样性不覆盖适用性。
存在多个适用家族时通常给 2–3 个方向，每家族优先不超过 2 项；场景锁定单家族时
允许同家族的不同表现，只有一个合格候选时直接推荐一个并说明原因，不凑数。
首方向仍按判据标注"默认推荐"。**推荐落盘（R-64）**：每次推荐决策后经
`scripts/recommend_feedback.py record` 只落家族归类标签（不存用户原话），
累积后 `suggest-weights` 输出家族 boost/decay 建议；仅形成反馈建议，不宣称自动学习
或真实推荐质量已经提升。决定是否等待用户遵守 SKILL.md 的协作方式。

### 分角色组合（R-30，可选档，默认关）

发布会/路演类场景，候选呈现**可选**给出"封面/内页分角色组合"：封面选更冲击
家族（如高攻击/科技暗色系），内页选更理性家族（如商务专业/极简排版系），主辅
搭配、deck 仍锁定**一个主风格**（分角色只影响封面页的家族倾向）。呈现时必须
带一句话说明（"封面更冲击、内页更理性"），用户未点头不启用；本档不改变上文
推荐合同（信号映射/候选行格式/多样性配额均照旧）。

### 场景预组合预设（R-67，可选档，默认关）

高频场景可按 [`style-presets.md`](style-presets.md) 预组合（风格+版式集+叙事+
密度+fallback 链）直接呈现；仅用户明确要预设时启用，预设缺失按 fallback 链
降级而非硬失败。

## 三、指定优先序与四式路径

优先序：**显式点名 > 参考图 > 推荐**——用户给了参考图或点名风格，跳过推荐直行。

1. **点名**（"用瑞士网格风"）：查名称/别名索引 → 实际源摘要核对 → 用户选择后读完整 brief →
   带选择守卫的 `style render` 注入；不再呈现无关推荐清单（AE2）。口语名先经真实 `aliases`
   字段命中（如"白板风"→手绘白板风、"dashboard"→数据仪表盘风）。多命中完整列出并在既有确认点消歧；风格不存在时列出相近候选
   （名称子串/别名/同轴邻近），不静默替换。
2. **沿用**（"跟上次一样"）：`${LEO_PPT_HOME}/template-library/canonical/styles/` 同场景自定义风格优先；
   无保存风格时如实说明并回落推荐，不假装沿用。
3. **照图做**（参考图）：按 [`style-library.md`](style-library.md)「照图做」节执行
   ——只提取可复用视觉系统，走既有样张里程碑并排比对。
4. **浏览**（"我自己挑"）：呈现三视图摘要（行业/气质/场景各列前若干项，复用
   `风格路由.md` 两张速查表），用户圈定范围后展开；**禁止一次性倾倒全部可选风格**。

## 四、冲突劝阻（一次，然后尊重）

用户指定与场景明显错配时（路由表场景轴冲突，如学术答辩×蒸汽波），给一句风险
提示并给替代建议；用户坚持即执行，并在 `deck_spec.style` 记录用户选择依据
（user sovereignty），不重复劝阻（AE5）。

## 五、照图做（参考图 → 风格 brief）

- **提取边界**：只提取可复用视觉系统——配色、字重气质、纹理、留白密度；不提取
  业务正文、人脸、可识别标识、水印。
- **写入**：提取结果写成 style brief 进 `deck_spec.style`（来源标注"参考图提取"）。
- **验证**：复用既有样张里程碑——样张产出时**与参考图并排呈现**供"像不像"比对
  （AE3），用户确认后锁定；满意可按 style-library 保存节沉淀为自定义风格。
- 两张参考图是比较或融合的视觉输入，不等于授权生成两张付费样张；按任务意图选择
  融合方向或提议双生，新增图片需有已披露费用的授权覆盖。

## 六、样张双生（看着挑，提议制）

- **触发**：agent 侦测到纠结信号（用户对候选表达犹豫，如"拿不准/两个都想要"）
  时**提议一句**："要我各出一张同内容样张二选一吗？会多花一张图片成本。"
  额外费用获授权后执行（AE6）；已授权同一加样不重复询问。两张参考图本身不构成该授权。
- **执行**：默认方向与最强备选各出一张**同内容**样张，用户二选一。
- **收敛**：落选方向即弃，不自动追加第三方向；二选一计入既有样张里程碑确认
  （一次交互），不构成新确认点。
- **成本纪律**：双生多一张图片成本，提议时必须告知；未获同意不生成。
- **样张角色锚定**（样张升级合同，与 `image-deck-workflow.md` 步骤 6 同源）：
  默认仍恰好 1 张，且锚定**正文页角色**——样张页选信息承载最重的正文页，
  不选目录/封面等结构页充当默认样张。结构页（目录/封面）加样为可选：提议
  样张时同一句内告知"另出一张结构页样张会多花一张图片成本，需要吗？"，
  点头才出，不点头不出。点名两张或说“不用再问”不能替代对尚未披露的额外成本的
  同意；已披露并获授权的同一加样无需重复询问。advise 只说明成本和待确认项，不把
  加样请求记成已接受额外成本。双生与结构页加样不叠加：双生时每方向仍 1 张正文页，
  胜出方向选定后才可（同样成本先告知、点头才出）补结构页。

## 七、样张反演（选定后、锁定前，三组判读）

用户选定样张后、锁定 `deck_spec.style` 前，agent **读回已选样张图**，输出
三组结构化判读。反演是读回动作，不是新确认门：判读结果**随样张确认的同一轮
回复呈现**（"样张已选定。我从样张读回以下稳定风格事实：…；以下效果好但需
确认是否整套延续：…；以下只在当前图偶然成立、不建议锁死：…。无异议即按此
锁定"），不产生第二次等待。

三组字段名固定（即 `deck_spec.style.style_inversion` 的三组键，见
[`manifest-schema.md`](manifest-schema.md)）：

| 组 | 字段 | 收什么 | 例子 |
|---|---|---|---|
| ① 明确应延续的 | `inherit_stable` | 已选样张中可观察、适合作为整套约束的视觉事实：明度、palette、材质、容器语法、密度、图文配比；单张不证明跨角色稳定 | "浅底网格 + 蓝色仅用于数据强调"、"左对齐单栏正文" |
| ② 效果好但需确认是否整套延续的 | `needs_confirmation` | 主题/场景锚：校徽、实验器材、领域图形语言等——单页成立、整套未必 | "封面整幅色块是否全套延续（未获确认，未锁）" |
| ③ 只在当前图偶然成立的 | `one_off_not_locked` | 渲染偶然、一次性装饰、构图巧合 | "样张中的手绘箭头装饰" |

- **默认规则（用户不回应时）**：保留第一组（`inherit_stable` 进 spec），第二组
  **不硬锁**（如实标注"未获确认，未锁"），第三组不进 spec。
- **证据优先序**：样张实证 > 原始 prompt 措辞；不把渲染事故当风格事实。
- **双生衔接**：样张双生场景在二选一之后，对**胜出样张**做同一反演；结构页
  补样获点头时，结构页样张的事实并组判读（通常落在第②组）。
- **落盘**：反演结论写入 `deck_spec.style.style_inversion`（`source:
  "sample-inversion"` + `sample_refs` + 三组），spec 冻结后随 manifest 落盘；
  未反演时该键不存在。三组只描述视觉事实，与内容合同字段互不重叠。
- **与样张双生的成本边界**：反演零图片成本、零新增等待轮次。
- **覆盖边界**：样张只验证已观察到的页面角色。批量阶段优先生产已计划中差异最大的
  页面（如原生数据页或深浅主题切换页），检查通过再展开余页；不默认增加成品页数、
  图片调用或确认门。数据精度优先核查数据和原生对象，不以额外图片替代。
