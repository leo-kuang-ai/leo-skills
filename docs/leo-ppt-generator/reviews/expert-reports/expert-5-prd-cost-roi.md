# 专家报告 5 · 成本与商业化（投入产出与排序）

- 评审对象：`docs/prd/2026-09-11-leo-ppt-capability-improvement-prd.md`（v1.0）
- 立场：token 成本、工程人力、交付时延、风险敞口与 ROI 排序
- 日期：2026-09-11 · 独立盲评 · 已核实 estimate_run_cost.py / charts[] 预留 / text_fallback 字段 / R-81 文档现状

## 总体结论

**有条件通过。** 方向判断（机械正确性下沉、决策证据补给人节点）在投入产出逻辑上成立。但存在一个系统性倒置：**把最贵的赌注（R-70）排在最便宜的测量（R-77）之前，且全批没有工程量分级与收益基线**——P0/P1/P2 划分依据是"结构重要性"而非 ROI。R-70 的招牌收益当前既无基线也无保守情形量化，验收还反向依赖排在其后的 P1 条目。

## Findings

- **E-1 [major] R-70/R-71 必须修改**：两条并列 P0 无资源受限时的先后依据。投入产出极不对称：R-71 复用现成基建、零外部 API、不碰门语义、无盲评风险、每个 run 直接受益（最贵返工前移 + 付费信任卖点），且先落地能给 R-70 开发提供免费全册预览工具；R-70 是本批工程量最大、唯一带盲评不确定性、指标要等基线的条目。→ 明确 **R-71 先于 R-70**，第 6 节补"资源受限分支"排序依据。
- **E-2 [major] R-70 必须修改**：收益口径三处不严——①≥90% 无基线无页型分布数据；②成本口径错位：背景图 token 与整页图大致相当，真正节省来自**消除 TF-1 付费重试与样张重确认的期望成本**，应改"含重试的每页期望成本（backend_stats attempts × token 均值）"；③降级形态只写触发条件没写沉没成本账（合成管线与模板可复用，TF-2 合同修订需部分回滚）。→ 开票前先跑基线 spike；成本改期望口径；补降级沉没成本清单；建议**分阶段转正**（先降级形态小范围上线并盲评，通过再做模板级文字层与全面转正，失败则回滚面接近零）。
- **E-3 [major] R-77 必须修改（排序）**：测量基建压在 P1 却被 P0 验收反向依赖——本批最明显排序倒置；且 R-77 是全批最便宜条目之一（只读聚合、依赖齐备、`text_fallback: true` 与 backend_stats attempts 均为既有结构化字段）。R-76 一期（模板成文、零依赖）同理被埋。→ R-77 最小子集（TF 触发率 + 成本对账）**前置为 R-70 先决**；R-76 一期可并行随做。
- **E-4 [major] R-72 质疑待答辩**：R-72 与 R-70 在"数据页"客群上竞争（R-70 后图片式数据页走 render lane 确定性表格，R-72 只服务可编辑路线），可触达价值 = 可编辑 run 图表页体量 × 用户改数频率，两数均未提供；双 builder 等价对净新增段意味着同一功能建两遍。→ 出示需求证据后再开工（R-77 lane 占比 + 图表页 QA 漂移缺陷率）；范围裁到 2 种最高频图型；净新增段豁免双 builder 等价（或答辩）。
- **E-5 [major] P2 四条 建议**：机会成本未评估——①R-81 先决核实是半小时级任务，评审期内直接做完，已并行当场关闭；②R-83 建议关闭（个人场景 sample-decision 累积慢、冷启动长，静态 profile 人工沉淀便宜 10 倍）；③R-79 缩围（alt 清单便宜保留，色觉模拟在外发频率有证据前缓议）；④R-80 缓议（R-70/74 后图像 lane 收缩为纯背景，缓存可触达支出需 R-77 数据）。R-78/R-82 工程量小保留。
- **E-6 [major] R-70/R-71 必须修改（小改）**：两条耦合（都改样张决策收据节与 SAMPLE-GATE 呈现物；R-71 上线本身改变人在样张门的决策，live run 层面污染 R-70 的 ≥90% 归因），"独立验收独立裁剪"在此不成立。→ 明确串行；R-70 指标宣称锁定回放集（固定母版，隔离人因）；合同修订按条目分 commit。
- **E-7 [minor] R-73 建议**：校准集构建时机——R-70 转正后文字密集页不再走图像 lane，R-73 可拦截范围收缩为残余纯图像页；现在建集一部分 fixture 会作废。→ R-73 排 R-70 后，校准集按落地后页型混合采集。
- **E-8 [minor] 全批 建议**：14 条无工程量分级（S/M/L），优先级与投入脱钩。按已核实基建推断：R-77/R-76 一期约 S，R-71 约 M，R-70/R-72 约 L。→ 总览表加工程量列与预期节省口径（token/人力/时延三选一）。
- **E-9 [minor] R-70 质疑待答辩**：盲评门对个人技能而言 n=1 既不盲也不可复现，"改一版再评"循环无预算上限。→ 定义最小评审协议（人数、结构化评分表、最多 2 轮复评）或答辩单评审者场景的严肃性。

## 建议实施排序（前 3）

1. **R-77 最小子集（TF 触发率 + 成本对账聚合）**——S 工程量、依赖齐备、只读无风险；先立基线。
2. **R-71 全册确定性预览**——P0 中 ROI 最高：零 token、无盲评风险、每 run 省最贵返工，且为 R-70 开发提供预览工具。
3. **R-70 分阶段转正**——先降级形态覆盖数据/文本密集页并跑盲评协议，通过再全面转正；失败则沉没成本锁定最小面。

## 一句话立场

方向押对了但顺序押反了：先花小钱立基线与预览（R-77→R-71），再分阶段押 R-70 这个大赌注，R-72 等需求证据、P2 砍掉一半——同样 14 条按 ROI 重排后风险敞口减半而收益不损失。
