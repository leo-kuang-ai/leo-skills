# leo-ppt-generator 质量回路优化方案（PPT 审查反哺）

- 日期：2026-08-28
- 证据来源：`ppt-quality-workspace/` 的 20 轮多 agent 审查（约 200 条发现）、5 评审官 × 8 维测评（总均分 8.63、6 维零方差）、18 页逐页验收审查（14 页无缺陷、4 项发现中 2 项经坐标核实为误判）
- 状态：方案待确认后进入 spec-plan / 开发；本文档不改动任何行为

## 一、结论先行

本次"研究业界 → 产出方法论 deck → 多轮对抗审查 → 独立测评"的全流程，本身构成一次对
skill 质量回路的大规模实测。实测确认了 skill 现有设计的正确性（五层非补偿质量门、样张
合同、对抗式审查、unknown 纪律、revision 纪律均在成品流程中真实生效），同时暴露了六个
skill 尚未覆盖、且已被实测证明高价值的缺口。按杠杆排序如下。

## 二、与现状的边界

已有、本方案不重复的能力：

- 内容合同八要素 + 来源不足标 unknown（`references/image-deck-workflow.md` 步骤 1）
- 大纲确认与页面角色七分类（步骤 2）
- 五层非补偿质量门、任一失败打回该页（步骤 10 / `references/visual-qa.md`）
- 对抗式审查清单与量化阈值（字号 18/16/14、对比度 4.5:1、字重阶梯、双线索、安全区）
- artifact revision 纪律（变更后新 revision、重新组装渲染复验、旧验证作废）

## 三、优化项

### P0-1 逐页内容母版（deck-master）作为 generate 的显式工件

- **证据**：本次全部 20 轮审查打在母版上而非成品图上——发现（如"S6 断言超出证据范围"）
  在母版层修复只改一行文本，随后单命令重建、QA、hash 记 revision。对照 skill 现状：
  大纲确认是列表级（角色/结论/来源/衔接），版式与视觉落位不在合同里，审查只能发生在
  成品 PNG 上，发现即整页重做，成本差即 deck 方法论 S9 论证的"1 vs N"。
- **落点**：`references/image-deck-workflow.md` 步骤 2 扩展 + 新增
  `references/deck-master.md`；`evals/` 增用例。
- **改动**：步骤 2 的"输出大纲"升级为"输出逐页母版"——每页固定四段：结论句标题 /
  要点（≤6 条、每条 ≤2 行）/ 视觉行（该页容器清单与每个要点的落位声明）/ 备注（口播与
  细则，不上版面）。母版确认后才进入风格与样张；母版文件纳入项目工件，参与 revision
  与 diff，后续所有修复优先改母版再重建。
- **验收**：新增 eval 用例 `master-before-render`——advise 模式下要求先产出母版并等待
  确认；`master-revision-on-fix`——视觉门失败后首先在母版层修复并 diff，而非直接改
  worker prompt。

### P0-2 修复波及复查（fix-regression check）

- **证据**：R11–R19 的修复多次引入新问题——R17 给 S10 加判定括注导致 R18 密度镜头
  抓到 90 字长难句；R15 压缩 S6 断言导致 R20 又抓回证据范围问题。修复不是终点，必须
  复查"修复目标项 + 修复可能波及项"。
- **落点**：`references/visual-qa.md` 第二节流程第 4 步；`prompts/slide-worker.md` 自查
  清单。
- **改动**：打回重做后的再检清单从"重跑全量对抗清单"细化为"目标判据 + 波及面"：目标
  判据（本次失败项）、同通道波及（改文字→查密度与截断；改颜色→查对比度与双线索；
  改版式→查安全区与样张继承）、以及"修复未引入新缺陷"的显式结论句写入 `qa_note`。
- **验收**：eval 用例 `fix-regression-note`——打回重做后的 `qa_note` 必须包含目标判据
  与波及面两部分；只写"已修复"判 FAIL。

### P1-3 断言-来源三级标注（引用 / 估算 / 示意 + unknown）

- **证据**：终局 P1 猎手轮抓到的最高价值发现均属此类——"主流工具**均**以大纲为首个
  确认点"超出两源证据范围；示意条形图被自家的"无量化数据不用图表"红线击穿。skill
  现有 unknown 是二态（有源/无源），缺"估算/示意"中间态与"断言强度不超证据等级"判据。
- **落点**：`references/image-deck-workflow.md` 步骤 1；`references/visual-qa.md` 第三节
  "数据"块。
- **改动**：内容合同把数字与因果断言分为三级——引用（有出处，正文可断言）、估算
  （本仓/经验推算，必须括注"估算"或"经验值"）、示意（修辞对比，不得使用图表版式呈现，
  必须标"示意"）。视觉门"数据"块加一条找茬问句："本页每个数字/断言的强度是否超出其
  来源等级？示意值是否用了图表版式？"
- **验收**：eval 用例 `assertion-source-tier`——包含无来源"70% 用户"数字的输入，
  advise 输出必须标 unknown 或求证；包含修辞对比的页面若用 KPI/H-Bar 版式应被视觉门
  打回。

### P1-4 多轮审查协议（镜头池轮换 + 收敛判据 + 台账）

- **证据**：单轮对抗清单会在 2–3 轮后饱和（R7/R8 出现 NONE），但轮换到新镜头
  （一致性、逻辑链、冷读者、P1 猎手）后 R11–R20 仍捕获 13 条 P1/P2 级真问题。收敛
  的正确判据是"多镜头 NONE"而非"单清单查完"。
- **落点**：`references/visual-qa.md` 新增第六节（或独立 `references/review-protocol.md`）。
- **改动**：把高要求任务的审查固化为协议——镜头池（内容事实/叙事结构/工艺可构建/视觉
  系统/受众适配/来源可信/行动启发/一致性/逻辑链）每轮取 3 个并行、逐轮轮换；发现按
  P1（误导或违约）/P2（需琢磨）/P3（锦上添花）分级；修复与驳回都记录台账，驳回必须
  给既定设计依据；连续两轮全镜头 NONE 判收敛；每轮修复后按 P0-2 复查波及。
- **验收**：eval 用例 `review-protocol-convergence`——模拟两轮 NONE 后是否停止；台账
  用例 `ledger-rejection-reason`——驳回记录必须含依据。

### P1-5 构建一致性核对（固定件与引用）

- **证据**：5 评审官独立收敛的三处漂移全部是"规范写了、构建没照办"——页码落右上
  （规范右下）、来源行引用未登记条目（OfficeCLI）、最小字号口径与脚注冲突。以及 R14/R17
  一致性镜头多次抓到"见 SX"指向错误、备注删条后断号。
- **落点**：`references/visual-qa.md` 第四节判据表；结构验证层（`image-deck-workflow.md`
  步骤 9）。
- **改动**：判据表增两行——"合同约定固定件（页码/页脚/署名位）时，位置与字号逐页
  一致"；"页内文本引用（第 X 页/见附录）与实际页码存在性一致"。结构验证清单加"若母版
  有固定件规范，逐页核对落位"。
- **验收**：eval 用例 `fixed-fixture-consistency`——母版规定右下页码，成品某页落右上
  应判 FAIL；`cross-ref-page-exists`——页内写"见第 12 页"而 deck 共 10 页应判 FAIL。

### P2-6 双评审官可选协议（交付档位增强）

- **证据**：5 评审官评分 6/8 维零方差、总极差 0.38——多评审官均值的稳定性远超单点
  判断；但单评审官在"受众适配/一致性"两维出现 1 分摆动，说明个体判断仍有噪声。
- **落点**：`references/execution-contract.md` 交付章节（可选档位，不改变默认流程）。
- **改动**：高要求交付可选"双独立评审官 rubric"——两个独立会话按同一 rubric 打分，
  任一维度分歧 ≥2 分触发复议；结果作为人工视觉验收的补充证据，不替代三证。
- **验收**：eval 用例 `dual-judge-rubric`——输出包含两份独立评分与分歧处理记录。

### P2-7 要点-容器落位声明进 worker 自查

- **证据**：工艺镜头（R12/R19/R20）靠"每个要点必须能说出自己进哪个容器"抓到 7 处
  版式无落位/容器装不下，是构建前最便宜的拦截点。
- **落点**：`prompts/slide-worker.md` 自查清单。
- **改动**：worker 生成前自查"本页每个要点是否都映射到版式容器；是否存在无内容容器"。
- **验收**：并入现有 worker prompt 的合同测试（锚点存在性断言）。

## 四、非目标

- 不改变五层质量门的分层与非补偿语义；不动控制面五字段合同与 reason_code 体系。
- 不在 generate 默认流程强制多轮审查（P1-4 是高要求档协议）与双评审官（P2-6 可选）。
- 不引入对兄弟技能（evidence-first-writing）的运行时依赖；断言三级标注在包内自洽。
- 图片式路线保持"禁止页码/页眉"违禁项不变；P1-5 固定件核对仅适用于合同显式约定
  固定件的场景（如可编辑路线或用户指定）。

## 五、建议实施顺序

P0-1 + P0-2（质量回路主链，互相咬合：母版层修复 + 波及复查）→ P1-3 + P1-5（判据
增补，可与 P0 同批）→ P1-4（协议固化）→ P2-6 / P2-7。每批交付配套 eval 用例与
`known-issues.md` 记录，评测命令沿用 `cd leo-ppt-generator && skill-up run evals/eval.yaml`。
