# 跨行业内容质量测评 fixture 包（20 行业）

依据 [方案 005 v2](../../../../docs/plans/2026-09-07-005-leo-ppt-20-industries-content-quality-evaluation-plan.md) §3.2 构造。本目录是 20 单元任务材料的**唯一权威源**；`evals/cases/content-quality-u*.yaml` 由 `build_cases.py` 从本目录确定性生成（生成侧仅获得允许输入，评审侧答案不进 case）。

## 目录结构

| 路径 | 内容 | 可见性 |
| --- | --- | --- |
| `tasks/u01-*.md` … `u20-*.md` | 20 份任务简报（1,500–3,000 字，含目标/受众/约束/决策背景/页数） | 生成侧（经 case prompt 内嵌副本） |
| `materials/u*.md` | 11 个直出单元的源材料（带来源标注与数字锚点；U04/U10/U16 含跨源冲突） | 生成侧（经 case prompt 内嵌副本） |
| `judge-side/terminology/u*.md` | 20 份行业术语正误对照表（10–15 条/行业，含依据与可核性分级） | **仅评审侧**（A4.1 判官输入） |
| `judge-side/adjudication-u04/u10/u16.md` | 冲突单元的裁决依据与植入冲突清单 | **仅评审侧**（A2.4 判官输入） |
| `judge-side/defect-controls/` | 健康基线与单缺陷植入副本（M0 生成后产生） | **仅评审侧**（L2 校准） |
| `build_cases.py` | 从 tasks/ + materials/ 确定性生成 20 个 case YAML | 评测侧工具 |
| `protocol.json` | D4 冻结的判据/梯度/通过线/模型/成本指纹 | 评测侧 |

## 采样矩阵与梯度（勘误登记）

方案 §3.2 原文称 G1 为「02_行业内容域 有专属 content_rules 的 12 行业」。**仓库实况**
（2026-09-08 核验）：`references/styles/02_行业内容域/` 下 12 个行业目录中仅 5 个有
`_content_rules.md`（医疗健康、咨询法律、政务公共、教育学术、金融审计），其余 7 个
（互联网科技、体育健身、制造能源、文旅餐饮、汽车交通、消费时尚、游戏娱乐）只有风格
brief、无专属内容规则。G2 的 8 行业确实无 content_rules，但其中建筑工程、物流供应链、
公益社会组织存在同域风格文件（位于邻近行业目录），仅农业、传媒出版、航空航天、
大宗商品贸易、人力资源服务为完全无专属风格资产。

**处置**：20 单元、行业、任务、受众、难度型、G2=8 的分母与 L1 通过线（G2 ≥7/8）
按方案冻结不变；报告与 `protocol.json` 中梯度口径改记三档——
`G1-rules`（5，有专属内容规则）、`G1-styles`（7，仅风格资产）、`G2`（8，无专属规则）。
不得把 G1-styles 单元的结果表述为「规则内行业」通过。

## 冻结纪律

- M0 可修正输入歧义；**M1 启动前**冻结 20 单元简报、材料、术语表、判据与 protocol 指纹（SHA-256）。
- 冻结后修改任何输入/判据 = 开启新协议版本，旧结果保留不可混算（方案 §3.4）。
- 术语表「依据」列标 `可核` 的条目才可作为 A4.1 硬失败依据；`常识性` 条目只能产生 judge 提示，不单独判 fail（方案 §3.2：无法核实的行业判断不作为硬失败依据）。
