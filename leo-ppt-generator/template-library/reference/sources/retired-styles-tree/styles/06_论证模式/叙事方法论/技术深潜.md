# 叙事方法论：技术深潜（technical-deepdive）

> **叙事层**条目：管「怎么说」——页序骨架与节奏；「怎么证」由论证模式轴承接（配对见第 4 节），
> RST 关系管同页/拆页（[`../../../rst-paging.md`](../../../rst-paging.md)）——三层正交。
> 拍选配仅白名单（第 5 节，源 [`../叙事拍库.md`](../叙事拍库.md)）。

一句话：机制先行的技术解释叙事——每个主张落在**约束、取舍与可观察行为**
上；组件只在读者需要它之后引入，深度随受众既有知识自适应。

## 1. 适用场景

架构评审、设计文档宣讲、技术方案深潜、内部技术分享、迁移/接入评估——
面向工程受众的机制讲解。

## 2. 页序骨架

节位序列（深度按受众既有知识分配，不复读固定章节顺序；同页/拆页按 RST 关系）：

| 节位 | 页角色（原文） | 沟通任务 |
|---|---|---|
| 问题 | 问题与约束（Problem and constraint） | 问题 + 使它难的约束（为什么不是平凡题） |
| 总览 | 系统总览（System overview） | 系统与组件关系一图 |
| 机制 | 机制走查（Mechanism walkthrough） | 机制逐步讲解（组件后置于需要） |
| 流动 | 数据/控制流（Data or control flow） | 数据与控制怎么流 |
| 契约 | 接口契约（Interface contract） | 边界上的承诺与语义 |
| 取舍 | 取舍对照（Trade-off comparison） | 该机制接受的取舍（与替代项对照） |
| 失效 | 失效模式（Failure mode） | 怎么坏、坏了什么样、怎么办 |
| 实测 | 测量证据（Measurement evidence） | 行为主张的实测（挂版本/配置/负载） |
| 落地 | 采用/迁移路径（Adoption or migration path） | 对建造/运维/迁移意味着什么 |
| 附录 | 参考细节（Reference detail） | 规格与细节（高密度备查） |

## 3. 节奏要点

- 每页讲清**一个机制、一个约束或一个行为**，标题（或同等显著的一行）写
  其后果；图与解释同页——图不裸放，机制不拆到需回忆前页。
- 规格、当前实现、实测、设计观点**四类措辞分明**：行为主张引用版本与配置，
  数字附带条件与负载，已知未知标为开放而非糊成自信描述。
- **规划/愿景设计绝不当作已上线行为呈现**。
- 收束必须落到对建造、运维或迁移的含义，不止于机制自洽。

## 4. 与论证模式轴的关系（正交声明）

- 本条管技术讲解的**页序与节奏**；论证形态由论证模式承接——推荐配对：
  **教学分解**（源声明 Preferred Mode: instructional；机制分解排序、
  概念后置于需要），实测页辅**学术五拍**（Numbers not adjectives）。
- 不重叠：教学分解定「怎么证——分解排序的教学论证」；本条定「问题-约束-
  机制-取舍的深潜页序、四类主张分明与版本/条件挂载纪律」。
