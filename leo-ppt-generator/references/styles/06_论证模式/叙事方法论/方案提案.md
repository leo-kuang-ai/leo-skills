# 叙事方法论：方案提案（solution-proposal）

> **叙事层**条目：管「怎么说」——页序骨架与节奏；「怎么证」由论证模式轴承接（配对见第 4 节），
> RST 关系管同页/拆页（[`../../../rst-paging.md`](../../../rst-paging.md)）——三层正交。
> 拍选配仅白名单（第 5 节，源 [`../叙事拍库.md`](../叙事拍库.md)）。

一句话：面向客户的提案叙事——**先证明理解，再凭一份具体、可计价的方案
挣得这份工作**；建议之后的一切都为让它可信、可签。

## 1. 适用场景

售前提案、投标应答、客户方案汇报、engagement 规划——买方可能已发布
需求书的场合。

## 2. 页序骨架

节位序列（买方有发布需求时，**按其条款的可追溯顺序应答**，不围绕便于
讲述重组；同页/拆页按 RST 关系）：

| 节位 | 页角色（原文） | 沟通任务 |
|---|---|---|
| 理解 | 情境理解（Situation understanding） | 用客户自己的话讲客户的处境 |
| 释需 | 需求解读（Requirement interpretation） | 逐条解读需求书/口头需求 |
| 建议 | 推荐方案（Recommended approach） | 推荐什么、将达成什么 |
| 备选 | 已考虑的替代（Alternatives considered） | 为何不选别的（含现状） |
| 架构 | 方案架构（Solution architecture） | 方案组件与关系总览 |
| 交付 | 交付计划（Delivery plan） | 阶段、里程碑、验收口径 |
| 团队 | 团队与职责（Team and responsibility） | 谁做什么（含客户侧依赖） |
| 凭据 | 证明与参考（Proof and reference） | 案例与参考（按真实范围） |
| 商务 | 商务条款（Commercial terms） | 计价、含什么/不含什么 |
| 风险 | 风险与缓解（Risk and mitigation） | 假设、依赖、敞口与对策 |
| 收束 | 下一步（Next step） | 签核路径上的下一动作 |

## 3. 节奏要点

- 每页**一个承诺、一个方案组件或一个凭据**；标题写客户得到什么，
  不写能力名；承诺与其支撑机制同页。
- 受访者是客户——**绝不做「以乙方为主角」的页面**，同样的版面应承载
  客户的结果。
- 已理解需求、建议承诺、假设、排除项、可选范围**五类显式分明**——此处的
  含混日后就是争议；含与另计分开，对客户的依赖逐项列出。
- 绝不暗示应要求时拿不出的能力、资质、参考或资源；参考与案例按实际范围
  呈现，不做讨喜的泛化。

## 4. 与论证模式轴的关系（正交声明）

- 本条管提案叙事的**页序与节奏**；论证形态由论证模式承接——推荐配对：
  **结论先行金字塔**（源声明 Preferred Mode: pyramid；推荐先行、断言标题、
  可追溯链）。
- 不重叠：金字塔定「怎么证——结论先行的论证骨架」；本条定「先证理解再挣
  工作的提案页序、五类主张分明纪律与按需求书可追溯应答的节奏」。

## 5. 拍库白名单（选配组件，非自由组合）

- 白名单拍：架构（architecture）、风险（risk）、缓解措施（mitigation）、参考文献（references）
- 节奏签名：先风险后管控（risk-then-control）、
  证据简报+决策条（evidence-brief-with-decision-strip）、
  细线静网格（thin-rules-quiet-grid）
