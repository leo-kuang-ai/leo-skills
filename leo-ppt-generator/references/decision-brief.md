# 六节点决策简报（decision brief，R-76）

六个推进节点向人呈现**三行固定摘要**——①变了什么②影响什么③需要决定什么。
非技术用户可读；不代人决策；不新增确认轮次；不是新工件门。本文件是全批
呈现/披露合同的单一来源：R-74/75/78/79 只断言内容字段存在与正确，格式类
FAIL 统一挂本条。一期由 Agent 按本模板成文；确定性构建入口为 runtime
`layout_proposals.decision_brief`（工具 JSON 保留结构化全量证据）。

## 六节点与三要素

| 节点 | 节点标识 | 典型"变了什么" | 典型"需要决定" |
| --- | --- | --- | --- |
| 内容合同 | `contract` | 合同字段（页数口径/时长/受众） | 确认或改写差异项 |
| 大纲 | `outline` | 页集合、结构页、论断式要点 | 认可故事线或打回 |
| 母版 | `master` | 逐页内容稿、数字登记、required_text | 确认母版基线 |
| 视觉方向＋样张 | `visual-sample` | 风格归因、样张、反演三组判读 | 认可方向并进入派发 |
| PARTIAL-GATE | `partial-gate` | 阶段交付范围与缺口 | 接受部分交付或继续 |
| DELIVERY-GATE | `delivery-gate` | 交付物、披露清单（TF-2 页等） | 确认收货 |

每份简报**必须**三要素齐全，缺任一为 FAIL（机器合同：
`brief_field_missing`）；节点必须为六节点之一（`brief_node_invalid`）。

## 用户语言强制项

1. **术语白名单通俗改写**（`layout_proposals.TERM_REWRITES`，随判例扩充）：
   "失效工件"→"之前确认过的样张需要重新确认"；"指纹失效"→"文件变了，
   需要重新检查"；"provenance"→"来源记录"；"post-confirm"→"确认后的修订"；
   "overflow"→"内容超出版式容量"。白名单外技术术语须随句解释。
2. **单行长度上限 60 字**（`brief_line_too_long` 拒绝）：超行时拆句或下钻，
   不截断含义。
3. **清单字段强制"计数＋页码区间"**："第 3、7、12–18 页，共 9 页"——完整
   清单按需下钻，不裸列页码。格式由 `format_page_ranges` 确定性给出。

## 不许编造

波及页数/失效结论一律来自生产者事实：母版节点的波及面引用
`scripts/compute_impact.py` 输出；失效样张引用 `image sample-verify` 结论。
简报不复算、不四舍五入、不"约等"（机器断言：简报页数 == 生产者输出页数，
不符即 FAIL）。

## 呈现与降级

- 六节点简报**寄生既有确认点**呈现，不新增确认轮次。
- **呈现层缺席 → 生产者降级 CLI 报告**：`presentation=cli-fallback`，简报
  文本（`render_brief`）照常落盘/输出，并在交付话术披露"未做交互呈现"。
- **委托模式豁免**：`presentation=exempt-user-delegated`——简报仍必须生成
  （留痕口径），仅交互呈现被豁免；豁免原话按 SAMPLE-GATE 纪律记录。

## 理解性抽查协议（人工-协议，随本条交付）

1. 抽取最近一次节点的简报文本原文（不含任何补充解释）。
2. 请一位非技术读者阅读 ≤60 秒。
3. 请其回答三问：变了什么？影响哪几页/多少页？现在要他决定什么？
4. **通过**＝三问全部答对且能用自己的话复述代价；任一答错即登记简报
   改写判例（术语/长度/结构），回写本文件白名单。
5. 每次真实交付抽查一次，结果记入交付披露（未执行如实写 `not-run`）。

## 与 R-75 的衔接

存在待决 overflow 时，母版/视觉方向节点简报的"需要决定"行必须携带
R-75 提案菜单（≤3 项＋首选标注＋一句话代价）；缺提案字段为 FAIL
（机器断言见 `tests/test_layout_proposals.py`）。
