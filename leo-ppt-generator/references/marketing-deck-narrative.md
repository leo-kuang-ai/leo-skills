# 营销叙事参考（marketing deck narrative）

> 本文档是营销 / 销售 / 融资路演类演示的**内容层叙事参考**：回答「每页讲什么、
> 按买家角色怎么变」，不回答「页面长什么样」——视觉层归风格 brief 库与 style
> 合同，两层解耦。
>
> **加载时机**：generate 路线判定为营销 / 销售 / 路演类内容规划时按需读取
> （大纲与逐页母版阶段最常用）；advise 模式与非营销类 deck 不读取。
>
> **来源与改写**：框架结构源自 marketingskills（MIT，快照 2026-08-28）的
> sales-enablement `deck-frameworks` 与 social `carousel-frameworks`，例句全部
> 中文自拟重写。**数据主张纪律**：上游「转化率提升 X%」式效果断言一律不搬运；
> 本文示例句中的数字均为虚构示意（三级标注的`示意`级），进入真实 deck 前必须
> 替换为用户材料中的真实数字，并完成三级标注与母版数字登记表登记。

## 叙事总弧：Situation → Complication → Resolution

- 说服型 deck 的骨架是 **SCR**：先让买家感到被理解，再展示更好的路。目标不是
  展示功能，而是让买家说出「他懂我的处境」。
- 三段对位 deck 节奏：
  - **Situation（现状问题）= 开篇**：买家每天生活的世界，建立共识；
  - **Complication（问题代价 + 正在发生的变化）= 开篇后段**：现状为何不可
    持续、制造紧迫；「变化页」是从 what-is 切入 what-could-be 的转折点；
  - **Resolution（你的方案）= 中段到收尾**：方法、走查、证据、路径与行动。
- 映射母版 `beat` 词表（情境 / 张力 / 转折 / 回报 / 新常态）：终点页（CTA）
  必须落**新常态**——「说 yes 之后的世界」，不是普通总结；what-is 与
  what-could-be 交替的波形纪律沿用 deck-master（连续 3 页同侧视为 P2）。
- 三拍自检（Human Action Model，与 SCR 同构）：每页 `audience_takeaway` 应可
  归入「当下的不适 / 更好的图景 / 行动的路径」之一；缺一拍听众即停滞——
  无不适 = 没有理由动，无图景 = 没有目的地，无路径 = 没有理由相信你。

## 11 页销售 deck 框架

缺省 11 页、按`结论先行金字塔`论证模式给标题（完整句断言、先于正文可懂、
不写话题词）；**每页标题 = 该页结论句**，全部标题连读应构成完整 SCR 故事线
——即母版合同校验标题连读稿（TITLE-READTHROUGH）的预期形态。合同声明
`中性简报` / `视觉展示`时，标题形态按母版规则放宽，页职责不变。要点按页面
角色禅档位执行（多数页 ≤3 条、每条 ≤2 行）。融资路演复用此骨架：定价页 →
商业模式页、下一步页 → 融资诉求（ask）页。示例场景为虚构的 B2B 工单分派
SaaS，示例数字均为示意。

### 第 1 页：当前世界的问题（Situation）

- 职责：写出买家每天面对的那一个核心挑战，配一个量化问题的数字与醒目图形，
  建立「这就是我」的识别。
- 本页回答：「如果只能描述一个问题、且要让买家脱口而出『这就是我的处境』，
  选哪一个？」
- 示例标题：「工单分派靠人肉记忆，是客服团队每天最先流失的一小时」
- 禁忌：以公司 / 产品自我介绍开场；不接痛点的泛行业趋势；一页塞多个问题。

### 第 2 页：问题的代价（Complication）

- 职责：把问题折算成财务、时间、风险三种代价；选 2-3 个最有冲击力的指标。
- 本页回答：「如果买家接下来 12 个月什么都不做，代价是什么？」
- 示例标题：「错派一张工单，客户就多等一个工作日，而等待中的客户正在流向
  竞品」
- 禁忌：无数据的空泛主张；无依据的恐吓；指标堆砌。

### 第 3 页：正在发生的变化（Complication）

- 职责：指出让老办法不可持续的市场或技术变化，回答「为什么是现在」。
- 本页回答：「市场发生了什么变化，让旧做法难以为继？」
- 示例标题：「客户已经习惯即时响应，工单量却还在逐季上涨——人肉分派追不上了」
- 禁忌：追风口式空趋势；此处仍不得转向产品；过度技术化。

### 第 4 页：你的方法（Resolution）

- 职责：给出你的方法论与独特视角——区别于常规解法的那个「aha」洞察。
- 本页回答：「关于解决这个问题，你相信什么大多数人做错了的判断？」
- 示例标题：「先让分派规则可解释、再让模型学习规则——智能分派不该是黑盒」
- 禁忌：过早列功能清单；行话与缩写；不可证明的「唯一 / 第一」。

### 第 5 页：产品走查（Resolution）

- 职责：展示 3-4 个映射第 1 页痛点的**工作流**（买家第一周会做的事），配截图
  与标注——是工作流叙事，不是功能巡礼。
- 本页回答：「买家上线第一周会在产品里做的 3 件事是什么？」
- 示例标题：「上线第一周只需三个工作流：建规则、看分派理由、一键纠偏」
- 禁忌：展示每个功能；无标注的密集 UI 截图；讲技术不讲结果。

### 第 6 页：证据点（Resolution·回摆）

- 职责：客户标识（买家行业内可识别者优先）+ 关键指标 + 分析机构 / 认证
  （若有），证明「它有效」。
- 本页回答：「能证明产品有效的 3 个数字是什么？」
- 示例标题：「上线客户的首次响应时长、错派率、人均处理量三项指标同向改善」
- 禁忌：无出处的断言；无上下文的 logo 墙；与买家痛点无关的虚荣指标。

### 第 7 页：案例研究（Resolution·回摆）

- 职责：讲好一个与买家相似的客户故事：挑战 → 方案 → 结果（前后对比数字 +
  客户引言）。
- 本页回答：「讲一个客户从挣扎到成功的故事。」
- 示例标题：「一家 40 人客服团队上线 6 周，把高峰期积压清到当天完结」
- 禁忌：一页塞多个案例；无具体数字的泛泛成果；与买家行业无关的客户。

### 第 8 页：实施与时间线（Resolution）

- 职责：分阶段时间线（第几周做什么）+ 双方各自投入 + 支持资源。
- 本页回答：「客户从签约到上线，每周都在做什么？」
- 示例标题：「签约到上线 4 周——第 1 周配置、第 2-3 周接入、第 4 周上线，
  客户侧投入不超过两个工作日」
- 禁忌：流程过度复杂化；隐藏时间成本；回避「我方要投入什么」。

### 第 9 页：ROI / 价值（Resolution）

- 职责：基于买家输入或行业基准的回报测算、回本周期、1-3 年总价值、与不行动
  成本的对比；算式必须可核。
- 本页回答：「如果今天购买，未来 12 个月在钱和小时上是什么样？」
- 示例标题：「按坐席规模测算，省下的响应工时在第一年内覆盖订阅成本」
- 禁忌：不可信的投影；不给算式的 ROI；与买家处境无关的通用数字。

### 第 10 页：定价（Resolution）

- 职责：定价结构与各档包含内容 + 针对买家处境的推荐档位；最多 3 档。
- 本页回答：「多少钱、买到什么、哪个方案适合他？」
- 示例标题：「按坐席计费、三档透明定价——你们这个规模从团队档起步最合适」
- 禁忌：藏价格或含糊其辞；超过 3 档；隐藏成本突袭。

### 第 11 页：下一步 / CTA（新常态）

- 职责：一个带时间线的具体行动 + 说 yes 之后发生什么 + 联系方式；以「新
  常态」图景收束。
- 本页回答：「会议结束后，你希望他做的唯一一件事是什么？」
- 示例标题：「下周启动 5 人小队试点，两周后用数据决定是否全员推广」
- 禁忌：「保持联系」式模糊 CTA；多个互相竞争的下一步；无能量地收尾。

beat 缺省分配（可调，波形以 deck-master 交替规则终审）：情境(1) → 张力(2)
→ 转折(3) → 回报(4-5) → 情境·回摆(6-7) → 回报(8-10，定价页兼记「呼吸」)
→ 新常态(11)。证据 / 案例页回摆 what-is 侧（已验证的事实），避免中段连续
what-could-be。

## 买家角色定制

同一骨架按在场的主要买家增删；角色判定进 deck 合同，增删发生在母版层。

- **技术买家**
  - 增：走查页后加**架构页**（部署形态、集成生态、API 与数据流）+ 安全
    合规细节页。
  - 删：ROI 测算页（他关心能力先于成本）；高层市场趋势（变化页压缩为半页）。
  - 语气：精确、不吹、去营销最高级，尊重其专业判断。
- **经济买家**
  - 增：开篇**执行摘要页** + 带算式的 ROI / TCO 对比页 + 风险与合规要点。
  - 删：架构与技术细节、功能级走查、实施细节（这些他会授权下属处理）。
  - 语气：业务语言、结果导向，用钱与百分比说话。
- **Champion（内部推动者）**
  - 增：**内部转述页**——他向团队与上级汇报用的要点 + 常见反对意见的预
    处理；再加 30 天速赢页与同类公司成功证据。
  - 删：深技术 / 深财务细节；任何他无法在组织内转述的内容。
  - 语气：赋能式——让他拿着这套材料在老板面前显得聪明。

- 判定式增删规则：一页若回答不了当前角色会问的问题，即删；他的第一个问题
  在骨架里没有落点，即增。
- 多角色同场不做平均化：以经济买家为主线，技术细节降级为附录页。
- 感知落差（Perception Gap）：同一卖点对不同风险偏好读法相反——「上手快」
  对初创是速度、对大企业是不稳。主线角色定调后，逐页核对卖点措辞与其风险
  容忍度匹配。

## 六大反模式

判定一行 + 纠正一行；命中即回母版修复，不在成品图上打补丁。

- **功能倾倒（Feature Dump）**
  - 判定：每页 = 一个功能 + 一张截图，没有「所以呢」，与买家世界无连接。
  - 纠正：每个功能页绑定第 1 页痛点；只保留映射痛点的 3-4 个工作流。
- **文字墙（Wall of Text）**
  - 判定：单页 200+ 字——现场没人读。
  - 纠正：必须通读的内容移入留存材料或母版 `speaker_script`；页面只留结论
    句 + 要点（≤3 条、每条 ≤2 行）。
- **缺故事弧（Missing Story Arc）**
  - 判定：逐页孤立，无「问题 → 方案 → 证明」流向，deck 像宣传册不像对话。
  - 纠正：回母版跑标题连读稿；连读不成故事线即重排页序、重写标题。
- **通用截图（Generic Screenshot）**
  - 判定：无标注、无裁切、无上下文的产品截图，买家看不出在看什么、为何
    重要。
  - 纠正：裁到动作、放大相关控件、一个箭头圈注，缩略尺寸下可懂；图源按
    母版视觉行三级标注。
- **过早演示（Premature Demo）**
  - 判定：问题未建立就跳进功能，买家没有参照系。
  - 纠正：演示只进 Resolution 段（走查页起）；此前只谈买家的世界。
- **40 页巨兽（Kitchen Sink）**
  - 判定：一个 deck 塞下所有角色、用例与功能。
  - 纠正：按买家角色表拆 deck；以 11 页骨架为基准上限，增页必须有角色依据。

## 卡片式营销叙事（5 框架）

适用于「逐页一个任务」的卡片式营销 deck（社交图文、知识卡片）：每页交付
一个想法，并让下一页值得翻。对应母版：一卡片 = 一页，框架的逐页任务写入页
职责与要点段（每条只属于一个可复述任务），封面 / 末页即 deck 的开场 / 收束
页；页标题按论证模式条件化——计数与清单式标题可用`中性简报`主题词形态，
钩子与立场页可用`视觉展示`唤起短语，断言式收束用完整句。封面（第 1 页）
必须**独立成立**：在没有后续页的情况下独自传达价值主张。合同按卡片口径
（≤2 页）执行时沿用 deck-master 结构页纪律（唯一卡片兼任开场、收束职能入
备注）。

选框架先于打磨单页：内容形态决定框架，框架决定逐页任务。

- **A 价值堆叠（4-14 页）**
  - 适用：资源 / 工具 / 技巧清单——完整性就是承诺，计数就是钩子。
  - 逐页任务：封面给出**精确计数 + 精确交付物** → 每页一项（配 3-6 个具体
    子项）→ 末页一个行动。
  - 关键纪律：封面数字必须精确兑现，为凑数加填充页即破功——紧的 8 页胜过
    注水的 14 页。
- **B 问题-证明（6-10 页）**
  - 适用：有真实成果、且成果背后有一套系统。
  - 逐页任务：带数字的结果钩子（是结果不是建议）→ 重命名真问题 → 机制页
    点名工具与步骤 → 可保存的实操细节 → 末页**收据**（成果的截图，不是
    描述）。
  - 关键纪律：开环是引擎——首页立论、末页证明、中间解释如何做到；中间页
    若不点名工具与步骤，末页的证明读起来就像运气。
- **C 技巧清单（6-10 页）**
  - 适用：同一主题下的多个可命名技巧。
  - 逐页任务：反常识钩子 → 常见做法为何失败 → 每页一个**命名**技巧（坏 /
    好对照）→ 末页一句话论点 + 保存 / 转发。
  - 关键纪律：技巧必须命名——「三秒法则」可被复述与转引，「保持简短」
    不行；两个技巧能合并成一个就合并、宁可更短。
- **D 观点檄文（4-8 页）**
  - 适用：对某个常见实践的强立场。
  - 逐页任务：挑衅性断言 → 逐页升级的具体罪状（展示细节而非泛指）→ 倒数
    第二页**立场转折**（「问题不在 X，在 Y」）→ 末页署名式收束。
  - 关键纪律：转折是成立前提——无转折是咆哮，有转折是精确划线；不骂自己
    也在做的事。
- **E 演示走查（5-11 页）**
  - 适用：可展示的产品或工作流——看到步骤比描述步骤更有说服力。
  - 逐页任务：成品 + 结果先行 → 它替代的具体痛点 → **步骤总览**（先给
    全图）→ 每步一图一句 → 成品全貌 + 一句定位。
  - 关键纪律：先总览后分步——见过「N 步、X 分钟」全图的读者才会走完；
    截图裁到动作、缩略尺寸下可懂。

## 使用边界

- 本参考只管**内容叙事**：页职责、页序、按角色的增删、标题的结论句写法。
  视觉风格（配色、版式、图表形状、卡片模板的一致性）走风格 brief 库与
  style 合同，不在本文职责内。
- 一切数字、指标、客户名与案例必须来自用户提供的真实材料（证据优先）：
  三级标注（引用 / 估算 / 示意）+ 母版数字登记表缺一不可；本文示例句中的
  虚构数字不得带入真实 deck；对比断言必带基准期间，无基准按编造阻断。
- 11 页是骨架不是配额：提交确认前按母版减法审计逐页问「删掉这页 deck 是否
  仍成立」；卡片式按框架页幅取紧端。
- 上游可迁移的是**经验结构**（SCR、逐页框架、反模式、角色增删）；其平台
  参数（社交平台尺寸、发布与流量分析工作流）不属本技能职责，未纳入本文。
