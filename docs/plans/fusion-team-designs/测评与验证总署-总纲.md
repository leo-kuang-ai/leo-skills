### 1.2 判定原则（效力序展开）

1. **治理红线最高**：任何一家的新测试/新闸门若使既有 49 case 出现非 model_gating 的 FAIL，该变更在合入前必须修复或回滚；既有测试文件的既有断言不得删除（可追加）。"既有 evals 全绿"判定口径 = F-6 的语义分层。
2. **总架构师裁决次之**：退出码统一语义 0/1/2（新闸门）；`linked_assets{sources_manifest@sha256, beta_sidecars@sha256} + builder_id` 收据上下文；TF-2 底图+终图双记；`render:html/render:mermaid/render:echarts` 枚举；确定性承诺分层（SVG 逐字节 / HTML 像素容差）；TF-2 与 render lane 均为"封闭例外 + 样张重确认 + 交付披露"；许可不阻断但登记为卫生项。本总纲逐条落位（见 C-1…C-7 冲突记录）。
3. **团队设计再次**：本总纲不重写四家用例细节，只归并去重补缺；发现四家间冲突时给收拢方案（§9 冲突登记表）。
4. **未执行 ≠ 通过**（不做清单 8）：任何 gate/验证未运行时如实标 `not-run`/skip 并披露，不得当通过引用——本原则同时约束 unittest skip、评测 case、验证分报告三处。

### 1.3 不做什么（总署边界）

- 不新造第四层测试运行器：单测归 unittest、行为归 skill-up、上游回归归 core-tests.yaml、确定性归 golden/fixture——四个既有通道收拢一切新测试。
- 不修改任何被测实现；本文件是唯一新增产物。
- 不把许可兼容做成阻断门（用户已线下确认授权）；来源登记与 NOTICE 作为 D-9 卫生项核验。

### 2.2 命名规范（仓库规范 + 既有惯例）

- **unittest**：`test_<可观察行为>`，否定感知断言用于"不得建议/不得出现"类（如 β 的 `test_soft_over_suggests_downgrade_never_smaller_font` 断言输出不含"缩小字号"）。四家草案已合规，总署只要求：正例（合规输入 → exit 0）与负例（违规输入 → exit 1/2）成对出现；每脚本三态各至少一例（0/1/2 见 §4 闸门表）。
- **fixture**：描述性名（`twice-p9.json`、`over-spec.json`、`mixed.pptx`、`blank.png`），禁止 `test1/fixture2`。
- **eval case id**：kebab-case 场景式，与既有 49 个同风格；新增 31 个 id 清单见 §5.2（已查无与既有重名、无同义重复）。
- **judge 脚本**：`judge_<case_id>.py`，**必须自包含**（C-4）：复制 `judge_common.py` 的 NEGATORS/QUOTE_SPAN/positive/require_positive/forbid_positive 骨架，不得 import（F-3 沙盒事实）。`judge_common.py` 继续作为本地自检工具。

### 2.3 fixture 策略：离线优先

1. **零依赖层**：抽块/映射/指纹/对账/退出码/打分器/投影函数全部纯 Python 可测——四家大多数用例属此类，直接绿。
2. **合成像素层**：visual_qa/aesthetic_metrics 用 Pillow 合成已知构图 fixture（空白页/满页/底边截断/50% 内容占比），不依赖真实渲染输出。
3. **本地网络层**：α `fabricated-url-fails-closed` 用本地 `http.server` 404 fixture，不依赖外网（沿 β/α 设计；R5 缓解）。
4. **确定性回归层**：`tests/fixtures/render_golden.json` 扩展登记 `{template_id, data_sha256, out_sha256}` 与 `{svg_sha256, png_sha256}`——resvg 链路断言逐字节 sha256 相等；playwright 链路登记像素 hash + 容差（0.1%），由 scripts/ 比较器执行（γ §5.2-4）。
5. **唯一允许的外部依赖**：chromium（playwright）与 resvg。见下条 skip 纪律。

### 2.4 skip ≠ pass 披露纪律（未执行≠通过红线的测试面落地）

- 需要浏览器/resvg 的测试在探测失败时 `unittest.skip("render backend missing: <原因>")`，**skip 清单必须出现在测试报告与交付披露**；CI/开发机装有浏览器时必须全跑。
- 每个里程碑验收（§8）强制在**至少一台装有 chromium 的环境**跑一次 `python3 -m unittest discover -s tests -p 'test_*.py'` 并记录 `tests/render/` skip 数为 0，否则该里程碑不得声明 D-2 达成。
- `render_backend_missing` 状态本身有专测（γ `render_ready_reports_missing_backend_without_network`：monkeypatch import 探测，无需真缺环境）。
- resvg 双路径（Py 优先/Node 子进程）测试：Py 路径必测；Node 备选路径在 node 缺失时 skip 并披露（γ §5.1 已列）。

### 2.5 unittest discover 兼容性核查清单

- 所有新目录含 `__init__.py`（`tests/render/` 必须）。
- 测试文件名 `test_*.py`；不引入 conftest/pytest 机制（仓库无 pytest）。
- runtime venv 依赖（python-pptx、PIL、playwright）缺失时**诚实 skip**（沿 F-10 环境型跳过先例），不得因 import 失败把整目录变成收集错误——boundary 既有实践为模块级 try-import + skipUnless。
- 全量命令沿用两种：仓库根 `python3 -m unittest discover -s leo-ppt-generator/tests -p 'test_*.py'`；包内 `cd leo-ppt-generator && python3 -m unittest discover -s tests -p 'test_*.py'`（与 AGENTS.md 的 evidence-first-writing 命令风格一致）。
