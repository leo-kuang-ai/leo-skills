# 逐页内容母版（deck master）

> 本文档定义 generate 路线「逐页内容稿」的结构化形态。母版是内容层的唯一真值工件：
> 用户确认的对象、后续审查与修复的第一落点、以及 revision 与 diff 的锚。它不改变
> 五层质量门，只把「内容事实/叙事结构」两层的检查前移到最便宜的位置。

## 为什么需要母版

成品图上发现内容问题（断言超源、要点无落位、引用错位）时，修复意味着整页重做；
同一问题在母版层修复只改一行文本，随后按已确认流程重建受影响页。审查与修复应尽
可能发生在母版上，而不是逐页产物上。

## 母版结构（每页固定四段）

每页必须包含以下四段，缺任何一段都不得提交用户确认：

1. **结论句标题**：一句话结论，先于正文可懂；不写话题词。
2. **要点**：≤6 条、每条 ≤2 行；每条只属于一个可复述任务。
3. **视觉行**：该页容器清单（卡片/表格/图例条/结论条等），并声明**每个要点落入哪个
   容器**；存在无落位要点或无内容容器即失败。
4. **备注**：口播提示、工程细则与失败路径；备注不上版面。

页面级元信息（角色分类、事实来源、衔接、预计用时）沿用
[`image-deck-workflow.md`](image-deck-workflow.md) 第 3 步要求，置于页首。

## 母版纪律

- 母版确认发生在视觉方向确认之前或同时；未确认母版不得进入样张与批量生成。
- 数字与断言按三级标注（引用/估算/示意，见 workflow 第 1 步）；示意项不得声明使用
  图表版式。
- 若合同约定版面固定件（页码/页脚/署名位），母版视觉行必须写明其位置与字号。
- 页内文本引用（「见第 X 页」「见附录」）必须在母版中与实际页码核对存在。

## 修复回路

- 视觉门或内容门打回后，**先修母版、再重建受影响页**；只在 worker prompt 层打补丁
  而不改母版，视为绕过母版真值。
- 母版文件随 run 工件保留，参与 artifact revision：母版变更即触发受影响页重验。
- 重做后再检必须覆盖「目标判据 + 波及面」（见
  [`visual-qa.md`](visual-qa.md) 流程第 4 步）。
