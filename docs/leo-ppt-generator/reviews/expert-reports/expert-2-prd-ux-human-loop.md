# 专家报告 2 · 用户体验（人在回路负担与决策体验）

- 评审对象：`docs/prd/2026-09-11-leo-ppt-capability-improvement-prd.md`（v1.0）
- 立场：PPT 最终用户（要交差的企业员工、咨询顾问、学术答辩者）的人在回路体验
- 日期：2026-09-11 · 独立盲评

## 总体结论

**有条件通过。** 值得肯定的底子：全批坚持"门数不增、不可自动通过"、R-71 明确写入反面用例、R-72 要求桌面真人验证、R-82 坚持 advisory、R-83 要求归因+回退——但**不系统、不稳定**：凡是和工程目标冲突的地方，用户视角就让位。核心缺陷是三个替代性论证缺失：①用"轮次不增"替代了"负担不增"；②用"生产端数字准确"替代了"接收端可理解"；③用工程指标替代了用户可感知收益。

**通过条件**（B-1/3/4/5/6/7，均必须修改）：
- C1：R-71/R-76 定义"单门审阅材料预算"与渐进披露（缩略总览 + 风险页标注优先），补接收端可理解性验收；
- C2：R-76 增加用户语言强制项（术语白名单、单行长度上限、清单用"计数 + 页码区间"）；
- C3：R-70 目标与验收补用户可感知指标（样张重确认次数下降、混合页端到端时长上限），TF 触发率降为内部代理指标；
- C4：全批新增"用户净影响"论证行，R-81 调度核实提前；
- C5：R-74 呈现必须携带"推荐默认 + 一句理由"；
- C6：R-71 预览指定移动端可打开形态或显式记录放弃。

## Findings

- **B-1 [major] R-71+R-76 必须修改**：样张门审阅材料从"看 1 张图"膨胀为"样张 + 全册预览 + 反演三组判读 + 三行简报"，轮次不变 ≠ 理解成本不变，阅读量无上限约束、无决策耗时度量。→ 定义材料预算与渐进披露（首屏缩略总览 + 机判风险页标注，逐页浏览为下钻）；60s 预览生成与样张生成并行。
- **B-2 [major] R-71 质疑待答辩**："未看过全册预览即派发 = FAIL"与"多问一轮 = FAIL"紧张——"看过"系统侧不可观测，最可能退化为合规仪式。→ 明确判定口径（同轮呈现+授权即视为已呈现，不要求 attestation）；附"同页骨架 vs 成品对照"作保真度校准锚点。
- **B-3 [major] R-71/R-78 必须修改**：移动端与 IM 汇报场景全批缺席（飞书/微信手机审阅是高频场景）。→ 预览加移动可行性（响应式单文件或联系表 PDF 导出）；R-78 拼图分页可放大；不做则显式非目标记录。
- **B-4 [major] R-70 必须修改**：成功全部用工程指标定义，用户可感知收益（TF-2 转正 → 运行中切换不再强制样张重确认 → 被打断次数下降；错字结构性消失）没进验收。→ 目标改用户价值陈述 + 配套指标，TF 触发率降为内部代理指标。
- **B-5 [major] R-76 必须修改**：三行简报对非技术用户不可读（"波及页/失效工件"是工程词汇；清单型字段会击穿三行）。→ 术语白名单/通俗改写规则；单行长度上限；清单强制"计数 + 页码区间"（"第 3、7、12–18 页，共 9 页"）；补理解性 evals。
- **B-6 [major] 全批 必须修改**：无一条论证用户等待/步数/理解成本净影响——系统性优先倒挂：增加阅读负担的条目在 P0/P1，唯一直接削等待的 R-81 躺 P2。→ 每条加"用户净影响"行；R-81 核实提前。
- **B-7 [major] R-74 必须修改**：lane 方案等于在既有门上新增技术选型决策，"lane"对用户不可理解，无默认推荐时变成橡皮图章。→ 呈现强制"推荐默认 + 一句理由 + 备选折叠"，一句话可采纳，不裸露 lane 术语。
- **B-8 [minor] R-80 建议**：跨 run 复用同一素材 = 用户先后两份 PPT 可能撞图，省钱变成用户不知情的质量降级。→ 复用命中在样张/简报层披露或提供档案级开关。
- **B-9 [minor] R-73 建议**：误报 ≤5% 的用户面代价（好页被拦 → 重渲 → 多等多花钱）无处体现。→ 误报复检在交付披露标注；校准指标加"误报导致的用户可见重试"维度。
- **B-10 [minor] R-75 建议**：提案菜单无候选上限，5 个带测算的方案本身又是一份小报告。→ 候选 ≤3，每项一句话代价，默认标注首选项。

## 一句话立场

工程指标全绿不等于交付体验变好——把验收口径从"门没多、数字没编"升级为"负担没涨、语言可读、等待可感知下降"，才真正站在要交差的那个人一边。
