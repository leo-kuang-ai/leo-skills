## 3. 详细技术设计

### 3.1 A1《学术图表证据规则》reference + 母版图行合同

**新文件 `references/academic-figure-evidence.md`**（全部原创中文措辞，借 scholar-ppt-cn MIT 思想）内容骨架：

1. **选图先于版式**：每张入 deck 的图必须回答一个明确的演示问题（对应母版"服务的比较"字段）；不推进论证的图删除或留 `not-use`。
2. **6 种处理模式**（封闭枚举，进母版视觉行与 sources manifest）：
   `preserve`（整图保留）/ `overview+detail`（总览图 + 已有独立面板或用户提供细节图）/ `split`（独立面板分页讲解，保留标签与上下文）/ `cross-slide`（一张核心复杂图跨多页）/ `not-use`（不用：无关/不可读/重复/误导）/ `request-higher-resolution`（关键图无法忠实呈现时先求高清源）。本地裁剪**不是**默认能力：全图密集或比例不佳时，优先 preserve / cross-slide / 已有独立面板 / 求高清 / 弃用。
3. **图视觉审查 5 级状态**（封闭枚举）：`vision-reviewed`（真打开图看过）/ `metadata-reviewed`（只看了尺寸页码等元数据）/ `caption-inferred`（仅从图注推断）/ `user-described`（依用户口述）/ `not-reviewed`。**只有 `vision-reviewed` 的图允许母版/提示词中出现基于图内位置或图内结构的标注**（如"高亮右上子图""箭头 ② 指向的通路"）；否则标 `figure_review_status_insufficient` 打回。
4. **原图裸上纪律**：学术证据图默认不加边框/卡片/白色垫板/圆角容器/阴影，直接坐在版面上；轴、图例、单位、比例尺、panel 标签、表头必须可见；多图用留白/对齐/编号/简短图注区分，不靠包框；禁止自动"高亮区域"裁剪。高危拆分、跨页讲解、核心证据替换必须确认或明确披露（寄生母版确认点）。
5. **图过多/过小的降级顺序**（固定次序，不可跳步）：①删不必要图 → ②减解释结构 → ③放大关键图 → ④不同证据拆页 → ⑤对密集核心图用 overview+detail / split / cross-slide → ⑥省略撑不起可读页的次要证据。不得把多图缩成不可读缩略图"证明读过论文"。
6. **母版图行绑定语法**（机读，`check_master_contract.py` v2 消费）：

   ```text
   图[F3] 模式:preserve 状态:vision-reviewed 焦点:消融对比的主表
   承载:表2的误差线与均值 | 服务:方法A vs 基线的显著性比较 | 避免误读:误差线不等于统计显著性
   ```

   `figure_id`（`F<数字>`，deck 内唯一）+ `focus`（这张图回答的演示问题）为必填；`模式`/`状态` 必填且取值在封闭枚举内。
7. **与既有真值的关系**：图的"来源三级"（实拍/生成-氛围/生成-示意，deck-master L26）继续管来源等级；本规则管处理方式与审查状态；两者同写一行。数据页数值仍按图表样式规范的置信度形状语法。Paper2Slides 保真条款并入：方法页如含公式须保留 LaTeX 原式 + 变量解释（引用级）；表格 extract 必须带真实数值，不得四舍五入重写。

**`deck-master.md` 修改**：视觉行段（L24–L27）增补"页面用图按《学术图表证据规则》逐图登记 `图[F*] 模式/状态/焦点/承载/服务/避免误读` 行"。

**`check_master_contract.py` 扩展（母版机读语法 v2）**：
- 新增 `FIGURE_ROW_RE`：匹配 `图[F\d+]\s+模式:(\S+)\s+状态:(\S+)(...)` 与三段行 `承载:... \| 服务:... \| 避免误读:...`。
- 校验：模式/状态枚举合法；`figure_id` deck 内唯一；三段（承载/服务/避免误读）齐备；`状态 != vision-reviewed` 的图行文本中不得出现位置性标注词（"高亮…区域/右上/子图/箭头"等白名单词表）→ 命中即 FAIL（exit 1）。
- 交叉：图行 `figure_id` 与 sources manifest（若在场）的 `figure_id` 对得上（A2 校验器负责，母版校验器只管母版内一致性）。
- 向后兼容：不含 `图[F` 行的母版不触发该校验（旧 deck 恢复天然兼容，CI-3）。
- 输出新增 `MASTER-SCHEMA: v2` 行，供评测与下游识别语法版本。

**加载阶段（按需读取治理）**：`execute` + Route=generate、进入母版制作阶段（第 3 步）且材料含图片证据/学术场景时读取；与 `deck-master.md` 同批。SKILL.md 按需读取表 `generate` 行追加该文件（延迟列原则不变）。**不得**在入口/Route 判断阶段读取。

### 3.2 A2 sources_manifest.json（证据治理权威工件）

**Schema v1（`references/sources-manifest-schema.md` 定义，canonical JSON 排序键，原子写）**：

```json
{
  "schema_version": 1,
  "manifest_kind": "visual-sources",
  "route": "generate",
  "run_ref": "runs/<run-id>",
  "generated_from": "content/deck-master-v3.md",
  "pages": [
    {
      "page_id": "slide_02",
      "visuals": [
        {
          "visual_id": "v1",
          "figure_id": "F3",
          "kind": "figure",
          "source_class": "user-material",
          "tier": "引用",
          "handling_mode": "preserve",
          "review_status": "vision-reviewed",
          "source_ref": "sources/paper/fig3.png",
          "source_sha256": "…",
          "backend": "user"
        },
        {
          "visual_id": "v2",
          "kind": "background",
          "source_class": "ai-generated",
          "tier": "示意",
          "handling_mode": null,
          "review_status": null,
          "source_ref": null,
          "source_sha256": null,
          "backend": "builtin-imagegen"
        }
      ]
    }
  ],
  "contents_sha256": "…"
}
```

字段规则：

- `source_class` 封闭枚举：`user-material`（用户素材原图）/ `derived-crop`（用户素材裁剪派生）/ `ai-generated`（AI 生成）/ `illustrative`（示意图/修辞图）/ `native-rebuild`（对象级原生重建，仅 upgrade）/ `deterministic-render`（CI-1 渲染 lane 产物）。
- `tier` ∈ {引用, 估算, 示意}——三级标注的逐图投影（不新增第四级；`unknown` 不入 manifest，入 manifest 前必须先求证闭环）。
- `handling_mode`/`review_status` 复用 A1 枚举；非图类 visual（背景/装饰）可为 `null`。
- `backend` 与 image record / imagegen-jobs 的 backend 词表同一来源；按 CI-1 预留 `render:html` / `render:mermaid` / `render:echarts` 前缀（γ 扩展枚举时无需改 schema）。
- `source_ref`：本地文件用相对 `sources/` 或 run input 的 POSIX 路径；URL 用完整 https URL（A3 校验可达性）；`null` 仅允许 `source_class ∈ {ai-generated, native-rebuild}` 且 `tier=示意/估算`。
- `contents_sha256`：`sha256(canonical_json(去掉本字段后的整个对象))`——自指纹，γ 的五指纹收据直接消费；任何字段变更必然翻转（可 diff：键序 canonical，diff 即语义 diff）（CI-2）。
- 敏感纪律：复用 evidence.py 的 `_SENSITIVE` 正则扫描，命中即 `sources_manifest_invalid`。

**生成与冻结（CLI 真值，不手写领域状态）**：

- generate：agent 从 confirmed 母版视觉行**派生**（母版仍是人确认的内容真值；manifest 是机器投影），写入 `<project-root>/content/sources-manifest.json`；`image prepare` 新增 `--sources <path>` 参数，runtime 校验 schema 后复制冻结进 `<run>/input/sources-manifest.json`，并把其 `contents_sha256` 并入 `prepare_fingerprint` 的输入集合（adapter.py `prepare()` 改动：fingerprint = sha256(canonical({slides, sources_manifest}))；旧 run 无 sources 输入时保持原 fingerprint 算法并记 `sources: null`，保证恢复兼容，CI-3 迁移注记写入 schema 文档）。
- upgrade-full / upgrade-selected / direct-editable：由页级 `manifest.json` 的 `asset_provenance`（source_type 枚举）+ `imagegen-jobs.json`（backend/output_sha256）聚合生成——`scripts/check_sources_manifest.py --compile <run>` 子模式读取各页 provenance 聚合为 deck 级 manifest（`source_type: user-provided/asset-sheet-separated → user-material/derived-crop`；`imagegen → ai-generated`；`user-approved-rasterization → derived-crop`）。δ 若在 F5 引入稳定对象 ID，聚合时填 `object_ref`（见第 10 节）。

**校验脚本 `scripts/check_sources_manifest.py`**（退出码 CI-4：0 过 / 1 FAIL 阻断 / 2 WARN 可交付）：

- 输入：`<run>/input/sources-manifest.json` + `<run>`（对照 slide_jobs.json 页集合）+ 母版文档（可选，对照图行）。
- 默认档校验：schema/枚举/figure_id 唯一/页集合覆盖（每页至少一条 visual 或显式 `visuals: []`）/`contents_sha256` 自洽/敏感扫描。命中 → 1。
- WARN 档（exit 2，可交付但披露）：`review_status ∈ {caption-inferred, user-described, not-reviewed}` 的图存在；`handling_mode=request-higher-resolution` 未闭环；URL 缓存过期（A3 TTL）。
- `--strict` 档（FAIL）：在默认档之上追加——①`tier=引用` 的每条 visual 必须能回溯到用户输入（`source_ref` 存在于 `<project-root>/sources/` 或 run 冻结输入且 `source_sha256` 匹配）；②`tier=引用` 且 `source_class ∈ {ai-generated, illustrative}` → FAIL（AI 图冒充实拍证据，与 visual-qa"生成图禁入证据槽"联动）；③与母版图行的 figure_id 集合一致；④`review_status != vision-reviewed` 的引用级图带位置性标注 → FAIL。
- 输出 JSON 行摘要（页号 × 判据 id），供 γ 的 E2 像素 QA 报告与指纹收据对账。

**DELIVERY-GATE 接入**：`execution-contract.md` 交付节 + `SKILL.md` 交付不变量各加一句：含图片证据的交付（generate 全部、upgrade 聚合后）交付前必须运行 `python3 scripts/check_sources_manifest.py <run> --strict`（在技能目录内执行），非 0 退出（1 或 strict 下的 2）阻止交付——与 `check_deck_geometry.py` 同一模式，不新增人在回路门（CI-5）。

**reason codes 新增**（reason-codes.md，语义稳定承诺）：`sources_manifest_missing`（prepare/交付时缺 manifest 且路线要求）、`sources_manifest_invalid`（schema/枚举/自指纹/敏感命中）、`source_unverifiable`（strict 下引用级无法回溯用户输入，可恢复：补源文件或降级为示意并重新确认）。

### 3.3 A3 素材存在性 / URL 可达性校验闭环

**新脚本 `scripts/validate_assets.py`**（Python stdlib urllib，无 Node，CI-6）：

- 输入：sources manifest（优先）或 slides.json 的 `required_images`/`input_images` 列表；`--offline` 只做本地。
- 本地检查：路径存在、可读、是图片（PIL 头读取，与 contracts.py 同法）、sha256 与 manifest 记录一致。
- URL 检查：仅 `https://`；`HEAD`（405 时降级 `GET` + Range 0–1024）；超时 10s；2xx/3xx 为可达；结果与 `Content-Type` 前缀记录。**不下载整文件、不执行任何内容**。
- 缓存：`<project-root>/sources/.asset-validation.json`（键 = URL/路径 + sha256，值 = 状态/时间戳/最终 URL），用于报告 diff 与"校验→替换→重验"闭环的第二次比对；缓存永不作为"通过"的替代——交付前重跑必须全绿。
- 闭环合同（写进 image-deck-workflow 第 1 步与第 7 步之间）：素材校验失败 → 该素材标 `unknown`（禁止入页）→ 二选一：用户提供真实素材 / 改为 AI 生成并标示意 → 重跑校验 → 缓存 diff 展示替换前后。编造链接直接出图 = 红灯（红灯清单加一行）。
- 退出码：0 全可达 / 1 存在不可达（阻断入页）/ 2 仅缓存过期或慢端警告。
- reason code：`asset_validation_failed`（可恢复：替换素材或降级示意）。

**署名**：机制源自 OpenCanvas `image_validation`（MIT）；脚本头注 + upstreams.yaml 登记（第 8 节）。

### 3.5 C1 slide-worker 提示词四件套

### 3.6 C2 Text Fidelity Fallback 降级链

**触发**：视觉质检"文字准确性"失败（错字/漏字/白名单外文字），且视觉方向本身已接受（ian 的适用前提）。

**TF-1 压文本预算重生成**：回到母版做要点减法（禅档位降一档 / 每条压缩 / 标签数减半），登记 `revision_kind: post-confirm`（页数或结构变化才退回 pending，复用既有 3a 通道）→ 白名单更新 → 同 backend 同方法重生成该页。TF-1 优先于 TF-2，且至少尝试一轮。文本预算参考：标题 ≤12 字、要点每条 ≤2 行、标签 ≤5 个、图注 ≤6 条每条 ≤12 字（与禅档位联动，非新档位）。

**TF-2 留白版式 + 确定性贴字**：TF-1 仍失败时——

1. 用确认的 backend 生成"留白版式页"：prompt 声明为每个白名单文字项预留空白区，禁止任何占位假字（no invented placeholder writing）；
2. `scripts/overlay_text.py`（新，Pillow 确定性）：读该页 `required_text[]` + 版式锚点（母版视觉行声明的容器落位区域），逐字渲染叠加；字体来自风格 brief 字体段；输出 PNG 尺寸档必须保持 2560×1440（贴字后重验画幅）；
3. **治理对齐（关键）**：TF-2 = `sample_generation_method` 变更。SKILL.md 既有规则（L108–L112）已规定方法变更须"重新生成并确认样张"——TF-2 的启用**天然寄生样张确认点**，零新增确认门（CI-5）；未经该确认，slide-worker 的 "manually composited text overlays" 禁令（L41）不变。`image-deck-workflow.md` 该段（L104–L106）追加例外条款："唯一例外：经样张确认的 text-fidelity-fallback 模式，底图仍须来自确认 backend，叠加文字由 `overlay_text.py` 确定性产生并逐字来自白名单"。
4. 记录：sources manifest 该页加 `{"visual_id": "text-overlay", "source_class": "deterministic-overlay"}`（`source_class` 枚举增此值）；slide job 记 `text_fallback: true`；交付披露逐页列明 fallback 页；qa_note 写"TF-2 engaged + 白名单逐字 + 无残留生成假字复检"。
5. reason code：`text_fallback_engaged`（状态码，非错误）；`text_budget_exhausted`（TF-1+TF-2 均失败 → 该页 blocked，回母版重构或换 backend，不得无限重试）。

**回滚**：TF-2 未获样张确认即整链禁用（退回现状"整页重生"），其余 A/C 动作不受影响。

### 3.7 C3 论断式大纲规则（AGPL 红线：全部原创措辞）

**规则**（deck-master 要点段 + image-deck-workflow 大纲/母版步骤）：

- 内容页（论点/证据/解释/方案/台账等）**第一条要点必须是完整论断句**——主谓宾齐备、可独立成立、听众不听讲解也能读懂的判断句；其后 1–2 条要点是该论断的证据跟随（数字/图/引用），逐条带三级短标。
- **功能页豁免**：开场（封面）、目录、章节隔断、收束页的第一条要点不要求论断句（陈述/金句/呼应用途）。
- 与既有"结论句标题"两段贯通：标题是页级论断（结论先行金字塔模式），第一条要点是论据层的第一论断——大纲-标题-要点三层连读成同一故事线。
- **takeaway 连读**：`check_master_contract.py` 新增输出 `TAKEAWAY-READTHROUGH: <全部内容页第一条要点连读>`，与既有 `TITLE-READTHROUGH` 并列；连读不成故事线 → 打回母版（同现有判据纪律）。功能页不进连读。
- 实现要点：识别"第一条要点"沿用 `POINT_LINE_RE` 的既有解析（排除 `_NON_POINT` 前缀行）；功能页识别依据页面角色行（`角色[:：]`或页首元信息 `role`），角色词表取 13_页面语义（开场/目录/章节/收束）。
- 登记方式：banana-slides 只登记为 idea-borrowed（无文本搬运），设计文档与本节即为原创性声明载体（第 8 节）。

### 3.8 C4 母版合同学术字段 + rubric 锚点

**合同层**（image-deck-workflow 第 1 步冻结项追加，三字段可选、学术场景必填）：

- `math_load`：`light | medium | heavy`（公式密度与推导深度；heavy = 页均含公式或含推导链）。
- `figure_orientation`：`figure-first | balanced | text-first`（图表取向，驱动版式与页数倾向）。
- `section_priority`：节级表 `| 节 | 优先级 H/M/L | 建议页数 |`——高优先节多页、低优先节压缩或并入；与页数口径算式（既有）对账，Σ建议页数 ≠ 内容页数时 WARN。

```text
deck-contract:
  math_load: medium
  figure_orientation: figure-first
  section_priority: | 节 | H/M/L | 页数 | …
```

**rubric 锚点**：三字段成为 visual-qa 镜头池新镜头"合同锚点"（contract-anchor）的判据源——审查时逐页对照：figure-first deck 的图页占比是否 ≥ 六成、math_load=heavy 是否保留了公式原式与变量解释、section_priority 的 H 节是否拿到页数、L 节是否被压缩。γ 的双评审官 rubric（分歧 ≥2 分复议）可直接引用本锚点，交付评审不再"确认完就散在聊天记录里"（ArcDeck commitment_refs 思想：每条评审发现可指回 `math_load/figure_orientation/section_priority` 条目）。

### 3.9 C5 RST 分页启发式

**新文件 `references/rst-paging.md`**（原创中文表述，ArcDeck MIT 思想）：

- 8 关系封闭词表（中文对照 + 英文码）：`elaboration（细化）/ explanation（解释）/ context（背景）/ purpose（目的）/ evaluation（评价）/ organization（组织）/ joint（并列）/ same-unit（同单元）`。
- 分页启发式表（轻量版，不做树解析）：

  | 关系 | 分页规则 |
  | --- | --- |
  | elaboration / explanation | 核心段与其细化/解释段**同页**（拆开即断因果） |
  | same-unit | **绝不拆页**（本来就是一个单元被排版切开） |
  | evaluation | 评价/局限内容**可独立成页**（长时优先独立） |
  | joint | 同级并列 ≤4 段可同页，>4 拆页或改台账版式 |
  | context / purpose | 常作页首（背景/动机开场） |
  | organization | 作主题句与后续内容同页 |

- **与禅档位的关系**：禅档位管"一页装多少"（容量），RST 关系管"哪些内容必须同页/必须拆页"（结构）——双判据：先按 RST 定内容分组边界，再按禅档位定每组页数与要点上限；两判据冲突时（如 same-unit 组内容超档位容量）按 A1 降级顺序处理（拆图/减结构/升档），不得拆 same-unit。
- **接入**：大纲文档每页行可选标注 `rst: 与前页关系`；母版页首元信息可选 `rst_relation` 字段；两者均为 advisory（不进 check 硬校验），确认摘要中呈现"分页依据"一句。C4 的 section_priority 表与 RST 分组天然对齐（节 = 关系分组的外层）。
- 加载阶段：generate 路线大纲制作阶段按需读取（材料多段/结构复杂/学术长文时），与 deck-master.md 同批；不进入口阶段。
