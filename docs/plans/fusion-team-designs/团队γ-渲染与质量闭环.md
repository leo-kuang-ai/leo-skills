## 1. 设计目标与范围

### 1.1 目标

1. **D 柱（确定性渲染 lane）**：为 generate 路线增加与图像模型并列的第二类页产物来源。页型路由两条 lane：图像模型继续管视觉创意页（封面/概念/氛围），确定性渲染接管正确性合同最重的页型（数据图表/表格/文字密集）。`backend-selection.md` 已有 `chart|text-heavy|image` 页型路由与 `backend_stats.jsonl` 通过率统计（见 §2.3），本层只接入插槽，不推翻既有路由。
2. **E 柱（质量闭环机器化）**：把"已审"从状态字段变成不可伪造、不会静默过期的事实——指纹收据（E1）、确定性像素 QA 前置闸门（E2）、美学度量（E3）、worker 三层容错（E4）、渲染器感知 lint（E5）、提示词进化记账（E6）。

### 1.3 非目标

- 不替代图像模型路线，不改变四条 route 的定义与确认门序列。
- 不引入 Node 进 PPTX 组装路径（冲突裁决 1）；resvg 仅以独立子进程出现在渲染叶子节点。
- 不做 foreignObject 系 CLI 成图、不做 canvas 序列化（明确不做清单 4/5）。

## 3. 详细技术设计

### 3.0 总体架构（文字版）

```
页型路由（backend-selection.md，既有）
  ├─ image lane（不变）：worker → 图像模型 → image record --backend <provider>
  └─ render lane（新增）：
       父 Agent 路由判定（页型 + backend_stats + render backend readiness）
         ├─ D1 页面级：render page --template <id> --data slide.json
         │     └─ playwright-python：本地 HTTP 字体服务 + 模板 deterministic 模式
         │        + fonts.ready + data-leo-ready 信号 + viewport1280×720×dsf2 → 2560×1440 PNG
         ├─ D2 图表级：render chart --dialect mermaid --source <11_图表语法文件或内联>
         │     └─ 同一浏览器实例内 mermaid.render → SVG
         ├─ D4 图表级：render chart --dialect echarts --option <option.json>（P2）
         │     └─ 同一浏览器实例内 echarts.renderToSVGString → SVG
         ├─ D3 栅格化：SVG → resvg 子进程（stdin/stdout JSON）→ PNG 2560 宽
         └─ D5 后处理：Pillow 变体（delivery 2560 / web 1280）+ 体积治理
       产物 + render provenance sidecar → image record --backend render:html|render:mermaid|render:echarts
         └─ CI-1：与图像模型产物同构（sha256/lease/operation/backend_stats）

质量闭环（E 柱，横跨两条 lane）：
  每页：E2 visual_qa.py（0/1/2，FAIL 页不进 LLM 审）→ visual-qa.md 对抗审查（既有）
       + E3 aesthetic_metrics.py（WARN 披露，镜头池确定性镜头）
  全册：E4 三层容错（阶段分层重试≤3 → sweep ≤2 轮 → rendered 页跳过）
  交付：E1 delivery receipt（五类 sha256 + 新鲜度断言 + 指纹 diff 波及页）
       → validation-summary quality_gates.delivery_receipt → delivery_readiness
  治理：E5 渲染器感知 lint（规则-渲染器映射 + 跳过集）
       E6 prompts/registry.yaml（提示词进化记账，lint baseline 纪律适配）
```

### 3.1 D1：Playwright 页面渲染 backend

#### 3.1.1 CLI 接口（CLI 真值红线：输出 versioned JSON）

```bash
"$LEO_PPT" render page --template <template-id> --data <slide.json> \
    --out <slide_N.png> --size 2560x1440 [--variant none|web|both]
"$LEO_PPT" render ready [--json]        # render backend readiness 探测（doctor 分面）
```

输出（成功）：

```json
{
  "protocol": "leo-ppt-machine/v1",
  "schema_version": 1,
  "status": "ready",
  "reason_code": "render_page_completed",
  "render": {
    "template_id": "body-basic",
    "template_sha256": "…",
    "data_sha256": "…",
    "renderer": "playwright-chromium",
    "renderer_version": "<playwright pkg ver>",
    "out": "/abs/slide_03.png",
    "out_sha256": "…",
    "width": 2560,
    "height": 1440,
    "device_scale_factor": 2,
    "render_ms": 1830,
    "ready_signal": "data-leo-ready",
    "warnings": []
  },
  "artifact_refs": ["/abs/slide_03.png"],
  "evidence_refs": ["/abs/slide_03.png.render.json"]
}
```

失败走既有 envelope + 新 reason code（§3.12），`status=blocked` → 进程退出码 2（与 CLI 现状一致；CI-4 的 1=FAIL 只用于脚本层）。

**比例合同**：`--size` 缺省 2560x1440；实现上读 PNG 头断言实际像素（与 slide-worker 的"read the image file header, not the CLI arguments"纪律同源）；不符 → `render_size_mismatch`，不产出。

#### 3.1.2 渲染模板合同（HTML 模板必须遵守，写进模板目录 README + lint）

新目录 `leo-ppt-generator/assets/render-templates/`，每模板一个 `<id>.html` + 可选 `<id>.css`。合同条款（吸取 frontend-slides 教训）：

1. **deterministic 模式**：URL 查询参数 `?leo_render=1`（渲染器注入）时模板必须：禁用全部 animation/transition（模板自带 `[data-leo-render] .animated { animation: none; transition: none; }` 类兜底）、不注册 IntersectionObserver/scroll 触发逻辑。
2. **显式 ready 信号**：模板在字体与数据就绪后设置 `document.documentElement.dataset.leoReady = "1"`。渲染器以 `page.wait_for_selector("html[data-leo-ready='1']", timeout=…) ` 为**主门**；模板缺该信号 → 回退 `document.fonts.ready + 固定 800ms`，并记 `warnings: ["ready_signal_missing_fallback_wait"]`（WARN 不阻断，但模板 lint 会 FAIL，见 §3.10）。
3. **数据注入**：渲染器 `page.evaluate` 写 `window.__LEO_SLIDE_DATA__ = <slide.json 原文>`；模板只从该全局读数据，不 fetch 外部。
4. **字体**：模板 `@font-face` 的 `src: url(/leo-fonts/<family>.woff2)`；渲染器起本地 HTTP 服务（见 3.1.3）从 `assets/render-fonts/`（或风格包字体目录）供给。**禁止 file:// 直引**（frontend-slides L14 实证不可靠）。
5. **画幅**：模板根容器 `width:1280px; height:720px`（逻辑像素），由 deviceScaleFactor 2 输出 2560×1440 位图；模板内禁止出现滚动条（`overflow:hidden`）。
6. **可 lint 的结构锚点**：内容容器带 `data-leo-block="<block-id>"` 属性，供 E2 策划卡对账与 E5 lint 使用（对齐 ppt-agent-skill 的 `data-card-id` 思想）。

种子模板 2 个由 γ 交付（`cover-basic.html`、`body-basic.html`），其余版式映射（12_版式库 39 骨架 → 模板族）是 β 团队接口（§10）。

#### 3.1.3 渲染执行流程（`runtime/src/leo_ppt_generator/render/page.py`）

```
1. 解析 --template → 在 assets/render-templates/ 定位（缺失 → render_template_not_found）
2. 起本地 HTTP 服务（Python 标准库 http.server，随机端口，serve 模板目录 + /leo-fonts/ 映射）
   —— 服务生命周期 = 渲染生命周期，结束即关（对齐 upstream_bridge 子进程纪律：环境白名单、
      start_new_session、超时杀进程组）
3. chromium.launch()（playwright-python；executable_path 可由 LEO_PPT_RENDER_CHROMIUM 覆盖）
4. new_context(viewport={1280,720}, device_scale_factor=2)
5. page.goto("http://127.0.0.1:<port>/<id>.html?leo_render=1", wait_until="networkidle")
6. page.evaluate("window.__LEO_SLIDE_DATA__ = <json>") + 注入 themeVariables
7. wait_for_selector("html[data-leo-ready='1']")（或 §3.1.2-2 回退）
8. await page.evaluate("() => document.fonts.ready")
9. page.screenshot(path=out, full_page=False, clip={0,0,1280,720})
10. 读 PNG 头断言 2560×1440；写 <out>.render.json sidecar（provenance，见 3.1.5）
11. 关 context/browser/server；输出 envelope
```

超时：单页渲染 60s 缺省、`--timeout` 可覆盖；超时 → `render_timeout`（blocked）。浏览器实例在同进程内可复用于多页（渲染 worker 场景），但**每次渲染独立 context**（防页面间状态泄漏破坏确定性）。

#### 3.1.4 模块落点与 Node 边界（CI-6）

- 全部 Python：`runtime/src/leo_ppt_generator/render/__init__.py`、`render/page.py`。playwright 用 **playwright-python 官方包**（`runtime/requirements` 增补，`runtime_manager.py ensure` 安装；`playwright install chromium` 由 `render ready` 探测并提示）。chromium 二进制缓存路径固定在 `$LEO_PPT_HOME/render-browsers/`（`PLAYWRIGHT_BROWSERS_PATH` 注入），不污染用户全局。
- 渲染子进程环境沿用 `_isolated_env` 思想：白名单 + 显式注入，绝不让渲染进程看到 provider 凭据。

#### 3.1.5 render provenance sidecar（CI-1 核心）

每次 render 成功在 `<out>` 旁写 `<out>.render.json`：

```json

### 3.3 D3：SVG→PNG 栅格化（resvg）

#### 3.3.1 选型与 Node 边界（CI-6）

- **首选**：Python 绑定（`resvg-python` 系 PyPI 包）进 runtime 依赖——零 Node。
- **备选**（Python 绑定在目标平台不可用时）：Node 绑定 `@resvg/resvg-js`，**独立子进程隔离**：新文件 `leo-ppt-generator/scripts/render/rasterize_svg.mjs`，协议 = stdin 一行 JSON `{svg_path|svg_string, out_path, width, font_dirs[], background}` → stdout 一行 JSON `{ok, out, width, height}` 或 `{ok:false, error}`。调用方（`render/raster.py`）以 `subprocess` 起 `node`，超时杀进程组，永不进 PPTX 组装路径。node 不可用 → `rasterizer_unavailable`（blocked，提示安装或降级纯图形态）。

#### 3.3.2 参数合同（确定性）

- `font.fontDirs = [<skill>/assets/render-fonts/, <style pack fonts dir>]`、`loadSystemFonts=false`（位级确定前提）、`defaultFontFamily` 取 deck 字体锚。
- `fitTo = {mode:'width', value:2560}`；背景色显式传入（不透明 PNG）。
- 同输入两次栅格化 `out_sha256` 必须相等——进单测与 evals（§5/§7）。

#### 3.3.3 离线字体

`assets/render-fonts/` 收录 1 套开源中文字体子集（如思源黑体子集，OFL 许可，NOTICE 登记）+ 西文缺省，保证零网络、跨机器一致；deck 专用字体由风格包（β）提供路径。diagram_render.py 的字体回退链思想保留：fontDirs 缺字体时 WARN 并用 defaultFontFamily，不静默换系统字体（那是非确定的）。

### 3.8 E3：美学度量三件套（自研，P2）

新脚本 `scripts/aesthetic_metrics.py`（Pillow + numpy 可选退化为纯 Pillow）：

1. **局部方差留白率**：16×9 网格局部方差二值化（方差<THRESH=空白格）→ 内容格占比 `r`；判带 `0.40 ≤ r ≤ 0.60` 为 PASS，带外 WARN（`aesthetic_whitespace_out_of_band`）。对齐 note-slides 40–60% 内容面积带。
2. **bbox 加权质心偏移**：以格内容密度为权重算质心 `(cx,cy)`，与画布中心偏移 `d = hypot(cx-0.5, cy-0.5)`；`d > 0.12` WARN（版面失衡）。
3. **纵横比平坦区**：连通内容块 bbox 的 w/h 分布集中在 `[0.9, 1.1]` 的比例 > 0.7 → WARN（方块堆砌、缺乏节奏）。

- 输出 JSON 报告 + 退出码恒 `0`（度量失败才非 0）——**美学度量是相机不是闸门**，发现只进 WARN/披露，永不阻断（与 E2 的 FAIL 语义严格区分）。
- 接入：visual-qa.md 第六节镜头池新增"量化美学"镜头（确定性、每轮自动携带）；双评审官档把它作为 rubric"工艺/视觉"两维的量化输入。

### 3.9 E4：worker 逐页三层容错

#### 3.9.1 协议（文本合同，写进 execution-contract.md Worker 节 + slide-worker.md/render-worker）

## 6. 验证方案（渲染证据如何进验证分报告）

治理红线要求结构/provider/OCR/viewer/desktop/独立渲染/人工视觉**分别报告**。团队γ的接线：

1. **独立渲染分册（本层独有双角色）**：
   - 角色 A（生成侧）：render lane 页产物本身是确定性渲染输出，其 `*.render.json` provenance sidecar 是页级证据。
   - 角色 B（验证侧）：对成品 PPTX 的独立渲染证据——`record_visual()` 的 receipt 合同（renderer/renderer_version/pptx_sha256/pages[].render_sha256）现在可以用**渲染 lane 自己**满足：`render page --template preview-basic --data <从 PPTX 反解的页描述>` 或对 editable 路线导出的页渲染 PNG，逐页写 render_path+render_sha256，`"$LEO_PPT" evidence visual --receipt <path>` 落 `visual-render.json`，`quality_gates.visual_render=passed`。renderer 字段如实填 `leo-render-lane/playwright-chromium@<ver>`——确定性渲染器做"独立渲染验证者"不构成自证（它验证的是 PPTX 装配结果，不是验证自己生成的图）。
2. **机器 QA 分册**：visual_qa/aesthetic_metrics/geometry 报告归档 `<run>/reports/`，路径进交付回复的"必要逐页/failure report 路径"清单（execution-contract.md 交付节措辞已支持）。
3. **指纹收据**：`reports/delivery-receipt.json` 作为交付回复必引证据；`delivery_readiness.accepted` 隐含收据 fresh。
4. **未执行≠通过**：render lane 各验证未运行时按现状写 `not-run`；`render_backend_missing` 时独立渲染分册明示降级原因。

## 9. 风险与回滚

| # | 风险 | 概率/影响 | 缓解 | 回滚 |
| --- | --- | --- | --- | --- |
| 1 | **浏览器依赖安装链**（playwright + chromium ~150MB；CI/离线/受限网络环境失败） | 高/中 | render lane 完全可选：`render_backend_missing` 三态抑制路由提议，图像 lane 全功能不受影响；chromium 固定缓存路径 + 国内镜像 env 覆盖（`LEO_PPT_RENDER_BROWSER_MIRROR`）；测试 skip 纪律显式披露 | render 子命令整体保持 gated；不卸载既有任何路径。回滚 = 不提议路由（合同开关一处分支） |
| 2 | **字体确定性**（系统字体差异、离线子集缺字、mermaid 文本整形差异） | 中/中 | 渲染 lane 全部走 fontDirs/@font-face 显式字体，`loadSystemFonts=false`；缺字 WARN 不静默替换；字体内嵌不进文档（渲染环境提供字体——PPTist 反面教训） | 切回图像 lane 该页重做；字体目录按版本替换（旧 sha256 进收据指纹自动暴露漂移） |
| 3 | **合同冲突迁移**（image-deck-workflow L104 与 slide-worker 禁令改写若不彻底，出现 worker 违规本地渲染冒充） | 中/高 | 禁令改写为"未经路由确认"限定；render 页走独立 render-worker prompt；backend 字符串如实回报 + evals 反冒充 case；E5 lint 按 backend 来源交叉核验 | 保留原文禁令即可回到现状（render lane 仅父级显式执行路径） |
| 4 | **时序漏气**（模板未实现 ready 信号导致偶发截断/空白图） | 中/中 | ready 信号为模板 lint FAIL 级合同；回退等待路径必带 WARN；确定性回归 fixture 抓空白页 | 回退等待+加时；模板下线 |
| 5 | **E1 收据误阻断**（指纹类收集过宽，正常中间产物更新被当漂移） | 低/中 | 五类清单收窄到"交付语义文件"；空类显式登记；verify 输出 changed 明细而非笼统阻断；`--dry-run` 计划模式 | delivery gate 不置于 accepted 必要条件（降级为 WARN 披露），一处 cli.py 分支 |
| 6 | **resvg MPL 合规误用**（未来有人改其源码） | 低/高 | NOTICE 声明"仅作二进制依赖使用"；禁止 patch resvg 源码的纪律写入 render-contract.md | 换 Python 绑定或纯图形态 |

## 10. 对其他团队的接口需求 / 暴露

### 10.1 对团队α（内容与合同层）的需求

1. `slides.json`（image prepare 输入）页对象需含**容器清单**（每页 blocks：id/角色/要点落位）——E2 PLAN-01 对账的输入；建议复用母版"视觉行容器清单"结构（α-I1）。

3. 文档协同：`image-deck-workflow.md` L104-106 禁令改写、"数据密度路由"文字（图表样式规范 §五）纳入 render lane 第三选项——α 拥有内容合同文本，γ 提供准确措辞。

### 10.2 对团队β（风格版式资产层）的需求

1. **模板族供给**：12_版式库骨架 → `assets/render-templates/` HTML 模板的映射生产（γ 交付模板合同+2 种子模板，β 扩族）；模板必须满足 §3.1.2 六条合同。
2. **deck colors 锚 → themeVariables/theme JSON**：风格 brief 头部主题元数据（B5 五段令牌）落地后，γ 消费其 colors/fonts 段做 mermaid/echarts 注入；过渡期接受 `style render --color` 的调色板输出。
3. **风格包字体路径**：deck 专用字体目录约定（进 fontDirs）；β sidecar（B1 layouts.json）路径稳定后进 E1 `linked_assets.beta_sidecars`（CI-2）。

### 10.3 对团队δ（内核与 IR 层）的需求

1. `image record` 的 provenance 扩展若涉及 PageArtifact schema 变更（当前方案不动 schema，provenance 留在 slide_jobs entry 层），δ 知会 IR v2 演进时保留该字段语义。
2. upgrade 路线若引入 F3 对象级 dump，γ 的独立渲染角色 B（§6）可复用其页描述数据做 preview 渲染——接口为"页描述 JSON"，格式由 δ 定义时与 render 模板 data 槽对齐。
