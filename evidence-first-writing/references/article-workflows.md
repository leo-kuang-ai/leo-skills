# 文章类型 Workflow

先由 `intent-routing.md` 选择一个主 family。所有类型继承 `editorial-pipeline.md` 的权限、事实、分层编辑和最终回归门禁；本文件只定义各自不同的生产主轴。

## 骨架选择

以下各 family 的主轴是论证骨架（Toulmin 式）。大众渠道、题材含时间线或人物、读者规模优先于同行评审时，可改用或混用叙事骨架：悬念前置（结论延迟）、双线交织（故事线与论证线交替收束）、问题-恶化-转折。

硬规则：

- 叙事骨架下，大纲每节必须回答：读者此刻知道什么、不知道什么、想知道什么；
- 关键信息（反转、关键证据、身份）在大纲中有明确释放位置；
- 可以延迟陈述，不得误导——延迟揭示的信息在释放时必须完整兑现；
- 事实、证据与授权门禁不因骨架放宽。

## 1. 观点评论 `argument`

适用：评论、观点文、思想文章、专栏、thought leadership。

```text
现实问题 -> 作者立场 -> 最强反方 -> 证据与 warrant
-> 论证推进 -> 边界/代价 -> 结尾判断
```

必须有能被反驳的 thesis，但不为“有牙”制造敌人。事实支撑外部 claim，作者价值判断明确归属作者。结尾可以保留开放问题，不强行行动号召。

退出：读者能复述作者的判断、理由、最强反方和适用边界。

## 2. 研究解释 `evidence-explainer`

适用：机制解释、趋势分析、政策/行业解释、证据型科普。

```text
可回答问题 -> 研究问题树 -> 来源地图 -> 冲突证据
-> 概念/机制模型 -> 解释型结构 -> 事实审查 -> 读者理解测试
```

优先原始研究和官方材料，区分共识、争议、未知、相关与因果。作者可以给判断，但不能让观点吞掉证据不确定性。标题不使用来源无法支持的规模和确定性。

退出：读者不仅知道“是什么”，还理解“为什么、证据多强、边界在哪”。

## 3. 教程 `tutorial`

适用：从陌生起点学习并完成一个可验证结果的教程。技术内容同时读取 `technical-docs.md`。

```text
目标结果 -> 读者起点/前置条件 -> 最短成功路径
-> 可执行步骤 -> 中间检查点 -> 故障恢复 -> 全程复跑
```

教程服务学习路径。每个动作使用明确主体、输入和预期结果。代码、命令、链接和参数必须实际验证；无法运行标记 `not_run`。

退出：目标读者能在声明环境中完成结果，并知道失败时如何恢复。

## 4. How-to `how-to`

适用：读者已有基础和明确目标，需要完成一项操作、配置或排障。

```text
已知目标 -> 前置条件 -> 最短任务路径 -> 验证点 -> 常见失败 -> 恢复路径
```

不解释所有背景，只提供完成目标所需的信息。技术 How-to 必须读取 `technical-docs.md`，并实际验证命令、参数、链接与预期输出。

退出：读者能完成具体目标，并知道失败时如何恢复。

## 5. 技术 Reference `technical-reference`

适用：API、CLI、配置、参数、字段、错误码和稳定行为查询。

```text
当前实现/Schema -> 查询结构 -> 精确条目 -> 示例或边界 -> 版本与链接核验
```

不使用教程叙事、营销语气或强行的“读者旅程”。所有名称、默认值、返回结构和示例回到当前实现或官方 Schema。

退出：读者能准确查询事实，且条目可回溯到实现或官方契约。

## 6. 技术 Explanation `technical-explanation`

适用：技术机制、架构权衡、设计原因、历史和概念关系。

```text
可回答问题 -> 机制/约束 -> 方案与权衡 -> 边界/替代方案 -> 读者理解测试
```

不强求 Quickstart 或完整参数表；示例用于解释机制，仍需核验技术真值。

退出：读者理解为什么当前设计如此、替代方案的代价及适用边界。

## 7. 案例复盘 `case-retrospective`

适用：项目复盘、事故复盘、业务案例、决策回顾、人物/组织案例研究。

```text
复盘边界 -> 原始时间线 -> 当时目标/信息/约束
-> 关键决策 -> 结果与反事实 -> 机制解释 -> 可迁移教训
```

严格区分当时已知与事后才知，避免 hindsight bias。保留决策记录、版本、指标口径和失败尝试。教训必须说明适用条件，不能从一个案例升级为普遍规律。

退出：事实时间线可追溯，读者能看见决策为何在当时发生以及教训何时不适用。

## 8. 个人叙事 `personal-narrative`

适用：个人经历、随笔、自述、成长故事、现场记录。

```text
真实经历边界 -> 关键场景/选择 -> 当时体感与未知
-> 变化或未解决张力 -> 当前理解 -> 克制收束
```

个人经历只能来自作者。保留记忆的不确定性，不把回忆写成逐字录音，不虚构数字、对话和感官细节。外部事实另走证据账本。故事无需证明普遍规律。

退出：文本让具体作者出现，但没有通过编造“人味”或假脆弱服务论点。

## 9. Newsletter / 平台文章 `newsletter-platform`

适用：Newsletter、公众号栏目、知乎文章、平台长帖和周期性内容。

```text
栏目长期承诺 -> 本期单一价值 -> 来源/作者素材
-> 可扫描结构 -> 标题/摘要/首屏 -> 正文 -> 平台压力测试
```

区分稳定声音与本期语气。平台影响长度、标题、摘要、段落和互动入口，不拥有事实与立场。不得预测 CTR、完读率或分享率。Newsletter 需要兑现订阅关系，不把每期都写成营销漏斗。

退出：本期提供明确新增价值，并与栏目长期承诺和平台阅读方式一致。

## 10. 正式报告 `formal-report`

适用：管理报告、调研报告、决策简报、正式分析和方案建议。

```text
决策问题/使用者 -> executive summary -> 事实与方法
-> 分析/备选方案 -> 风险和反方 -> 建议/owner/时限/验收
```

先确认报告支持谁做什么决定。区分事实、分析、建议和待确认项；建议包含 owner、期限、交付物、验收和延误影响。语气克制，允许表格用于精确比较，不为“人味”打乱稳定结构。

退出：决策者无需阅读全部背景也能理解结论、证据、选项、风险和下一步。

## 11. 产品营销文案 `marketing-copy`

转 `copywriting.md`。主轴是页面动作、具体读者、产品结果、流量入口和证明，而不是长文 thesis。产品状态文案不使用说服框架。

退出：每行服务唯一动作或必要状态，所有证明可追溯，CTA 与用户结果一致。

## 知识卡片共创节奏（来源：Tasihi89/vibe-writing-workflow，快照 2025-11，重写表述）

本节奏细化 `workflow-contract.md` 第 7 节 `coauthor` 的逐节共创，适用于任何 family 叠加 `collaboration_modifier.mode: coauthor` 的长会话；短共创仍按原三阶段执行，不强制落盘。

- **对话沉淀机制**：每约 4 轮对话，按「理解目标」把已答内容分组固化为知识卡片。逐轮回看用户这一轮想理解什么——即使提到新概念，也可能只是为对比理解原概念；理解目标相同的轮次归为一组，每组一张卡片，理解目标转向新概念时开新卡。用户可随时手动触发生成。
- **卡片是对话的文章化**：不是问答堆砌，而是把该组的问题、回答、例子与类比改写成连贯文章，保留丰富度、删除重复。开头引用块记录疑问从哪来——作者在哪里停下来产生了这个问题；结尾引用块回归主题，说明这张卡与文章主旨的关系。
- **按认知轨迹组织，不按教科书逻辑**：从困惑开始而非从定义开始；推导卡在哪里就地解决，不延后到「基础知识」节；层层递进，每步给收获同时引出新问题。小标题可直接用作者的原始问法，保守润色，不学术化。
- **双链回插源文档**：卡片以链接形式回插到其来源文档的对应位置，记录作者在哪里停下来产生疑问；后续组装大纲时沿链接还原认知路径，而不是只按主题归类。
- **润色三原则**（并入共创合同的措辞）：作者框架不可侵犯——留下什么保留什么、顺序完全保持，从 2000 字删到 400 字就只润色这 400 字；**作者删掉的内容永不恢复**，即使 AI 认为重要——删减是作者的价值判断；每处改动自问「是让原有内容更清晰，还是添加了新内容」——更清晰允许，新内容禁止。
- **断点续传**：卡片文件是唯一真值，对话清空后仍可准确续作。中断恢复时先报上次进行到哪张卡、哪个阶段，再给「继续当前 / 进入下一步」两类出口，不让作者不知道下一步。

## 混合请求

- 「写一篇带个人经历的研究文章」：主 family 是 `evidence-explainer`，个人叙事作为受事实边界约束的局部材料。
- 「把项目复盘写成公众号文章」：主 family 是 `case-retrospective`，叠加 `newsletter-platform` 渠道适配。
- 「写一个产品使用教程并促使升级」：优先拆为教程和营销 CTA 两个交付物；不能让转化目标污染操作真值。
- 「正式报告的技术附录」：主文 `formal-report`，附录按 `technical-docs.md` 的 Reference 处理。
