# 视觉质检规范（图片式 generate 路线）

> 本文档是「五层非补偿质量门」中**「视觉呈现」层**的可执行展开。leo-ppt 已有
> 质量门框架（`image-deck-workflow.md` 第 10 步）与 worker 自查清单
> （`prompts/slide-worker.md`），本文档把它们整合成**闭环 + 对抗式审查 + 具体判据**。
> 判据阈值引用 [`../template-library/governance/authoring/index/通用设计规范.md`](../template-library/governance/authoring/index/通用设计规范.md)，不重复定义。

## 一、质检定位：对抗式审查，不是正向核对

「结构验证不等于视觉等价」。自动检查只证明确定性合同；**每页视觉质检必须是
「对抗式审查」**——主动假设这页有问题、专门找茬，直到找不到问题才判通过。
正向「照着清单打勾」会漏掉它没列出的错误。

## 二、质检流程（闭环，缺一不可）

1. **worker 自查**（正向）：`slide-worker.md` 的 visually check 清单。
2. **父 Agent 独立复核**：不看 worker 的自述 `qa_note` 就下结论；亲自打开
   `origin_image/slide_<N>.png` 与 `prompts/slide_<N>.json` 逐条对照。风格来自
   参考图提取时，复核呈现须为参考图与样张**并排比对**形态（见
   [`style-recommendation.md`](style-recommendation.md) 第五节）。
2.5. **确定性像素闸门（机器前置，LLM 审之前）**：每页 record 前运行
   `python3 scripts/visual_qa.py <页图或 origin_image 目录> --report <run>/reports/visual-qa.json`。
   退出码 `1`（FAIL：近乎纯色/尺寸不符/图片无法解码等）→ **直接打回该页，附机器
   findings 作为打回理由，不进第 3 步 LLM 对抗审查、不消耗审阅**；修复后重跑
   本步。退出码 `2`（仅 WARN：边缘截断嫌疑/对比度分区/竖排嫌疑）→ 可继续，
   但 WARN 必须写入 `qa_note` 并在交付话术披露。退出码 `0` 或仅 WARN 均进入第 3 步。
   render lane 页同样适用（render-worker 单页自查与父 Agent 批量复跑两层，
   见 [`render-contract.md`](render-contract.md)）。检查族与阈值：DIM-01
   （16:9 + 2560 交付档）、BLANK-01（近乎纯色 FAIL；差异像素少于 15% 提示 WARN）、
   CUT-01/CONT-01/VTXT-01（WARN）、SIZE-01（<600K 仅 WARN，压缩体积不代表设计质量）。
   DESIGN-01 提示四象限差异像素分布，包括完全空象限；墨迹比例不是布局占用率，
   任何机器 PASS 都不能替代结合页面角色的视觉复核。
3. **对抗式审查**：按下节清单**专门找茬**，每条问「这一页最可能错在哪」。
   提示词只提供任务目的、原始材料与检查项，先隐藏上轮分数、预期提升和作者修复
   自述，避免诱导性评审。缩略图不能辨认的文字标记为未确认，放大后保留完整证据；
   模型回答中的“推测”“可能”不得在汇报时改写成“已确认”。卡片数量、页面填满率
   和模型自评分不作为通过条件；同一 Agent 自审也不写成独立专家验收。
4. **任一失败 → 打回该页重做**：内容层失败先改母版（见
   [`deck-master.md`](deck-master.md)），视觉层失败改变输入/prompt/backend 后重试；
   其他检查通过不能补偿；「警告后继续」在视觉质量门上不成立。**重做后的再检必须
   覆盖「目标判据 + 波及面」**：目标判据＝本次失败项；波及面＝修复可能引入的新缺陷
   （改文字→查密度与截断；改颜色→查对比度与双线索；改版式→查安全区与样张继承）。
   再检的 `qa_note` 必须同时写出目标判据结论与波及面结论；只写「已修复」不算通过。
5. **全部通过 → `image record`** + 写 `qa_note` + 留可复核证据路径（截图/对照）。

> 质检与「通用设计规范」的分工：后者是**生成时**的规范（怎么画得好）；本规范是
> **生成后**的检查（怎么验证达标）。

## 三、对抗式审查清单（找茬视角）

逐页过，任一条命中即失败：

**文字**
- 中文是否乱码、错字、漏字？
- 标题 / 数字 / 单位 / 标签 / 引用与 `slide_jobs.json` 白名单的**逐字机械对齐**由
  R-73 OCR 对齐门承担（`image record` 前消费 `image-deck/ocr/page_<N>.txt`；
  WARN 期披露、校准通过后 enforce 硬门，见
  [`render-contract.md`](render-contract.md) 组合页合成节与 `ocr_alignment.py`）：
  审查者**不再重复目视逐字比对**，但须复核门的 `not_run` 披露——门未运行的页
  仍按本条人工判读，且错字拦截不因此视为已覆盖。语义级文字判读（术语口径、
  编造百分比、上下文错位）保留人工/多模态职责。
- 有没有把「智能补全/实时协作」这类概念硬塞进数据图表并编造百分比？

**数据**(判据全文见 [`../template-library/governance/authoring/index/图表样式规范.md`](../template-library/governance/authoring/index/图表样式规范.md))
- 图表数值 / 单位 / 标签 / 图例 / 排序是否与 approved 完全一致?
- 有没有「无量化数据的内容用了 H-Bar/KPI 塔」这种**版式滥用**（编数据）?
- 有没有**无数据授权的 chart-like 形状**(装饰竖线/塔/条)?编形状 = 编数据。
- 估算值是否实心渲染、与引用值不可分辨?**置信度形状语法**:引用=实心;估算=纹理/虚线 +「~」前缀 + 同页混级图例;示意=禁入量化图形(含 KPI 卡)。
- 柱状图是否共零基线?纵轴截断有无断轴符号?跨页同指标是否同尺度?
- 应用数、CPU 核数、内存 GB 等不同单位是否错误共用同一数值轴？应拆成独立
  面板，或在分母清晰、允许计算时统一为变化百分比，不能用绝对柱高暗示可直接比较。
- 本页每个数字与断言的强度是否超出其来源等级？「估算/经验值」是否已括注、
  「示意」是否用了图表版式（示意值用图表版式 = 失败）?

**风格**
- 是否真正继承已批准样张（配色/字体/密度/纹理）？有没有逐页换风格？
- 大标题字重是否在本风格声明的**表情档**(Whisper/Speak/Shout)之内?档内一致、
  同 deck 不跨档;Shout 档例外是否已登记且 ≤2 页?

**图像**
- required asset 是否**可见**且**未被「重画近似」替换**？
- 主体（人脸/关键对象）是否被裁切？白底信息图是否被灰底包白图？
- 页面用图是否在母版标注了**来源三级**(实拍/生成-氛围/生成-示意)?AI 生成写实图
  冒充实拍进证据槽 = 失败。

**版式**
- 有没有截断 / 遮挡 / 溢出（内容越过安全区）？
- 关键信息是否**只靠颜色区分**（必须同时有文字/标签/形状/位置第二线索）？
- kicker 是否压成大标题左右、而非上下结构？

**违禁**
- 有没有假 logo / 水印 / 页眉页脚 / 页码 / 角标 / 署名？
- 有没有 emoji 当图标？装饰性杂图（不解释任何东西的 SVG 圆/散点/光斑）？

**可读性**
- 投屏距离下字号 / 对比度是否达标？（阈值见下节）

**表述合规**（行业域命中时）
- 本页是否命中 `_content_rules.md` 禁词表？按力度分级处置：blocked 级词与伪造
  公文图元（红头/公章/文号/密级）→ deck 级阻断（不可逆风险）；rewrite/annotate
  级 → 逐条定位到页，走"母版→受影响页重建"页级修复（`industry_rule_violation`）。
- 监管用语档位是否正确（如"临床研究中"不得写成已获批结论）？

## 四、视觉呈现具体判据（可执行阈值）

| 检查项 | 判据 | 来源 |
| --- | --- | --- |
| 投屏字号下限(双口径) | 1920 口径:正文 18/caption 16/meta 14px;2560 生图口径:正文 32/caption 28/meta 24px | 通用设计规范 |
| 对比度 | 正文 vs 背景 ≥ 4.5:1;大字与非文本 ≥ 3:1;蓝字压黑图 = 失败 | 通用设计规范 / WCAG |
| 双重编码 | 关键信息不只用颜色,需第二线索 | 五层质量门(铁律) |
| 标题形态断言 | 标题形态按论证模式条件化:金字塔/未声明=完整句断言;中性简报=主题词允许;视觉展示=唤起短语允许;形态须在母版页首声明,与后续页面逐字一致 | deck-master(本判据行由风格系统计划 U8 独占落地) |
| 置信度形状语法 | 引用=实心;估算=纹理/虚线+「~」+混级图例;示意=禁入量化图形(含 KPI 卡) | 图表样式规范 |
| 数据形状授权 | 任何 bar/塔/竖线高度须绑定 approved 序列;钳制区间标「非线性」 | 图表样式规范 |
| 图像来源三级 | 实拍/生成-氛围/生成-示意标注存在;生成图禁入证据槽 | 通用设计规范 |
| 大字号限高 | `min(Xvw, Yvh)` 且 Y ≥ X×1.6；不限高导致溢出 = 失败 | 版心Canon |
| 截断/安全区 | 内容最低处不触及分页 nav，留 ≥3vh 呼吸 | guizang 对齐法则 |
| 字重阶梯 | 越大越细、越小越粗;按风格表情档校验,同 deck 不跨档 | 通用设计规范 |
| 样张继承 | 配色/字体/密度/纹理与 approved 一致，不逐页换风格 | 五层质量门 |
| 固定件一致 | 合同/母版约定固定件（页码/页脚/署名位）时，位置与字号逐页一致；未约定则按违禁项禁止 | deck-master 纪律 |
| 交叉引用存在 | 页内「见第 X 页/见附录」与实际页码/附录存在性一致 | deck-master 纪律 |
| 数字三件套 | KPI/数据页每个数字可追溯到登记表行；期间+单位+口径随数可查，缺一即失败 | 数字登记表合同 |
| 统计标注门槛 | 统计图带 n/误差/显著性；无来源统计量使用数据版式 = 失败，降级示意 | 数字登记表合同 |
| 密集表格机读比对 | P25 行数 ≥12 的页：期望值清单 × OCR 回读逐格比对（check_table_values.py），值未命中即打回 | P25 机读比对合同 |
| 测量式几何校验 | 可选机读补充：`scripts/validate_visual_measure.py` 对测量 JSON 跑溢出/最小字号/4 横带密度/边界/标题间距规则（playwright 可用时 `--html` 实测，缺失时降级指引，退出码 0/1/3）；只补人审不替代 | social-card-specs §6 |

## 四b、全 deck 末轮跨页一致性轮检

全部页通过单页质检后，追加一轮 deck 级比对：每页 vs 已批准样张（配色采样/
字重气质/留白密度），相邻页成对比较；超阈值（明显色相漂移、密度突变）打回
该页重做。风格来自 `--brand`/`--anchor` 时比对风格锚附录的 HEX/字族清单。
worker 再锚定（长 deck）：双参考＝原样张 + 最近 accepted **同角色**页，同角色
页仅继承**结构与密度维度**（排除 palette/纹理）——样张仍是风格唯一锚定源。

## 五、质检结果记录

worker 返回与父 Agent record 时，`qa_note` 只写一句结论（通过 / 具体失败项），
并附可复核证据路径（截图或对照图）。失败按
[`reason-codes.md`](reason-codes.md) 给稳定 reason code 与恢复动作。

## 六、多轮审查协议（高要求任务可选档）

单轮对抗清单会在 2–3 轮后饱和；对高要求任务，按以下协议轮换镜头直至收敛：

- **镜头池**：内容事实 / 叙事结构（one_thing 回扣、全部标题连读是否成故事线）/ 工艺可构建（要点-容器落位）/ 视觉系统 /
  受众适配 / 来源可信（断言-来源匹配）/ 行动启发 / 一致性（交叉引用与编号）/
  逻辑链（主张有独立理由，非循环引用）/ **数据图形**（零基线、截断轴、形状授权、置信度形状语法；>10 数据点页强制启用）/ **图像来源**（AI 生成图冒充实拍检测）/ **表述合规**（行业禁词与监管用语档位）。每轮取 3 个镜头并行、逐轮轮换。
- **发现分级**：P1＝误导受众或违反本规范红线；P2＝需重读才懂或口径含糊；
  P3＝锦上添花。修复按 P1 → P2 顺序，P3 可显式驳回。
- **收敛判据**：连续两轮全部镜头无 P1/P2 发现才判收敛；单轮"清单查完"不构成收敛。
- **台账**：每轮记录镜头组合、发现与分级、修复摘要；**驳回必须给出既定设计依据**，
  不得无理由忽略发现。
- **波及复查**：每轮修复后按流程第 4 步复查波及面，防止修复引入新缺陷。
- **rubric 合成分（高保障档可选，默认不启用）**：判据与分级不变，仅追加确定性
  记分表：满分 100，**命中扣分制**——每条 P1 扣 10、P2 扣 5、P3 扣 2；同一发现
  跨镜头重复命中只按最高级扣一次（发现级去重）。选扣分制而非达标得分制：本
  清单是对抗找茬视角，命中即缺陷，扣分与「任一失败不可补偿」语义一致。合成
  分 < 90（默认阈值，可按交付档位调整）→ 阻止组装；每轮分数构成（各分级
  命中数与扣分明细）记入台账。
- **迭代硬预算（高保障档可选，默认不启用）**：多轮审查至多 3 轮（默认，可调）；
  与收敛判据**先到者生效**——3 轮内未达成「连续两轮无 P1/P2」即停止自动重试，
  升级用户并呈现当前分歧与各轮台账，由用户裁决后续（防无限重试烧 token，
  与成本预估前置合同呼应）。

本协议不改变五层质量门，只扩展「视觉呈现 + 内容事实」两层的执行深度；默认任务
执行单轮对抗清单即可，本协议仅在用户要求高保障或交付档位显式启用。

## 七、与现有环节的关系（不新建重复流程）

- 本规范**展开** `image-deck-workflow.md` 第 10 步的「视觉呈现」层，不新增第五层之外的门。
- worker 自查清单（`slide-worker.md`）保留为「流程①正向自查」，本规范补「②独立复核 + ③对抗审查 + ④打回」。
- 「现场验收」层（真实 provider / PowerPoint 桌面 / 投屏 / 人工审美）仍按原规范
  分别实际执行并记录，未执行写 `not-run`。
