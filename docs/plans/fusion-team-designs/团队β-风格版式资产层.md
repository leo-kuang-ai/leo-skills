## 3. 详细技术设计

### 3.1 B1 · layout bank sidecar（双层结构，真值不复制）

**关键架构决策**：leo 是正交轴模型（风格×版式解耦，`设计体系.md` §一），不是 gpt-image2 的"风格内嵌 layout 集"模型。因此 sidecar 分两层，**版式层为唯一真值，风格层是薄路由视图**，避免 11×36 复制爆炸：

```
版式层（权威真值，36 份）
  references/styles/12_版式库/<stem>.layouts.json
  例：references/styles/12_版式库/06_KPI_Tower.layouts.json

风格层（路由视图，11 份，只引用不复制）
  references/styles/<风格名>.layouts.json
  例：references/styles/清爽专业风.layouts.json
```

**版式层 schema**（新文件 `runtime/src/leo_ppt_generator/schemas/layout-bank-v1.schema.json`，CI-3 版本化）：

```json
{
  "schema_version": 1,
  "entity": "layout",
  "layout_id": "P6",
  "name": "KPI Tower",
  "page_type": "data",
  "visual_signature": "4 列不等高柱状 KPI，bar 高度由数据决定，顶部图标+中段巨数+底部标签",
  "content_capacity": {
    "items": {"desc": "4 项可比量化数据（数量必须=4）", "count_min": 4, "count_max": 4},
    "item_label": {"desc": "列标签", "chars_per_line": 8, "max_lines": 1, "max_chars": 9},
    "big_number": {"desc": "中段巨数", "chars_per_line": 6, "max_lines": 1, "max_chars": 7}
  },
  "best_for": ["成本/容量/计数/效率指标的 4 项对比", "bar 高度能由真实数据决定的场景"],
  "avoid_for": ["无数据的概念列举（P4/P5 的事）", "超过 4 项或不足 4 项的数据"],
  "reuse_friendly": true
}
```

- **字段边界（裁决 3 落地）**：语义描述字段**五字段封顶** = `visual_signature` / `content_capacity` / `best_for` / `avoid_for` / `reuse_friendly`。`schema_version/layout_id/name/page_type` 是标识与治理字段，不计入封顶。**显式不引入**：`variation_tags`、`json_schema`、`external_image_slots`、`reuse_reason`、`summary`（leo 的 `用途/适用内容类型` 已在 .md 骨架内，sidecar 不重复）。合同分层原则：提示词层（.md 骨架）管语义，数据层（sidecar）只管可验证事实。
- **`page_type` 枚举**（从 `runtime_profile.py` L22-31 收敛为 6 值）：`cover / agenda / section / content / data / closing`。36 版式逐一归属（P1→cover，P32→agenda，P23→section，P4/P5/P19→content，P6/P7/P20/P21/P25/P35→data，P9/P36→closing…），映射表随 sidecar 落盘。
- **`content_capacity` 双形态**：数量型 slot 用 `count_min/count_max`（对齐版式内容Schema 的硬数量约束），文本型 slot 用 B3 的 `chars_per_line/max_lines/max_chars` 三值。语义描述一律从 `00_索引/版式内容Schema.md` 提炼，**不另造口径**。
- **`reuse_friendly` 标定规则**（对齐上游"强视觉锚点版式一 deck 一次"）：`false` 集合 = P1 封面、P9 Closing Manifesto（版式内容Schema L17 明言"每个 deck 只有一页"）、P23 Section Divider（每章至多一页）、P24 Number Hero（每章至多一页）、P34 Quote Hero、P36 Ambience Full Bleed（每 deck ≤2 页，单列 `max_per_deck: 2` 时 reuse_friendly 置 false 并在 avoid_for 注明上限）。其余默认 true。P36 这类"≤N 次"用 `reuse_friendly: false` + sidecar 顶层可选 `max_per_deck: 2` 表达（仍不新增第六个语义字段）。

**风格层 schema**（同一 schema 文件内 `entity: "style-layout-bank"` 分支）：

```json
{
  "schema_version": 1,
  "entity": "style-layout-bank",
  "style_id": "清爽专业风",
  "capacity_factor": {"text": 1.0},
  "routing": [
    {"page_type": "cover", "preferred": ["P1"], "discouraged": ["P36"]},
    {"page_type": "data", "preferred": ["P6", "P20", "P21", "P25"], "discouraged": []},
    {"page_type": "content", "preferred": ["P4", "P5", "P19", "P8"], "discouraged": ["P13"]}
  ]
}
```

- `capacity_factor.text`：该风格对版式默认文本容量的折减系数（如手绘白板风 0.85——留白/笔迹占位；数据仪表盘风 1.1——网格更密）。11 风格初值全 1.0，仅手绘两风 0.85、数据仪表盘 1.1，其余待实测调。
- `routing` 只存版式 id 引用（必须可解析到 36 版式之一），**悬空引用 = lint ERROR**。
- 顶层风格的 brief `.md` 保持不动（B5 的 theme 块是另一条线），sidecar 为独立文件——**风格可加载性判定不受影响**（`styles.py` L64-84 `_is_style_md` 只认 ```json 块，`.layouts.json` 不是 `.md`，不会混入 `style list`）。

**lint 配对检查**（缺 sidecar 报 ERROR，对齐上游"Markdown-only 在加载边界拒绝"）：

1. `scripts/lint_layout_grid.py` 扩展（保持退出码 0/1 语义，docstring 补 CI-4 说明）：
   - 检查 A：`12_版式库/*.md`（排除 `00_/01_常犯/02_关键类` 前缀，沿用 L22 `RULE_FILE_PREFIXES`）必须有同名 `.layouts.json`；缺失、JSON 不可解析、`layout_id` 与 .md 标题 P 码不一致 → **ERROR（exit 1）**。

   - 检查 C（数值一致性，服务 B3）：sidecar 内任一文本 slot 满足 `max_chars == floor(chars_per_line * max_lines * 1.2)`（TOLERANCE 移植值）→ 不满足 **ERROR**（防手写漂移）。
2. `scripts/lint_style_briefs.py` 扩展：顶层内置风格缺同名 `.layouts.json` → **ERROR**（范围仅 11 内置；126 子目录参考风格**不强制**——渐进轴，将来按批次纳入时走 baseline 收敛纪律，本设计不扩大范围）。

  ```

  输出 sidecar JSON（含各文件 sha256，服务 CI-2 资产指纹）。

### 3.2 B2 · 模板调度师（思想改写，规则链 + 确定性打分器）

**规则链**（原创改写 banana-slides 优先级序，AGPL 零文本搬运）：

```
角色对齐 → 结构匹配 → 节奏感 → 置信度裁决
```

1. **角色对齐**：`deck_spec.slides[].page_role`（13_页面语义 25 角色，如"对比·多维/指标·计分榜"）映射到版式 `page_type`（6 值）+ 版式内容Schema 的适用内容类型行；角色不符的候选直接出局。
2. **结构匹配**：页面侧 `{要点条数, 预估字数, 数据点数, 图源数}`（母版内容行已有）对 sidecar `content_capacity`（count_min/count_max 区间包含度 + max_chars 覆盖度）与 `visual_signature`（图文比倾向）匹配打分。
3. **节奏感**：同版式不连续（至少隔 1 页）；`reuse_friendly=false` 且已用 → **硬排除**（与 B1 检查脚本同口径）；同 page_type 连续 ≤3 页提示换型。
4. **置信度裁决**：top1 综合分 <0.5 → 该页 `decision: "undecided"`，在母版确认点作为待人工行呈现（"第 7 页版式待定：P8 或 P13，理由…"）；**禁止编造版式 id**——候选只能来自 `style render --list-templates` / `style layouts` 枚举集，未枚举 id 出现在输出即脚本自身 bug，评测断言拦截。

**确定性打分器** `scripts/suggest_layout.py`（让 B2 从纯提示词变成可测机器行为）：

```json
// 输入 stdin 或文件
{"pages": [
  {"page": 3, "page_role": "对比·多维", "points": 2, "est_chars": 120,
   "data_points": 0, "image_sources": 0, "already_used": ["P1", "P4"]}
]}
// 输出（stdout，键排序、确定性）
{"pages": [
  {"page": 3,

**合同文档**：新 `references/layout-dispatch.md`（调度规则合同：四步链、打分口径、undecided 呈现格式、禁编造纪律、与 B3 预检的衔接——超容量时先降档/换版式再回到匹配环）。从 `deck-master.md` 与 `style-library.md` 各加一行引用。

### 3.3 B3 · vw 视觉宽度容量模型（生成前预检）

**落点（会议指定）**：`scripts/check_deck_geometry.py` 新增 `--capacity <deck_spec.json|master.json>` 互斥模式（沿用 `--self-test` 的"模式先例"结构，positional pptx 与该旗标互斥，同给报用法错误 exit 2）。

- **`vw_of()` 移植**（MIT 署名，逐字符语义一致）：CJK/全角（U+4E00–9FFF、U+3000–303F、U+FF00–FFEF）= 1.0；空格 = 0.35；ASCII = 0.5；其他 = 0.8。
- **`capacity_for()` leo 化标定**（Gorden 是 PPTX 模板物理语境，leo 是版心 token 语境，公式换算、系数保留）：
  - 画布 16:9 基准 2560×1440（1vw = 25.6px）；容器可用宽 = `栏数/12 × (100vw − 2×5vw page-margin-x − 栏距) × 25.6px × 0.95`（0.95 近似 Gorden H_MARGIN 内边距让渡）。
  - 字号从版心Canon 字阶刻度取（body 44–56px、caption ≥28px、meta ≥24px）；`chars_per_line = floor(可用px宽 / 字号px)`；`max_lines` 按版式骨架的容器高度（vh）与行高 1.0 推导；`max_chars = floor(cpl × max_lines × 1.2)`（TOLERANCE 1.2 保留——上游校准假阳 0–5%）。
- **三态输出**（对齐 Gorden 编辑铁律与版心Canon 刻度纪律）：
  - `ok`：全部 slot 装得下 → exit 0。
  - `over`：某 slot 超 `max_chars` 但 ≤ `max_chars × 1.2`（软超）→ 打印"降档位或换版式建议"（**绝不建议缩字号**——同级字号一致铁律 + 字阶刻度离散表），exit 0 附 WARN 行（CI-4 的 2 语义保留给用法错误，此处用输出行区分而非退出码，避免与既有 0/1/2/3 冲突；文档写明）。
  - `overflow`：超 `max_chars × 1.2`（硬超）→ exit 1 阻断定稿，输出逐 slot 的"当前 vw / 容量 vw / 建议替代版式（content_capacity 覆盖的候选）"。
- **36 版式容量数值**：进 B1 版式 sidecar 的 `content_capacity` 每 slot（单一真值，B2 打分器与 B3 预检同源消费）。标定流程：一次性脚本 `scripts/generate_capacity_draft.py`（按上述公式从版心 token + 骨架栏数生成初稿 JSON）→ 人工审定落盘 → lint 检查 C 守恒。**要点禅档位寄生**：`references/deck-master.md` L21 档位节增"母版定稿前对要点行跑 `--capacity` 预检；硬超页先降档（论点页 ≤3 → ≤2）或换版式，不缩字号、不省略号截断"。
- 与 γ 团队 visual_qa（E2，交付后像素断言）划清职责：B3 是**生成前文本级**预检，E2 是**生成后像素级**闸门，一个防患一个兜底，不重复。

### 3.4 B4 · PPTX 主题提取器（TS→Py 移植，纯 stdlib）

**新脚本 `scripts/extract_pptx_theme.py <可信.pptx> [--json out.json]`**（zipfile + xml.etree，零第三方依赖，CI-6；逻辑从 `pptx-theme-extractor.ts` 移植并保留 MIT 署名注释）：

1. **rels 链解析**：`ppt/_rels/presentation.xml.rels` → slideMaster → `slideMaster.rels` → `ppt/theme/theme1.xml`（移植 `resolveThemeXml` 的相对路径解析）。
2. **clrMap + 12 slot 调色板**：slideMaster `clrMap`（默认 bg1→lt1/tx1→dk1/…）；theme `clrScheme` 逐 slot 取 `srgbClr@val` 或 `sysClr@lastClr`；`applyColorModifiers` 移植（lumMod/lumOff/tint/shade/satMod/satOff，HSL 换算）。
3. **字体双槽**：`fontScheme/majorFont|minorFont/latin@typeface` → **Office→Web 字体映射 16 条**（Calibri→Inter…逐条直搬并注明来源）→ 中文字体不在表内时保留原名并标注 `"mapped": null, "note": "生图后端可用性需样张验证"`。
4. **内容扫描角色色推导**：扫描 `ppt/slides/slideN.xml` 文本 run（字号 ≥18pt 判 heading，权重 `max(1, sz) × 1/sqrt(N)`，多巨标色惩罚）、shape fill、slide bg 频次 → 角色色。
5. **leo 四角色映射**（与三层 token 兼容的关键，见下）：`primary`（shapeFill 频次最高或 accent1）、`accent`（heading 高频高饱和色或 accent2）、`secondary`（accent3-6 按色距分散度选一）、`neutral`（dk1 或 body 高频色）。

  "source_pptx_sha256": "…",

             "body": {"raw": "Calibri", "mapped": "Inter"}},

|---|---|---|---|---|
| R1 | **render 字节确定红线被破坏**（B5 theme 键注入或 B1 sidecar 意外进入 render 组装路径，破坏下游快照消费者） | 中/高 | B5-T2 先行快照证明"无 theme 逐字节不变"再动数据；sidecar 只经 `style layouts` 新命令与规划层暴露，`compose_style/compose_layout` 零改动写入任务验收；`test_render_without_theme_byte_identical_after_schema_bump` 常驻回归 | 删除 schema `theme` 键与透传行即回到 v1.0；sidecar 文件整体删除不影响 render（lint 检查 A/B/C 同步回退） |

| R4 | B7 多页样张推高成本/交互（用户误以为默认两图） | 低/中 | 默认恒 1 张；结构页"成本先告知 + 点头才出"复用双生纪律；eval 断言未点头不出第二张 | 合同文本回退到"恰好一个代表性样张"单句（改动集中在两份 references 的两节） |

### 需要其他团队 / 总架构师确认

1. **α**：sources_manifest 中风格/版式资产指纹的字段名与粒度（per-file 还是 per-deck-spec 引用集）——影响 `style layouts` 输出是否需要聚合视图。
2. **γ**：E2 像素断言若引入"内容占比 40–60% 带"类密度规则，须与 B3 容量口径对表（同一版心 token 推导），避免一个说装得下、一个说太密。
3. **δ**：F1 python-pptx 迁移若重写 `load_layout` 消费方（compose 链），sidecar 加载器（`layout_bank.py`）保持独立模块以便内核迁移时零改动——请勿将其并入 builder。
4. **总架构师**：B2 调度器输出是否需要进 run 状态机（当前设计为无状态只读脚本 + 母版文档落痕，不新增状态）；若 γ 的 E4 逐页容错需要调度重试，请确认在 γ 层包装而非本层加状态。
