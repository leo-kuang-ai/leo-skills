# Leo PPT Generator 五类目标与内容能力测评方案

> 文档版本：v3；日期：2026-09-06；状态：方案完成，测评未在本会话执行。沿用既有文件路径，避免打断 zcode 引用。
> 当前重点：管理层汇报与营销路演的内容能力；同时覆盖正式交付、规模化生产和跨行业迁移。先做内容层配对测量，再按预算进入成品与真实听众验证。最大边界：专家或模型评分不能替代真实使用效果。

## 目标

在高可靠交付基线之外，测量 `leo-ppt-generator` 是否能帮助用户把原始材料组织成：

1. 可被复述的核心判断；
2. 支撑判断的证据链；
3. 对听众有意义的解释和决策含义；
4. 推动行动或达成共识的结尾。

本方案评价的是内容组织和说服效果，不把视觉精美、规则数量或字数多少当作洞察。最终验收采用“真实多行业任务 + 人在回路关键节点确认 + 成品文件验收”的组合标准。

## 验收总原则：三层闭环

| 层级 | 要回答的问题 | 权威证据 | 可否由系统替代 |
|---|---|---|---|
| 流程覆盖 | 是否覆盖 PPT 创作的必要环节 | Skill 源码、合同、脚本、运行账本 | 只能证明流程存在，不能证明结果好 |
| 关键节点决策 | 内容、叙事、视觉方向是否符合用户意图 | 用户在合同、大纲、母版、样张节点的确认收据 | 不能由模型自称确认；用户未确认则保留 pending |
| 最终成品结果 | 真实 PPT 是否可用并达到用户接受标准 | 真实文件、渲染结果、查看器检查、用户验收记录 | 自动检查只能覆盖结构和部分事实，不能替代用户验收 |

测评结论只有在三层均有证据时才可写为“通过”。流程完整但用户拒绝关键节点，结论为“流程可运行、内容未接受”；用户接受内容但成品存在 P0/P1，结论为“决策通过、交付失败”。

## 人在回路确认协议

用户只需要在会改变内容方向或验收结果的节点做决定，系统自动完成可逆准备和确定性检查。必须保留以下收据：

1. **内容合同确认**：主题、受众、场景、页数、`one_thing`、事实边界和行动目标；
2. **大纲确认**：页序、每页核心判断、证据分配和删减取舍；
3. **母版确认**：逐页标题、要点、视觉行、来源和论证角色；
4. **视觉方向与样张确认**：风格、版式、密度、典型难页和需要修改的地方；
5. **最终成品验收**：文件完整性、事实、可读性、行业适配、可编辑性（如适用）和交付用途。

每个节点记录 `decision_source: user-confirmed|user-delegated`、用户原话或授权依据、决策版本、时间和绑定工件哈希。`user-delegated` 表示用户授权 Agent 在范围内决策，不等于用户逐项审阅；只有 `user-confirmed` 才能声称该节点由用户确认。

用户拒绝时必须记录拒绝原因和修改方向，建立新版本后重新确认。不得用“用户没有反对”“模型认为符合”或最终下载动作替代确认。

## 核心判断模型

每套 deck 必须回答五个问题：

| 问题 | 可观察证据 |
|---|---|
| 讲什么 | `one_thing` 能否用一句完整判断句表达 |
| 为什么相信 | 每个关键判断是否有来源、数字、案例或明确不确定性 |
| 为什么现在关心 | 是否解释影响、机会、风险或代价 |
| 听众要理解什么变化 | 页间是否形成因果、比较、转折或取舍链 |
| 之后做什么 | 收束页是否给出具体行动、决策或待确认事项 |

## 五类目标模式覆盖矩阵

同一套 Skill 不能用单一总分评价。测评开始时必须声明目标模式，并使用对应的主要短板、指标权重和失败门槛。

| 目标模式 | 短板优先级 | 首要测评问题 | 核心指标 | 一票否决 |
|---|---|---|---|---|
| 高风险正式交付 | 事实、来源、行业合规、交付可靠性 | 文件能否在真实环境中无重大错误交付 | P0/P1 错误率、来源可追溯率、敏感数据违规率、交付成功率、恢复一致性 | 事实错误、来源断链、合规违规、页缺失、查看器打不开 |
| 管理层汇报 | 洞察、决策支持、信息压缩 | 高管能否快速理解判断、取舍和行动 | 核心判断复述率、决策一致率、关键页保留率、信息压缩损失率、行动明确率 | 无法说清核心判断、关键证据被压掉、没有决策请求 |
| 营销路演 | 叙事节奏、视觉冲击、记忆点 | 听众能否被吸引、记住价值并继续行动 | 关键节点记忆率、叙事完成率、价值主张复述率、视觉层级通过率、行动转化意愿 | 价值主张不清、故事断裂、记忆点与事实冲突、视觉遮蔽关键内容 |
| 规模化生产 | 流程复杂度、成本、吞吐、自动化程度 | 在可接受成本下能否稳定批量交付 | 单 deck 耗时 P50/P95、单位页成本、并发吞吐、人工介入率、失败恢复率、重复计费率 | 批量任务无法恢复、成本失控、人工介入随规模线性失控 |
| 通用 PPT Agent | 跨行业迁移、真实效果评测 | 换行业、换材料和换听众后，核心能力是否仍成立 | 跨行业性能方差、迁移后 P0/P1 率、零样本任务成功率、评审者一致率、真实任务改善率 | 只在单一模板或单一行业有效、换领域后事实或论证系统性失效 |

### 模式之间的关系

- 高风险正式交付是安全底线，任何其他模式都不能绕过事实、来源和交付门禁。
- 管理层汇报和营销路演共享“洞察与说服”能力，但管理层偏向决策压缩，营销偏向注意力和记忆。
- 规模化生产主要评价系统运行特征，不应通过降低事实或人工验收标准换取吞吐。
- 通用 PPT Agent 不是把五类模式平均相加，而是要求在不同模式间保持可解释的能力迁移，并暴露性能下降。

### 模式选择记录

每次 zcode 测评在输入合同中新增：

```yaml
evaluation_goal: high-risk-delivery | executive-briefing | marketing-pitch | scaled-production | general-agent
primary_failure_lens: <与目标模式一致>
secondary_lenses: [<可选>]
acceptance_owner: <负责最终取舍的人>
```

目标可从明确任务推断并记录依据；无法推断时采用探索性分轨报告，不建立跨轨总分。只有会实质改变成本或验收范围时才补问。

## 五条可执行测评轨道

### 轨道 A：高风险正式交付

扩展运行集为 4 个领域 × 3 套 deck；每领域选择一套有合法输入的任务做两路线配对。不能把同一文字输入强塞进重建路线。每套交付检查来源、数字、敏感字段、真实查看器和人工验收；预期阻断用例单独统计。正式交付详细方法沿用 [可靠性基线方案](2026-09-06-001-leo-ppt-reliability-baseline-evaluation-plan.md)，已运行的 zcode 批次不回写新规则，后续批次采用本版补充的统计口径。

建议权重：事实与来源 35%，行业合规 25%，交付完整性 25%，恢复与可追溯 15%。任何一票否决项出现即失败。

### 轨道 B：管理层汇报

固定同一份经营材料，分别生成 CEO、业务负责人和财务负责人版本。比较三版是否改变了重点、证据粒度和决策请求。要求评审者在 60 秒内写出核心判断、最大风险和建议行动。

建议权重：洞察 30%，决策支持 30%，信息压缩 20%，证据可信 15%，视觉 5%。

### 轨道 C：营销路演

使用同一产品或项目材料生成 5 分钟路演 deck，设置首次观看、延迟复述和行动意愿三个时间点。评审者先不看讲稿，只看页面；之后再检查页面是否能被演讲者自然讲完。

建议权重：价值主张 25%，叙事节奏 25%，记忆点 20%，视觉冲击 15%，证据与边界 15%。视觉冲击不得以牺牲事实和可读性换取。

### 轨道 D：规模化生产

先运行 20 页任务，再按获授权预算扩至 50、100 页，三档保持相同页型比例。先固定单一 backend 测并发 1 与宿主允许的较高并发；第二 backend 是独立扩展实验，不能同时更改页数、并发和 backend。记录耗时、成本、人工介入和重试；样本不足时报告逐次数据和最大值。失败任务不得通过删除失败页变成成功。

建议权重：吞吐 25%，成本 20%，自动化率 20%，恢复成功率 20%，一致性 15%。事实和交付门禁仍为硬约束。

### 轨道 E：通用 PPT Agent

对固定 Skill 快照使用领域留出盲测：开发者只接触开发集，封存领域的业务 fixture 与答案不参与调整。内置行业规则可能已覆盖该领域，必须披露，故不能声称“模型从未见过该行业”。每次启封前锁定 Skill 与 Judge；启封后该集合退役为回归集。若做四折开发实验，每折从同一初始快照开始，禁止把前折盲测答案带入后折。零样本仅指本次任务未提供示例，不能据此推断训练数据无污染。

建议权重：跨行业稳定性 30%，零样本成功率 25%，事实与合规 20%，论证质量 15%，用户介入成本 10%。

## 最小样本与重复规则

- 每个基准 fixture 在相同材料、听众、页数、预算和配置下独立重复 3 次，记录随机种子（若支持）；输入顺序、听众或证据变化另建变体 ID，每次只改一个变量，不混入重复统计；
- Provider、模型、字体、查看器和 runtime 版本固定并写入 `baseline-inventory.md`；
- 同一任务的首次运行、返工运行和恢复运行分开统计；
- 任何人工修改后的 deck 只能进入返工结果，不能回填首次通过率；
- 评审者不知道 deck 来自哪条路线或哪个 backend，减少来源偏见。

## 跨轨道比较

报告不得只给一个总分，至少同时展示：

1. 五条轨道的主要指标和一票否决结果；
2. 同一 fixture 在不同目标模式下的取舍变化；
3. 事实可靠性与洞察说服力的相关或冲突；
4. 成本、耗时、人工介入与质量之间的曲线；
5. 从开发集迁移到盲测集的性能下降。

若某项优化提升视觉或速度，却提高 P0/P1、降低复述率或增加人工返工，判定为负收益，不能以平均分掩盖。

每次测评任务开头填写：

```yaml

fixture_id: <固定编号>
route: generate
deliverable_type: image
evaluation_stage: content
audience: <单一主要听众>
success_claim: <本轮要验证的一句话>
hard_gates: [facts, sources, compliance, delivery]

```

上面是评测侧记录示例，不是已实现的 CLI schema。`route` 取现有 `generate|direct-editable|upgrade-full|upgrade-selected`；`deliverable_type` 取 `image|editable|hybrid`；`evaluation_stage` 取 `content|artifact|audience`。内容轨不启动生成 runtime，因此 route 仅为计划值，实际 route 以运行收据为准。

任务结束必须输出：

- 生成物路径和版本指纹；
- 逐页缺陷与证据；
- 目标模式指标；
- 未运行的现场或人工检查；
- 与上一次基线的差异；
- 下一轮只保留一个最高影响改进假设。

## 测评对象

### 材料难度

- **事实堆积型**：资料完整但没有现成结论；
- **冲突型**：不同来源、数字或观点互相矛盾；
- **信号弱型**：重要洞察埋在大量次要信息中；
- **不确定型**：材料同时包含事实、估算、假设和未知项；
- **决策型**：需要在多个方案、风险或资源分配之间做选择。

### 听众类型

- 管理层：关心判断、风险、资源和决策；
- 客户或投资人：关心价值、可信度、差异和回报；
- 技术或学术同行：关心方法、证据、边界和可复核性；
- 合规或公共部门：关心依据、影响、公平性和责任边界。

每个 fixture 固定一个主要听众，禁止用“所有人都能看懂”替代受众定义。

## 评测任务设计

内容轨先产出合同、大纲、逐页内容母版与下列证据，不要求生成图片或 PPTX；成品轨才要求完整 deck。两轨单独报告，内容通过不等于成品通过：

- 内容合同；
- `one_thing`；
- 论证模式及选择理由；
- 逐页大纲；
- 证据与来源映射；
- 关键不确定性和未决问题；
- 收束页行动或决策请求。

设置三种对照：

1. **原始材料直出**：检验是否只是重排材料；
2. **用户给定结论**：检验有充分支持时能否组织证据；证据反驳该结论时必须指出冲突，不能把迎合用户计为成功；
3. **用户只给目标**：检验 Skill 能否自主发现合理洞察并明确不确定性。

## 内容质量维度

### 1. 洞察发现

检查是否识别材料中的趋势、反常、差异、因果线索、约束和关键取舍。洞察必须能指向材料中的具体证据，不能只是抽象口号。

### 2. 判断清晰度

检查内容页的首要信息是否清晰独立成立，标题是否符合已选论证模式；封面、目录、章节隔断、合法悬念页不机械要求论断句。对演讲型页面另检查与讲稿配合后的含义，避免把适合演讲的简短页面误判为信息不完整。

### 3. 证据链完整性

检查“判断—证据—解释—含义”是否闭合；数字、引用和案例是否标注来源等级；证据不足时是否保留 unknown 或限制性表述。

### 4. 论证推进

检查页面之间的背景、原因、转折、取舍与行动关系。删除测试仅作为疑点线索；必要的引用、合规声明、节奏停顿和附录可有独立职责，不能因为不改变主论点就判为冗余。

### 5. 听众适配

检查同一材料是否根据听众改变重点、术语、证据粒度和行动请求，而不是只替换封面标题。

### 6. 反方与边界

检查是否主动呈现最强反方、替代解释、数据缺口、适用边界和失败条件。说服力不能通过隐藏不利证据获得。

### 7. 行动转化

检查结尾是否对应任务目标：决策稿应明确选择、依据与下一步；科普或学术分享可以用理解目标、结论边界或研究问题收束。未知负责人、期限和预算必须留待指定，不得为评分编造承诺。

## 评分与证据

每个维度 0–4 分，并记录逐页证据：

- 0：缺失或与材料冲突；
- 1：形式出现，但不能支持理解；
- 2：基本成立，存在明显断裂；
- 3：清晰、可复核、适配听众；
- 4：形成强判断和可执行决策支持。

评分不采用简单总分通过。以下任一项为 0 或 1，整套 deck 标记为说服力失败：

- 核心判断清晰度；
- 关键证据链；
- 听众适配；
- 行动转化。

另设两个结果指标：

- **复述率**：听众在看完后能否准确复述 `one_thing`；
- **决策一致率**：不同评审者是否从 deck 得出相同的主要决策含义。

### 指标计算与判官校准

- 复述率 = 准确复述 `one_thing` 的评审人数 / 有效评审人数；先定义允许的同义表达，再盲评。
- 决策一致率 = 给出同一主要决策含义的评审对数 / 全部有效评审对数；若任务允许多方案，先登记可接受集合。
- 信息压缩损失率 = 压缩版中丢失且被评审判为关键的证据项 / 原版关键证据项；不能按字数或页数直接推算。
- 跨行业性能方差 = 各行业同一指标的方差或区间；报告样本量，不能把小样本差异解释成迁移结论。

正式评分前，三类评审者用两套共享校准样例练习；对 P0/P1 与 0/1 分边界逐项对齐，保留独立初评。可报告一致率或 Krippendorff's alpha，但统计量只描述一致程度，不替代裁决。低一致时先修订 rubric 或证据定义，再重评，不取平均掩盖分歧。

## 反事实与对抗测试

- 删除核心证据，检查 Skill 是否仍声称原结论确定；
- 交换两组数据，检查标题和结论是否随证据变化；
- 加入诱导性但无来源的数字，检查是否拒绝或标记；
- 提供强反方材料，检查是否纳入而非静默忽略；
- 将同一材料交给不同听众，检查是否出现真正的重点变化；
- 要求压缩页数，检查是否优先保留主线和关键证据，而非均匀删字；
- 将结论改为相反方向，检查证据链是否能够指出不成立。

## 人工评审协议

至少三类评审者独立打分：领域专家、叙事或咨询专家、目标听众代表。评审者先看 deck，再看原始材料，避免被 Skill 的解释性文字影响。每个 P0/P1 内容问题必须附页码、原文证据和影响说明。

评审后进行结构化访谈，只问三件事：

1. 你认为这套 deck 的核心判断是什么？
2. 哪一页最让你相信或怀疑这个判断？
3. 你会因此采取什么行动或提出什么决策？

答案与 `one_thing`、证据页和收束页对照，形成复述率和决策一致率。

## 主要失败类型

- **材料复述**：内容完整，但没有新增判断；
- **伪洞察**：把相关性包装成因果，把单点数据包装成趋势；
- **证据断链**：标题结论超过来源强度；
- **平均主义**：所有材料获得相同篇幅，关键矛盾没有突出；
- **受众错配**：技术细节、商业价值或合规依据放错层级；
- **反方缺席**：只展示支持结论的材料；
- **行动空泛**：结论没有转化为决策或下一步；
- **视觉替代论证**：依靠大数字、金句或风格冲击掩盖证据不足。

## 结果输出

每次评测至少产出：

- `content-contract.md`；
- `outline.md`；
- `evidence-map.csv`；
- `argument-review.md`；
- `audience-recall.json`；
- `persuasion-defect-ledger.csv`；
- `insight-persuasion-baseline.md`。

报告必须分别给出：Skill 自主发现的洞察、用户已提供的洞察、评审者推断的洞察，以及尚未被材料证明的假设。

## 完成标准与停止规则

一个目标模式的基线在以下条件同时满足时才算完成：

1. 该模式的最小样本已按固定版本运行；
2. 每个 fixture 有输入、预期答案、逐页证据和评审记录；
3. 首次、返工、恢复和现场未运行项已分开；
4. 一票否决项已由领域负责人复核；
5. 最高影响失败已归因到内容、渲染、运行或协作边界之一，或明确标记为未知；
6. 报告能支持下一轮只改变一个变量的对照实验。

出现以下情况应停止扩样并先修复测量：预期答案无来源、评审者无法区分事实与假设、同一变量在同批次同时改变、人工修订混入首次结果，或跨轨道指标定义不一致。

## 真实多行业任务的最终通过条件

单个任务通过必须同时满足：

- 用户确认了合同、大纲、母版和视觉方向等适用关键节点；
- 确认后的内容没有超出用户授权范围的事实、结论或视觉方向漂移；
- 最终 PPT 文件在目标查看器或导出形态中可打开、页数完整、无 P0/P1 缺陷；
- 用户明确表示文件符合本次用途，或按约定提出的修改已完成并再次验收；
- 所有未运行的 Provider、OCR、桌面、投屏或人工检查均如实标记；
- 交付收据能够绑定最终文件、输入材料、QA、渲染预览和模板样式源。

跨行业基线通过不要求五类行业使用相同模板，而要求每个行业有明确的用户验收标准，并能解释行业差异、失败原因和适用边界。没有用户验收证据的任务只能标记为“技术完成”或“待验收”，不得进入“高质量交付通过”统计。

## 第一轮最重要的验收问题

> 对同一份材料，Skill 是否能让不同评审者更快形成同一个、可由证据复核的判断，并明确知道应该采取什么行动？

如果不能，优先改进内容合同、论证组织、证据映射和受众适配，再考虑增加风格或行业模板。
