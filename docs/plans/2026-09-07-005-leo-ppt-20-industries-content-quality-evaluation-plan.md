## 一、背景与定位

**执行摘要**：本轮回答“20 个固定行业任务能否产出合格的大纲、母版与风格选择合同”。复用现有 skill-up 和检查器，在评测侧补输入转换、缺失断言与结果汇总；先完成 5 单元 M0，再冻结正式协议。最大风险是把检查器覆盖不足、判官失准或训练样本适配误当作内容质量通过。当前仅规划评测资产开发，M2 技能修复必须由实际失败清单界定。

### 1.1 存量证据盘点与缺口

| 已有证据 | 覆盖内容 | 缺口 |
| --- | --- | --- |
| `evals/eval.yaml` 约 120 个政策/门禁用例 | agent 是否守规矩（Office 信任、确认门落盘、版式不缩字号等） | 不测产出内容本身的好坏 |
| 风格路由 20+50 行业轮（2026-09-01） | 风格路由可见性/索引/CLI 可加载/render 就绪/优雅降级，70/70 行业全绿 | 路由机制正确 ≠ 内容质量；未产出一套真实大纲与母版 |
| 说服力测评第一、二轮（2026-09-06/07） | 内容深度七维、反方承载、金额纪律、盲评与植入缺陷校准 | 固定 fixture F1–F8（互联网/商业语境），无行业广度 |
| 可靠性基线方案（2026-09-06-001） | 交付完整性、恢复一致性 | 以内容达标为前提，不回答跨行业质量方差 |

**缺口一句话：没有任何一轮测评回答过「换一个行业，大纲、逐页母版、风格与版式选择的内容质量是否仍然成立」。** 本方案补这条证据链。

### 1.2 目标与非目标

**目标**：以 20 个固定行业任务为输入，验证 generate 管线内容三件套的质量：大纲的结构与页序逻辑，逐页母版的结论标题、密度、断言来源和备注，以及风格与版式选择的语境匹配和容量预检。输出可复现结论与弱点清单，判断内容是否具备进入样张验证的条件；样张及最终视觉效果不在本轮证明范围内。

**非目标与口径边界**（进入报告前必须声明，不得超出证据声称）：

1. **不测图片生成与视觉呈现**。截断点在样张之前；风格维度只评「选择与合同层」（style render 注入、版式调度、容量预检、母版视觉行），不声称视觉呈现质量。
2. **不重测风格路由机制**（50 行业轮已全绿），只测「在本行业任务语境下选得对不对、用得对不对」。
3. **不测速度/成本/规模化**（轨道 D 已规划）。
4. 单次运行只支撑「存在性失败清单」；固定任务达标声称必须来自门禁轮双次复跑（§3.6）。每行业只有一个任务，结果不代表该行业总体能力。
5. M1 样本会用于 M2 调优，因此 M3 只证明固定样本回归与重复稳定性，不证明未见任务迁移或零样本成功率。本轮不新增留出任务；未来需要泛化结论时，另建未参与调优、冻结后才开放的任务集，单独预算和报告。

### 1.3 与五类目标模式的关系

本方案是轨道 E 的固定行业任务内容子轨，不计算上游五项加权总分。报告 A1–A5 判据结果、重复稳定性及失败分布；零样本迁移和真实用户介入成本记为未测。生成阶段采用明确的委托执行任务，不安排人工补答；请求澄清的次数、原因与停点作为诊断记录，不能换算成真实人工成本为零。L2 人工评审时间单独登记。

## 二、业界调研与借鉴映射

**来源边界**：以下外部研究条目保留为方法线索；本次修订未逐篇核验论文内容、数据和引文对应关系，表内具体数字与效果结论均待原文核验，不作为开发准入或通过线的依据。正式报告只引用核验过的结论，并记录原文位置；仓库前作的历史实测也不代表当前版本已经通过。

### 2.1 演示文稿生成评测基准

| 基准 | 核心发现 | 对本方案的借鉴 |
| --- | --- | --- |
| [PPTEVAL](https://arxiv.org/abs/2501.03936)（PPTAgent, EMNLP 2025） | 用 MLLM 按 content（保真）/ design / coherence 三维评演示文稿 | 三维分解思想映射为 A1–A5 五维（design 因不出图缩窄为选择合同层） |
| [PresentBench](https://arxiv.org/abs/2603.07244)（[项目页](https://presentbench.github.io/)，238 项细粒度 rubric） | 粗粒度整体判分会**高估**系统能力（NotebookLM 案例）；真实任务 + 逐项 rubric 才能定位差距 | 判据必须分解为可观察 pass/fail 子项；fixture 用真实行业任务简报而非合成题 |
| [UniPPTBench](https://arxiv.org/abs/2605.17356) | 缺少场景感知（scenario-aware）的评测会高估生成能力 | 行业 × 任务类型 × 受众分层矩阵（§3.2），不允许「同模板换行业名」 |
| [SlidesGen-Bench](https://arxiv.org/abs/2601.09487)（[GitHub](https://github.com/YunqiaoYang/SlidesGen-Bench)） | 确定性/程序化指标与人工判断 Spearman 0.71 **高于** LLM-as-judge 的 0.57 | L0 机器层先行且全量；judge 只判机器不可判项（语境、结构感） |
| [受众条件化基准](https://arxiv.org/abs/2606.19256)（8,133 探针 × 3 受众画像 × 7 场景） | 同材料换受众，生成质量显著分化 | 每单元固定单一主要受众并纳入分层轴 |
| [PPTBench](https://arxiv.org/abs/2512.02624) | MLLM 跨 PowerPoint 任务能力盘点 | 不直接采用（对象级任务族），仅作参照 |

### 2.2 LLM-as-judge 方法学

| 结论 | 来源 | 落地形式 |
| --- | --- | --- |
| 判官三大偏差：位置、冗长、自我增强 | [MT-Bench / Judging LLM-as-a-Judge](https://arxiv.org/abs/2306.05685) | 不做成对优劣比较；每个产物独立上下文评审，打乱批次顺序；A3 检查冗长，不能据此声称偏差已消除 |
| rubric 分解 + 显式评分步骤 + 概率加权优于整体打分 | [G-Eval](https://arxiv.org/abs/2303.16634)（[解读](https://arpitbhayani.me/blogs/g-eval/)） | judge prompt 统一结构：判据 → 逐项核对步骤 → 每子项结论 → 维度结论；不给「打个总分」 |
| 子准则分解提升判定确定性 | [DeCE](https://arxiv.org/abs/2509.16093) | 每维度拆 3–6 条子判据，逐条独立输出 pass/fail |
| 自偏好偏差需跨模型家族评审 + 人工校准 | [Self-Preference Bias](https://arxiv.org/abs/2410.21819)（SPI 指数） | 双评审官取不同模型家族；L2 人工抽检量化 judge-human 一致率 |
| 绝对分噪声大，配对/判据式结论才可决策 | 仓库实证：6 判官交叉 ±8 极差、paired 6-0 全数一致 | 0–4 分沿用说服力一轮锚点**只做 triage**；决策只看判据 pass/fail |

### 2.3 评测工具框架对比与选型

[promptfoo](https://www.promptfoo.dev/)（CLI 优先、断言矩阵、CI 集成）、[DeepEval](https://deepeval.com/)（pytest 风格、内置 G-Eval/幻觉指标）、[Ragas](https://docs.ragas.io/)（faithfulness/相关性等 RAG 指标）、[LangSmith](https://www.langchain.com/langsmith) / [Braintrust](https://www.braintrust.dev/)（追踪、数据集管理、人工标注队列）的对比可见 [MLM 综述](https://machinelearningmastery.com/llm-evaluation-frameworks-compared-how-to-actually-measure-what-your-model-does/)、[GenAI QA](https://genai.qa/blog/promptfoo-vs-deepeval-vs-ragas/)、[AIML QA](https://aiml.qa/llm-evaluation-framework-benchmark-2026/)。

**选型结论：不引入任何外部评测框架作为运行时依赖。** 理由：① harness 职责（用例编排、断言、报告）已由 skill-up 承担且与 `evals/eval.yaml` 生态打通；② 断言/指标职责已由 `judge_*.py` 自包含脚本 + 确定性检查器覆盖（promptfoo 的 assertion 思想与 DeepEval 的 G-Eval 封装，仓库已有等价物）；③ 外部平台的追踪/托管数据集对单机技能评测收益低、引入供应链面。**借模式，不借依赖**：

- promptfoo 的 per-case 配置覆盖与 CI 门禁 → 本方案 per-case 覆盖 `max_turns/timeout`，结果并入已规划的评测五层 CI（可靠性加固第二批 WS7）；
- DeepEval 的指标脚本化 → judge 脚本进 `evals/fixtures/scripts/`，与既有 `judge_style_*.py` 同范式（自包含 + 否定感知）；
- Ragas 的 faithfulness 语义 → A2 断言来源纪律，以 `check_content_facts.py` 做数字候选差异检查，语义归属仍由 judge 核对；
- LangSmith 的人工标注队列 → fixture 版本化目录 + L2 人工抽检协议（§3.4）。

## 三、测评设计

### 3.1 评测对象与截断点

每单元以 execute 模式进入 generate 路线，运行至内容与风格合同完成，**停在样张之前**。受评产物（全部为落盘文件，可机检可审计）：

1. 内容合同（含 `one_thing`、受众、页数、事实边界；所有材料不足单元均含缺失声明）；
2. `content/outline-v<N>.md`（逐页大纲）；
3. `content/deck-master-v<N>.md`（逐页母版：结论句标题、要点、视觉行、备注）；
4. 风格选定记录：`style list/load/render` 的 selection_fingerprint 与归因句、版式 P 码调度、render 输出；
5. 评测侧从冻结母版和版式记录确定性投影的 `capacity-spec.json`、字段到母版页码/行号的映射、容量预检结果；
6. `sources/` 输入材料快照、材料清单与 SHA-256、执行轨迹、实际委托依据及内容决策记录。

不要求：样张、逐页出图、PPTX 组装（轨道 A/成品轨职责）。不调用图片 Provider，不派发逐页 worker；生成模型和 judge 模型仍需真实可用。任务开头明确“只完成样张前内容与风格选择，允许范围内可逆决策”；如无法可靠推断的关键事实仍需补答，记录 `blocked`，不模拟用户答案或人工确认。委托记录如实写为委托决策。核对当前执行路径是否支持该截断点是 M0 前置检查，不能伪造 worker/provider ready 来绕过路径限制。

### 3.3 质量维度与判据（A1–A5）

每维度拆子判据；**机器可判项归 L0，语义项归 L1，口径与校准归 L2**。judge 判据一律表述为可观察事实问题，配合否定感知词表（判「通过」需先逐条排除失败形态，命中失败形态即 fail——沿用仓库测试准则）。

**A1 大纲结构与页序**
- A1.1 页序形成因果/比较/转折链而非并列堆叠（judge，逐对相邻页问「为什么下一页是它」）；
- A1.2 大纲覆盖合同承诺（one_thing、行动目标、页数），deck-promises 表完整（机检：承诺页存在性 + 页数与合同一致）；
- A1.3 无重复页、无断层（judge + 目录/正文交叉引用核对）；
- A1.4 结构页（封面/目录/收束）从总页数内分配，收束页含行动项（机检 + judge）。

**A2 断言与来源纪律**
- A2.1 按当前执行合同四级标注：引用有出处、估算标明假设、示意标明性质、用户确认可回溯真实会话；来源不足标 `unknown`，不得支撑确定性结论。fixture 文本为材料引用，不冒充本轮用户确认（机检格式 + judge 全量语义核对）。三级登记表检查器的兼容性限制按 §3.5 处理；
- A2.2 数字登记表完备：结构由 `check_number_ledger.py <master>` 校验；评测侧补标题和要点数字到同页 ledger 的覆盖断言，沿用既有数值归一化规则并保留口径。`--diff <old> <new>` 只用于真实修订前后留存检查，无旧版时该留存项记 `not_applicable`；
- A2.3 事实回读：先用 `check_content_facts.py` 找数字候选差异，再由 judge 对照来源位置核对主体、期间、单位及因果归属；材料中出现同一数字不等于事实成立。生成阶段至多两轮修订，保留全部版本，最终冻结后只评不修；
- A2.4 冲突型单元（U04/U10/U16）：跨源冲突被显式裁决并披露，不盲从权威、不静默取舍（judge）。

**A3 要点密度与文案纪律**
- A3.1 结论句标题按页面角色和论证模式条件化，论点具体且有依据；有可信数字时用数字，无数字依据不强迫补数，封面/目录等结构页按其角色检查（机检线索 + judge）；
- A3.2 要点禅档位：论点页 ≤3 条、台账页 ≤6 条、论点页正文合计 ≤80 字（去机器标签与空白后的 Unicode 字符数，数字和标点各计一字符）。每条 ≤2 行只检查母版显式分行；实际渲染换行未测，不能声称像素级不溢出；
- A3.3 文案纪律：翻案腔/AI 腔超限即 fail（`check_deck_prose.py`，exit 1）；
- A3.4 备注分栏完整（speaker_script / engineering），无占位残留（机检）。

**A4 行业语境匹配**
- A4.1 行业术语使用正确：fixture 附每行业 10–15 条术语正误对照表（如政务「口径/层级」、金融「净额/全额」、临床「疗效/效果」），judge 按表核对（机检可先做词面误用扫描）；
- A4.2 语气与场合合规：政务语体庄重、医疗不绝对化、金融有风险披露意识、公益不滥用商业话术（judge，泛化区同判）；
- A4.3 行业数据直觉不越界：无该行业常识性错误（如把毛利率当周转率），无法核实的判断已标注不确定性（judge）。

**A5 风格与版式选择（合同层）**
- A5.1 风格归因在场：推荐带归因一句、选择依据落盘；错配有首次风险提示（机检记录 + judge）；
- A5.2 版式调度与页面角色匹配：数据页用图表版式、论证页用论证版式；P 码不虚构（机检：调度 ID 存在性）；
- A5.3 容量预检：`check_deck_geometry --capacity` 使用完整投影的页面内容；硬超为 fail，软超如实报告，不能写成“全部容量正常”；内容缺项或投影丢失为 error。修订只改内容或换版式，不缩字号；
- A5.4 泛化区附加（DG1–DG4，沿用 50 行业轮）：不误导、无虚构风格名、给降级指引、降落可 render 的近邻风格；
- A5.5 style render 注入产物含护栏且组合器白名单投影正常（机检 render 输出结构）。

### 3.4 三层判定体系

**L0 机器层（确定性，全量，先行）**：输出 `machine-report.json`，逐项记录判据、输入 hash、命令/函数入口、原始退出码、明细、证据位置和归一化状态。依据各检查器真实语义区分质量失败、warning 和工具错误，禁止将所有非零退出码都归因于内容。返回 0 但未检查必需字段同样不能 pass。L0 不停止可执行的 L1 检查；产物缺失导致无法评审的项记 `error`，不让 judge 猜测。

**L1 判官层（LLM judge，全量）**：
- 形式：每维度一个自包含 judge 脚本（`evals/fixtures/scripts/judge_content_a{1..5}.py`），输入为匿名化产物包。每次产物分配独立匿名 ID，移除模型/轮次信息，但保留合同、材料、事实出处与有效委托证据；匿名映射和原件由评测侧保管。每个产物独立上下文，不向生成侧回传标准答案；
- prompt 结构（G-Eval 式）：维度判据 → 逐子项核对步骤 → 每子项 pass/fail + 证据引用 → 维度结论；**禁止输出总分**（0–4 锚点分仅 triage 用，另存字段）；
- 否定感知：每个子判据附「失败形态清单」，judge 必须显式确认未命中才可 pass；
- 双评审官：两个不同模型家族各评一遍，至少一个不同于生成模型家族；具体模型、版本与采样配置在 M0 登记。缺少真实可用的第二家族时记 `blocked`，同模型角色模拟不能替代该条件。同子判据分歧由第三个独立上下文的仲裁调用核对，保留两份初判；维度内 ≥2 项分歧时仲裁覆盖整维度。仲裁可使用已登记模型，不额外声称第三家族；结果须含可定位证据。仍无法裁决记 `error`，不默认多数通过。

**L2 人工校准层（抽样 + 对照品）**：
- 对照品：保留 2 份经核对的健康基线，派生 6 份单缺陷副本，每份只植入一项（断链数字、裸算金额、估算冒充引用、密度超限、术语误用、风格虚构）。缺陷有证据依据和目标子判据，不虚称已经从历史台账找到。两位初评官各自须检出 ≥5/6（满足 ≥80%），两份健康基线的适用子判据均无误报。分别报告每位判官和最终仲裁结果；机器检出不能冒充 LLM 检出。
- 人工抽检固定 U02/U03/U04/U13/U18（G1×3 + G2×2），由用户或领域熟悉者独立判定后再揭盲。每个适用子判据为一个比较项，一致率 = 初判一致项 / 全部预定适用项；缺判不计一致。每位 judge 与人工均须 ≥75%，另报 fail 项一致情况和分歧明细，防止大量 pass 掩盖漏检。M0 准备抽检所需样例；M3 对两次运行均抽检。没有人工记录时 L2 为 `pending`，不自动由模型代签。
- 任一校准条件不满足，受影响协议的 L1 结果仅供诊断，最终达标声称暂停；不对 pass/fail 做漏检率折减。人工暂缺时可完成骨架、M0 运行和机检，正式 M1 准入仍待校准闭合。
- M0 可修改判据。M1 后若仅修改 judge prompt 或模型配置，须产生新评审版本，重新校准并对全部 M1/M3 存量冻结产物重评，不能只重评失败项；若修改判据含义、通过线或 fixture，则开启新协议版本，从 M0 校准及受影响生成轮重新建立基线，旧结果保留且不可混算。

### 3.5 执行工程（skill-up 集成）

- 用例文件：`evals/cases/content-quality-20industries.yaml`，每单元一 case，**per-case 覆盖** `max_turns: 48`、`timeout_seconds: 3600`（现有 defaults 4/300 为政策用例量级，内容单元远超；具体值以 M0 试点实测校准后冻结）；
- 路径基准：本节 `evals/`、`scripts/`、`tests/` 均相对 `leo-ppt-generator/`。fixture 存 `evals/fixtures/content-quality-20industries/`；生成侧输入与评审侧答案分目录，case 仅复制允许的输入。根目录 `leo-ppt-content-eval-workspace/` 为运行产物，开发时验证 Git 忽略规则，不能在技能发现目录内建临时工作区。
- 判官与机检适配属评测侧资产。采用 `compose / thin-glue`：复用现有检查器，只补输入转换、覆盖缺口、错误分类和汇总；不复制已有领域规则，不因测评便利修改技能本体。M2 的产品修复另受阶段门约束。
- 环境：`LEO_PPT_HOME` 按尝试隔离；每次运行记录 Skill/CLI/runtime、生成模型、judge 模型、prompt、fixture、判据和配置指纹到 `baseline-inventory.md`。当前工作树有未提交技能与执行合同改动，M0 必须记录实际文件 hash，不能只记 Git HEAD；M1 期间冻结快照，M2 后另记产品版本，M3 两次必须相同。

**最小接口与证据合同**：

| 输入/检查 | 复用边界与评测侧职责 | 必须发现的失败 |
| --- | --- | --- |
| 母版与 ledger | 结构检查复用 `scripts/check_number_ledger.py`；正文覆盖补充同页标题/要点到 ledger 对账；`--diff` 仅比较真实相邻修订 | 要点数字未登记、错页登记、已核实数字静默删除；年份/交叉引用按既有规则排除 |
| 来源回读 | `scripts/check_content_facts.py` 接收母版及允许的材料文件；其数字集合匹配只作候选检查 | 同数异主体/期间/单位交由 L1 判失败；缺材料文件是 error，不生成替代来源 |
| 容量投影 | `capacity-spec.json` 含 `style`、完整 `slides`；逐页 `page/layout` 以及检查器实际消费的 `points/slots` 等字段从母版转换；每字段可回溯 | 缺页、空内容、未知版式、投影丢字、硬超；禁止填空数组骗取通过 |
| 母版/文案/风格 | 通过实际 CLI 或函数入口运行已有检查器；M0 固定判据到检查项的映射，记录 WARN 和跳过项 | 仅 WARN 的必需内容违例由映射明确升级，不笼统将退出码视作覆盖证明 |
| judge 输出 | `criterion_id/status/evidence/reason` 与模型版本；证据定位到原件或匿名件可映射位置 | 非法 JSON、缺子项、无证据 pass、模型调用失败均为 error |
| 聚合结果 | 每次尝试保留原始 skill-up `result.json`、per-case evidence、machine-report、judge 原始响应和汇总结果 | 缺必需产物不能 pass；报告可由冻结原件和相同汇总逻辑重建 |

**已知兼容性边界**：`references/image-deck-workflow.md` 已定义四级证据，`scripts/check_number_ledger.py` 的 `VALID_TIERS` 当前仍为三级。遇到有真实依据的“用户确认”行时，保存原始报错并归为 `error/tool_contract_mismatch`，不改写事实等级或标为内容失败。本轮 fixture 不预造用户口述数据；若实际触发此兼容问题，暂停受影响项，修复当前 owner 后重验。该问题不能靠匿名化删除证据来规避。

**失败与重试**：质量 fail 不自动重生成；生成器超时/异常记 error，关键输入需人工补答记 blocked。模型服务临时失败或 judge 输出格式错误最多重试一次，原尝试完整留存；重试成功可恢复评审状态，但仍计调用和可靠性错误。中断只恢复未完成步骤，不覆盖冻结产物。达到成本上限停止新增调用，记未完成；不得筛选最佳尝试充当门禁重复。

### 3.6 阶段安排与准入条件

- **M0 试点（5 单元：U01/U03 互联网科技与医疗规内 + U13/U15/U18 泛化）**：实现评测骨架，校准 max_turns/timeout、容量投影、产物冻结和 judge 接入。每个判官对同一冻结产物的适用语义子项评两次，一致率 ≥80%；任一判官未达到则不能进入 M1。人工抽检另需 U02/U04 两个校准样例，加上 M0 中的 U03/U13/U18，凑齐 §3.4 固定五行业。完成健康/缺陷对照、人工校准及预算后冻结正式协议；
- **M1 全量挖掘（20 单元 ×1 次）**：失败即收获，产出弱点清单（失败单元 × 维度 × 子判据 × 证据），逐条定级 P0–P3 与修复方向；
- **M2 加固**：M1 报告给出每项失败的证据、根因、所属文件与修复验证，随后才确定技能本体修改范围。补 content_rules、改生成 prompt 或将既有判据做成产品硬门禁均不得改变评测题目/通过线。按实际影响运行包级检查；新增风格/版式时两条风格 lint 必须通过，其他 lint 按被修改资产的 owner 要求执行，既有政策用例做相关回归；
- **M3 门禁复跑（20 单元 ×2 次独立重复）**：相同产品快照、fixture、配置和判据；每次独立工作区与会话，禁止读取另一轮产物。两次均全 pass 才算固定任务达标。一 pass 一 fail 记不稳定且不达标，不加第三次投票翻盘；工具 error/blocked 记未完成，按重试规则处理；
- **M4 报告与沉淀**：失败案例固化为永久 eval cases 进 `evals/cases/`，报告按 §3.7 口径发布。

### 3.7 预注册判定规则（先锁后跑，M0 后冻结）

| 层 | 通过线 | 未达标处置 |
| --- | --- | --- |
| L0 机检 | 每轮 20/20 单元适用硬断言通过，无工具错误 | 质量违例记 fail，工具/输入错误记 error；warning 保留明细并按冻结映射处理 |
| L1 判据 | M3 每维度双次通过任务数 ≥18/20，基线 G2 单独 ≥7/8 | 只作套件维度门槛，不能替代逐任务五维全过；不足则报告未达门槛，修复后开启新的完整门禁轮 |
| L2 校准 | 每位 judge 植入检出 ≥5/6；健康对照零误报；与人工一致率 ≥75% | 任一未达或记录缺失即暂停达标结论；按 §3.4 版本化修订并重评，不修改已冻结通过线 |
| 一票否决 | 无伪造来源、无虚构风格名、无敏感数据违规、content 文档全部落盘 | 命中质量违例则任务 fail；缺文档按轨迹区分 fail/error；一律保留在固定分母内 |
| 最终声称 | L2 有效且完整评审后，M3 双次五维全过固定任务数 X/20 | 「本版本在 20 个固定行业任务中，X 个任务的内容层双次达标；未验证未见任务迁移或视觉质量」 |

**汇总规则（唯一口径）**：

- 原子项状态为 `pass/fail/not_applicable/error/blocked`；`not_applicable` 仅限冻结协议预先定义的条件（例如非冲突任务的冲突裁决、无修订的 diff、G1 的降级附加项），必须附理由，不用于缺证据或缺字段。
- 同一子项含机器与语义检查时，两者都通过才 pass。维度中全部适用子项通过才维度 pass；任一 fail 则 fail；否则存在 error/blocked 则未完成。整维度不能全部不适用。
- 单次任务通过要求必需产物齐全、L0 所有适用硬断言通过、A1–A5 全过、无否决。失败与工具错误可并存并分别报告；两次任务通过才计入 X，不稳定、失败、未完成均不计入分子，分母恒为 20，G2 恒为 8。
- 套件门禁通过要求 M3 两轮各自 L0 的 20 个任务全过、上表 L1 维度门槛和 L2 有效；与“20 个任务全部达标（X=20）”分开列出。维度门槛通过不保证同一批任务五维全过。
- 存在未完成评审时只报告“已确认通过 X/20，另有 Y 个任务未完成”，不能使用最终达标模板；L2 无效时只报告诊断矩阵，不发布 X 的有效达标结论。

负收益按同协议的 M1/M3 对照判定：新增 P0/P1 或原已通过子项转失败时，不以其他维度提升抵消；列出退化证据并回到修复定位。单次基线不足以证明退化的因果归属，必要复核单列诊断运行，不替换 M3 两次正式结果。

### 3.8 成本预算（假设值，M0 实测后更新）

- 生成基础量：M0 五任务 + 人工校准补充两任务 + M1 二十任务 + M3 四十任务 = **67 次生成**。健康基线优先复用已核对产物；另行生成、失败修复和重复试点单列追加。每任务 30–60 turns 仅为假设，48 turns 上限是否足够由 M0 实测决定；达到上限未完成记 error，不能算内容完成。
- L1 基础量：M1+M3 为 `60 × 5 × 2 = 600` 次调用；M0 一致率检查为 `5 × 5 × 2 × 2 = 100` 次；两个人工校准补充任务初评 `2 × 5 × 2 = 20` 次；两份健康及六份缺陷对照每次完整校准 `8 × 5 × 2 = 80` 次。M0 与 M3 前各校准一次，计划基础合计 **880 次 judge 调用**。M3 人工抽检复用对应的初评输出，不另生成。
- 仲裁、格式重试、M0 再调试、judge 版本变更后的全量重评另列预算，不包含在 880 次内。机检耗时和人工评审时间分别实测，不把人工校准称为分钟级免费操作。
- 金额按各模型实际输入/输出 token、缓存计费规则和运行日单价计算，披露币种与汇率；不按图片页数单价估算文本模型成本。M0 前给出试点调用上限与费用范围，M0 后冻结全量基础量、追加额度与总成本上限；按既有费用授权执行，若超出授权范围只确认新增部分。额度耗尽暂停新增调用并保存状态。

### 3.9 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 采样轴错位（20 单元实为同模板换名） | 任务/受众/材料形态/难度四轴显式平衡（§3.2）+ UniPPTBench 场景感知结论；fixture 需行业实质差异，M0 审一遍 |
| judge 慷慨 / 自偏好 | 否定感知 + 子判据分解 + 双评审官异家族 + 植入缺陷检出率量化 + 禁总分 |
| 单次运行方差 | 挖掘轮只做存在性结论；达标声称必须 M3 双次复跑 |
| 成本超支 | M0 实测 token 与调用量，执行费用上限；L0 优先定位问题，但不据此删掉可执行的 L1 检查预算 |
| 与存量重复 | 路由机制不重测；说服力维度只引用不重建；本方案判据为行业广度口径 |
| 口径漂移（报告超出证据） | 预注册声称模板（§3.7 最后一行）+ 诚实记录节 |
