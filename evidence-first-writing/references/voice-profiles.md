# 个人声音档案

用于 `voice`、`train-voice`、`evaluate-voice`，以及用户要求「像我写」「学习我的风格」的任务。声音档案是可选增强，不是写作阻塞条件。

## 运行时选择

按顺序处理：

1. 用户指定档案路径时，只读取该路径中的 `soul.md` 和当前渠道档案。
2. 未指定时，检查当前写作项目约定的位置；不要扫描主目录、邮箱、聊天或其他无关目录。
3. 找到档案则读取 `soul.md`（可选）和 `<platform>.md`（如 `blog.md`、`email.md`、`slack.md`）。渠道档案在渠道冲突上优先于 `soul.md`。
4. 没有档案时，提示用户可提供 2-5 份本人创作、具有代表性的案例，选择「本次临时校准」或「生成持久档案」。
5. 用户可以直接跳过案例输入和档案创建。跳过时继续写作；使用用户指定或根据体裁推断的临时语域，并明确未学习个人声音。

跳过时的最小可审计披露为：`voice_basis: temporary`、`profile_status: not_loaded_or_not_provided`、`personal_voice: not_verified`。自然语言可以解释这些字段，但不能声称已经还原或学会个人声音。

不得用仓库示例、其他作者作品或模型默认文风冒充用户档案。不得在输出中泄露声音档案原文或无关私人信息。

## 文件合同

`soul.md` 保存跨渠道稳定核心：

```markdown
# Soul
## 适用范围与证据
## 稳定语域与立场
## 核心信念与判断方式
## 观点张力
## 句子和段落节奏
## 常用词与准确口头禅
## 开头、转场和结尾
## 标点、拼写和格式
## 判断、不确定性与边界表达
## 禁用或反感表达
## 置信度与待验证项
```

认知层章节把「风格内核六问」从提炼提问落成可审计的档案结构（来源：blogger-distiller（MIT），快照 2026-08-31）：

- `## 核心信念与判断方式`：每条 = 信念陈述 + 最短出处摘录（须覆盖 ≥2 篇独立样本）+ 适用场景 + 适用边界。
- `## 观点张力`：最多 2 对内在矛盾，每对记观点A出处 vs 观点B出处，并写明何时用A、何时用B；矛盾是真实性信号，非待修复问题，不强行调和。
- 运营策略（系列规划、发布节奏、蹭热点）不属于声音档案，由 content-assets.md 与 topic-momentum.md 承接；Nuwa 排他性思想已在 2026-08-26 审计吸收（见 upstream-source-audit.md），本轮增量仅 schema 落地与行级证据格式。

`<platform>.md` 保存单一渠道语域：

```markdown
# Platform: blog
## 受众与用途
## 长度和结构习惯
## 语气与节奏
## 开头与结尾
## 格式与标点
## 已脱敏短摘录
## 与 soul.md 的覆盖项
## 证据量与置信度
```

标题可调整，但必须把观察证据、推断和低置信度规则区分开。短摘录只是节奏证据，不是替换名词的模板。

## 从案例建立档案

仅使用用户明确选择、拥有或获授权的文本。先确认每份案例的作者、渠道、时间和是否包含 AI 改写；排除转发、收到的消息、签名模板、敏感信息、机器人输出和作者不明确的文本。

合并样本前先核对作者锚点。作者、账号或栏目人格不一致时分组；无法可靠分组就停止并请用户决定是否确实需要混合档案。不得用已知身份的外部履历和印象补样本里没有的信息。

至少覆盖：句长、词汇具体程度、开头、段落推进、转场、结尾、确定程度、幽默、标点、反感表达。不要把一次错别字、单篇主题或偶然事件固化成规则。

表现类结论（例如「某类标题句式带来高阅读」）同理：来自单篇发布数据的只能作为 `observation` 或 `hypothesis`，进入稳定档案或标题公式前需至少两个可比项目重复出现、且反例已检查，并记录 `stable_rule_update` 决策。发布复盘不得把单篇表现写入声音档案当作已证规则，也不得承诺下次沿用。

- 先建立证据账本：每条观察记录最短原文摘录、样本位置、功能判断、可复用规则和适用边界。稳定特征至少有 2 条证据，来自至少 2 篇独立样本；单篇特征只能是候选。
- 行级证据格式（来源：blogger-distiller（MIT），快照 2026-08-31）：进入持久档案的每条稳定特征、信念行自带出处标记（样本编号或最短摘录锚点），`verified` 的「跨样本证据成立」据此逐行可审计；单篇特征保持候选身份，不入档。
- 2-5 个案例只足够生成 `provisional` 档案，必须标注样本薄弱。
- 长期档案应来自多个独立场景，并保留一部分案例不参与提炼，用于评估。
- 写入或覆盖持久档案前，展示目标路径和摘要，获得用户明确授权；先备份再原子替换。
- 用户只要本次校准时，不创建文件。

提炼时先做描述性量化：句长分布、问句/叹句比例、段落长度、标点密度、高频句首和重复词。量化只校准“感觉”，不能单独定义声音。然后回答风格内核：作者首先看见什么、自动排除什么、如何从现象推进到判断、偏爱和拒绝哪些素材、如何处理读者、如何表达不确定性。通用好文章规则不能冒充个人指纹。

档案状态：

- `provisional`：单篇或证据不足、未完成陌生主题与盲测；只能作低置信度方向参考。
- `verified`：跨样本证据成立，陌生主题能复现判断方式，且至少 3 组隔离盲测没有暴露稳定的判断方式破绽。

不得因文件存在就声称 `verified`。档案或样本变化后，旧验证结论自动视为需要重验。

产出持久档案前的自检清单（三列形态来源：blogger-distiller（MIT），快照 2026-08-31；条目自我方既有纪律改写）：

| 检查项 | 通过标准 | 失败信号 |
| --- | --- | --- |
| 稳定特征证据数 | 每条 ≥2 条证据、来自 ≥2 篇独立样本 | 无出处标记即入档 |
| 辨识度 | 换任何作者该条即不成立 | 「保持学习」式通用表述入档 |
| 三层分离 | 观察 / 推断 / 低置信各自标注 | 推断被写成观察 |
| 单篇特征 | 仅作候选 | 单篇主题固化为规则 |
| provisional 标注 | 2-5 样本档案标注样本薄弱 | 少样本冒充稳定结论 |
| 渠道覆盖 | soul 与渠道差异显式记录 | 渠道差异被静默合并 |
| 量化定位 | 量化只校准感觉 | 数字指纹单独定义声音 |
| 负例在档 | 反感表达与负例锚已记录 | 只记正面特征 |

## 使用档案写作

个人声音优先于通用词表，但不能覆盖事实、权限、安全、体裁真值和用户本轮明确要求。使用正文事实，不把档案中的默认姓名、数字、时间或故事带入新稿。渠道档案只控制语域，不能替代当前任务上下文。

覆盖边界披露（†合同性条款，来源：blogger-distiller（MIT），快照 2026-08-31）：任务的主题或体裁与档案样本显著不同时，显式说明该方向在档案样本中未覆盖，按临时语域处理或请用户补充样本；披露复用 `voice_basis`、`profile_status`、`personal_voice` 字段族，不新增状态名。不得以档案名义对未覆盖领域编造作者立场。档案可选维护 2-3 组「通用写法 vs 本人写法」负例锚，每侧 ≤50 字，仅作校准对照，禁止当填空模板。

## 盲评档案

`evaluate-voice` 比较相同任务的两个候选：baseline 不读取档案，profile 分支读取固定版本的本 Skill、`soul.md` 和渠道档案。两边必须使用相同模型、参数、任务字节和新会话。

评估案例来自未参与档案生成的用户真实文本。生成候选时不得读取参考答案；随机隐藏 A/B 身份后，由用户或独立人类根据「更像真实留出文本且事实完整」选择 `a`、`b`、`tie` 或 `invalid`。不得只按流畅度选择。

报告样本数、胜/负/平/无效、事实错误和典型失败。少于 10 个独立留出案例只能视为低支持观察。档案、样本、Skill、模型或案例变化后必须创建新评测，不能混用旧结果。

陌生主题测试与盲评关注五项：切入角度、素材选择、论证推进、句式节奏、情绪与读者关系。盲评者不读取档案、作者身份或建模上下文，并允许回答无法判断。机械统计接近样本但判断方式错误，仍判失败。
