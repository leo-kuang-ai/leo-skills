# 吸收的翻译方法与设计模式

本文件定义当前 Skill 的翻译方法层。它不是新的默认授权，也不要求每次任务生成过程文件。

## 方法矩阵

| 吸收项 | 当前实现 | 适用条件 | 边界 |
|---|---|---|---|
| 三模式交付 | `faithful` / `polished` / `publication` | 用户指定或从请求语义可靠推断 | 默认仍为 `faithful` |
| 全篇预分析 | 主题、受众、语气、术语、隐喻、结构难点 | 长文、发布型、深度审校 | 不替代译文，不扩写事实 |
| 会话级术语表 | `sense` + `scope` + authority/status | 多段文章、术语反复出现 | 不自动写入全局词库 |
| 挑战清单 | 条件链、长句、隐喻、文化指涉、理解缺口 | 分析深度为 `standard/deep` | 只记录会改变翻译决策的难点 |
| 分段一致性 | 按标题、段落、列表、表格、代码块边界处理 | 长文或 `chunk_policy: auto/required` | 不在保护区内任意切断 |
| 分阶段复核 | 保真初译 -> 技术复核 -> 编辑润色 -> 发布复核 | `polished/publication` | 技术问题未闭环不得润色掩盖 |
| 主体与说明分离 | 译文主体单独判断，说明区只披露证据 | 有译注、审校说明或多版本建议 | 说明不能冒充译文，也不能替代译文 |
| 图片语言提醒 | 从图片引用识别可能的文字型图片 | `image_text_policy: remind/review` | 无图像证据不断言图片文字内容 |
| 冲突产物保护 | 新文件或显式写回前先快照；已有结果不静默覆盖 | 本地文件、持久化产物 | 不移植强制备份重命名或自动 URL 抓取 |

## 翻译决策顺序

```text
源文事实与逻辑
  -> 保护区和结构
  -> 术语义项与范围
  -> 语气、隐喻和读者理解
  -> 保真初译
  -> 技术复核
  -> 受控中文重写
  -> 发布前编辑检查
```

“Rewrite, not translate”只在通过保真初译和技术复核后生效；它表示用自然中文重写表达，不表示自由增删或替换技术事实。

## 说明和候选表达

- 最终交付默认只保留一个主译文；候选译法只有在用户要求比较或原文存在未决歧义时才列出。
- 译注应简短、必要且与译文分区；不能用译注中的原文摘引满足正文保真断言。
- 官方运营文风优化节奏和可读性，但不把建议升级为承诺、不把可能升级为确定、不把隐喻解释成新事实。
