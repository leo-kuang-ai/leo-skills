# 完整 Humanizer 模式

用于完整模式审查、英文文本、量化线索或用户显式要求 `detect/rewrite/edit` 与多轮收敛。模式用于发现编辑问题，不用于证明作者身份。

先区分两件事：detector 估计文本与某训练分布的相似程度；editor 判断文本在当前体裁、作者和读者关系中是否有效。检测结果只能为编辑提供定位线索，不能决定改不改，也不能承担文章价值、事实或声音质量。

## 模式族

本文件是模式族概览。用户请求完整模式审查（当前 55 类）时，必须继续读取 [humanizer-pattern-catalog.md](humanizer-pattern-catalog.md)，逐项检查与报告；只读本文件时不得声称已完成完整模式审查。

完整模式审查的每条命中必须同时输出 catalog 中的 canonical pattern ID（如 `P34`）和名称；只写自然语言名称不算完成逐项目录审查。

### 内容 P1-P8

意义膨胀、知名媒体堆砌、虚假深度的分词尾句、宣传语言、模糊归因、公式化「挑战与展望」、AI 高频词簇、为避免简单系词而绕写。

### 语言与风格 P9-P18

否定式排比、强制三段式、同义词轮换、伪范围、破折号过密、格式强调过密、列表替代文章、标题大小写模板、引号/标点设备痕迹、过度正式语域。

### 沟通残留 P19-P21

助手话术、知识截止免责声明、讨好式开头。

### 填充与谨慎 P22-P30

空转短语、叠加限定、通用积极结尾、疑似幻觉标记、完美语法与低级错误交替、问句式标题模板、Markdown 泄漏、综合概述式开头、句长过度均匀。

### 新兴模式 P31-P43

名词短语轮换、协作对话泄漏、未填占位符、模型引用标记泄漏、AI 来源 UTM、语域突变、来源列表冒充论证、段落可互换、Whether/总结式段尾、象征意义硬解释、营销式悬念钩子、随机粗体、低信息跑步机效应。

### Craft 与取证 P44-P55

抽象对象虚假行动者、远距离叙述者、围绕改动历史而非当前状态写作、复合词连字符过密、假深刻格言、碎片标题后复述、无主体被动句、推理脚手架泄漏、Unicode 隐形字符/同形字符混淆、含糊枚举式开头、回应不存在反方的论证残留、与结论冲突的遗留限定词。

完整模式编号来自 2026-08-26 读取的上游版本，未来可能漂移。维护时以当前上游定义重新核对目录、触发和保护边界，不能只修改数量。

## 操作模式

- `detect`：只列模式簇、准确位置、影响和建议，不改写。
- `rewrite`：冻结事实后整体改写，但只处理已诊断问题。
- `edit`：对指定文件做最小原地修改；需要明确写授权。

可选声音：`casual`、`professional`、`technical`、`warm`、`blunt`。用户档案或明确样本优先于命名声音；没有档案时这些只能作为临时语域。

可选用途：`essay`、`email`、`marketing`、`technical`、`general`。用途规则不能覆盖事实与渠道约束。

## 评分与迭代

用户要求评分时可给 0-100 的「AI 模板线索密度」，同时列出模式数、句长变化、黑名单词密度等组成线索。必须声明：同一模型自评会偏乐观，分数不能证明文本由 AI 或人类创作，也不能作为发布门禁。短于约 40 词的样本不评分。

英文常用的 whitespace token、MATTR、Flesch、perplexity 和句长阈值不能直接迁移到中文。中文最多报告按句读切分的描述性分布、四字格/连接词/结构密度和样本内前后差异；没有中文校准 fixture 时不输出“人类通常为 X、AI 通常为 Y”的阈值判断。

用户要求迭代时，最多执行 3 轮 `检测 -> 定点修改 -> 再检测`；没有实质模式簇或达到用户指定轮数即停止。不得为降低分数加入错别字、隐形字符、虚构细节、无意义节奏扰动或删除必要事实。

## 误报保护

- 单个词、破折号、三项列表、正式语气或低句长波动不足以形成 finding。
- 引语、标题、代码、示例和被批评的 AI 文本按语义保护，不改其中的命中词。
- 技术写作允许准确术语重复；不要为同义变化破坏术语一致性。
- 非母语、神经多样性、学术、法律和百科式中性文体可能自然规整，必须看内容与语言模式簇。
- 真实日期、金额、路径、姓名、测量数字、未解决情绪和作者有意的不规则应优先保护。
- 自动修复只用于语义风险低且可逆的项目，如助手残留、隐形字符或明确空转短语；主张、语气、主体、引语和段落结构必须由编辑审查。

## 判断顺序与聚集原则

任何候选命中先查豁免再定罪，按顺序过四道检查，任何一道成立即降为观察项或放过：

1. 语义保护：命中的词落在引语、标题、代码、示例或被批评的 AI 文本内。
2. 人味信号：难编的具体细节、未解决的矛盾心情、年代梗与「模型晚一年」表达、2022-11-30 之前完成的编辑（详见 [humanizer-pattern-catalog.md](humanizer-pattern-catalog.md) 的「误报保护与人味保留」）。
3. 渠道容忍：该模式在当前渠道本就合法（见下节）。
4. 聚集检查：同段落没有其他模式叠加时，弱模式不立案。

四道全过才立案；第三、四道成立的候选降为观察项，不进入 finding，供簇分析时回看。第一、二道成立的按语义保护放行，不改其中的命中词。

聚集是默认定罪标准：同一段落多个模式叠加才是强证据。单个破折号、单个三项列表、单次排比、一处完美语法、一个正式词各自不构成 finding；模式簇、文本位置和当前体裁三者共同支持才报告。清点时宁可漏掉一个弱模式，不靠堆叠弱模式凑成结论。（来源：humanizer，快照 2026-08-18）

## 渠道容忍

同一模式在不同渠道宽严不同；检测前先确定渠道，再按对应宽严执行。宽严三档：

- **从紧**：连边缘命中也报；空泛表达在这类渠道代价最高。
- **放宽**：提高命中阈值或降低优先级；模式仍可报，簇出现时照常处理。
- **跳过**：该渠道下此类是正确形式，不审。

### 中文渠道矩阵

七类中文渠道由 brief 的 `article_family` 与 `channel` 字段推导：

- 公众号长文 ≈ `newsletter-platform` 的平台长文分支；
- 知乎回答 ≈ `argument` / `evidence-explainer` 落在问答渠道；
- 技术博客 / Reference ≈ `tutorial`、`how-to`、`technical-reference`、`technical-explanation`；
- 产品营销文案 = `marketing-copy`，正式报告 = `formal-report`；
- 口播稿 / 短视频文案、社交短帖无独立枚举，按 `channel` 字段或用户声明推导，缺省不猜。

|---|---|---|---|---|---|---|---|---|

### 英文渠道示例

英文渠道体系的中文表述示例：

- **社交短帖**：碎句与粗体钩子是语域常态，放宽；堆话题标签与宣传性收尾从紧。
- **技术博客**：术语准确重复豁免同义词轮换检查；「可能」是精确的不确定性而非对冲，对冲类检查放宽。
- **投资邮件**：高信任受众，宣传腔、通用结尾、意义膨胀从最紧——单个空泛搭配就能削弱整封邮件。
- **文档**：清晰优先于声音；列表、参数表与简洁被动句是正确形式，跳过；意义膨胀不因渠道放宽。
- **随意对话**：只清理助手残留与最严重的指纹，其余放过。

渠道无法从请求与文本判断时，按最严的通用长文渠道处理（中文场景按「公众号长文」行执行），并在报告中注明所选渠道与理由，用户可随时覆盖。渠道放宽的是检测宽严，不是事实与授权门禁。

中文渠道映射按文章家族与发布渠道字段推导，不直接套用英文渠道表；语域基线与体裁指纹的对应关系见 [chinese-editorial-protocol.md](chinese-editorial-protocol.md) 的「语域跟随体裁与渠道」与「公众号与平台体裁指纹」两节。矩阵方法参照 avoid-ai-writing 的 tolerance matrix，单元格宽严综合其规则表与中文协议体裁宽严改写（来源：avoid-ai-writing，快照 2026-08-30，非逐字摘录）。
