# 逐页内容母版（deck master）

> 本文档定义 generate 路线「逐页内容稿」的结构化形态。母版是内容层的唯一真值工件：
> 用户确认的对象、后续审查与修复的第一落点、以及 revision 与 diff 的锚。它不改变
> 五层质量门，只把「内容事实/叙事结构」两层的检查前移到最便宜的位置。

确认与等待统一按 SKILL.md 的协作方式：委托执行完成内部审查后可置
`confirmation: confirmed`，同时记录 `decision_source: user-delegated` 与
`decision_basis`；人工确认使用 `user-confirmed`。两者都不替代最终人工视觉验收。

## 为什么需要母版

成品图上发现内容问题（断言超源、要点无落位、引用错位）时，修复意味着整页重做；
同一问题在母版层修复只改一行文本，随后按已确认流程重建受影响页。审查与修复应尽
可能发生在母版上，而不是逐页产物上。

营销、销售或融资路演类演示在规划母版页职责与标题时，按需读取
[marketing-deck-narrative.md](marketing-deck-narrative.md)（11 页叙事框架、
买家角色增删与逐页任务约束）；该参考只管内容叙事，视觉风格仍走风格 brief 库。

## 母版结构（每页固定四段）

每页必须包含以下四段，缺任何一段都不得提交用户确认：

1. **结论句标题**：标题形态**按本 deck 的论证模式条件化**——`结论先行金字塔` 与
   未声明模式 = 完整句断言（先于正文可懂，不写话题词）；`中性简报` 允许
   主题词标题；`视觉展示` 允许唤起短语。三种形态在母版页首声明,同一 deck 不得无
   理由混用。
2. **要点**：按页面角色的**禅档位**取上限——陈述/氛围/金句页 0–1 条、论点/证据/
   方案页 ≤3 条、台账/账单/附录页 ≤6 条;每条 ≤2 行,每条只属于一个可复述任务。
   **零要点合法**：陈述/氛围页要点段可写「无」,视觉行声明「全幅图 + 一句断言」。
   **论断式第一条要点**：内容页（论点/证据/解释/方案/台账等承担论证任务的页）
   的第一条要点必须是**完整论断句**——主谓宾齐备、独立成句、不听讲解也能读懂
   的判断句;其后 1–2 条要点作为**证据跟随**（数字、图、引用,逐条带证据短标,
   四级词表与 source_ref 语法见「数字登记表」节）,
   不得只是论断的同义复述。**功能页豁免**：开场（封面）、目录、章节隔断、收束页
   的第一条要点不要求论断句（陈述/金句/呼应用途,角色词表对齐
   `styles/13_页面语义`）;零要点页合法跳过论断要求。
   **容量预检（定稿前）**：母版定稿前对要点行跑
   `python3 scripts/check_deck_geometry.py --capacity <母版/deck_spec JSON>`
   （输入含逐页 `layout` 与要点文本/条数）。**硬超页先降档（论点页 ≤3 → ≤2）
   或换版式,不缩字号、不省略号截断**——同级字号一致铁律与版心Canon 字阶
   刻度离散表优先于任何「塞下再说」冲动;软超（≤1.2×）以 WARN 行提示降档或
   换版式,不占退出码（三态与退出码语义见
   [layout-dispatch.md](layout-dispatch.md)）。
3. **视觉行**：该页容器清单（卡片/表格/图例条/结论条等），并声明**每个要点落入哪个
   容器**；存在无落位要点或无内容容器即失败。页面用图在此标注**来源三级**
   （实拍 / 生成-氛围 / 生成-示意，规则见通用设计规范图像铁律）。数据页数值按
   `../template-library/governance/authoring/index/图表样式规范.md` 置信度形状语法标注来源级。
   **风格约束摘抄**：`rendering_constraints` / `negative_prompt` /
   `visual_elements` 不在 `style render` 的机器注入键内（注入通道对照见
   [style-library.md](style-library.md)）；组页时须把所选 brief 的
   rendering_constraints 要点与 negative_prompt 词条**摘入该页视觉行**
   （约束一行 + 负面词条随图行或生成提示词携带），否则这些词表不进生图链路。
   **对照结构标记（dashi 集成 K3）**：双栏对照页必须在视觉行区显式声明
`对照侧: 标签｜标题｜要点；要点`（每侧一行，要点用全角分号分隔）；compare
类模板按声明数量硬校验（恰 2 侧合法，1/3 侧拒绝），无标记不猜结构——回
母版补齐标记后重编译。对照侧要点文本须与页面要点行文一致（去「要点 N：」
标签后逐字匹配），保证必需内容映射可对账。

**表格结构标记（dashi 集成 K6）**：台账/矩阵页在视觉行区显式声明
`表列: 列1,列2,列3`（一行，逗号分隔）与 `表行: 单元格｜单元格｜单元格`
（每行一条，全角竖线分隔，单元格数须与列数对齐）；spec-table 类模板按声明
物化 columns/rows，列数不对齐或只有单侧标记即校验失败，回母版补齐。四类
高价值任务（指标及基准差异/趋势及事件注释/决策矩阵/流程及责任分工）的承载
约定与 fixture 见 `tests/fixtures/dashi-integration/`。

**版式选择可由 `scripts/suggest_layout.py` 预打分**（四步链与打分口径见
   [layout-dispatch.md](layout-dispatch.md)；版式容量真值为
   `template-library/canonical/layouts/*/layout.json`（`layout-profile-v1`）可查，
   `"$LEO_PPT" style layouts` 返回同一份容量与复用字段）。
   **undecided 页固定呈现格式**：置信度 <0.5 的页在母版中标注
   `第 <页号> 页版式待定：候选 <P码A> 或 <P码B>，理由 <一行>`，在既有母版
   审查节点裁决；委托执行可给出有依据的选择，仍须容量预检和样张验证，不能把低置信度
   推荐当作已经验证。共创时等待用户选择，不新增确认门（CI-5）。
   **强视觉版式一 deck 一次**：P1/P9/P23/P24/P34/P36（`reuse_friendly=false`）
   全 deck 合计不超 canonical profile 声明的 `max_per_deck` 上限（P36 为 2，其余 1），
   定稿前跑 `python3 scripts/check_layout_reuse.py <deck_spec.json>` 机器复核。
   页面用图另按 [academic-figure-evidence.md](academic-figure-evidence.md) 逐图登记
   **图行**：`图[F<N>] 模式:<处理模式> 状态:<审查状态> 焦点:<该图回答的演示问题> |
   承载:<承载元素> | 服务:<服务的比较> | 避免误读:<要避免的误读>`;`figure_id`
   （`F<数字>`）deck 内唯一,模式/状态取值在该规则封闭枚举内。含图页缺图行、
   图行缺三段或枚举非法即校验失败;无图页不写图行——**向后兼容**：无图行母版合法。
   **图上文字协议（R-24）**：全出血封面/大图井页面的视觉行必须额外声明
   **文字落位区**（安静区横/竖带）与**主体映射**（读图标注人脸/显著主体位置，
   文字只进安全区）并注入生成提示词；判据与四步降级协议见
   [image-text-composition.md](image-text-composition.md)。
4. **备注**：拆分为两个子段——**`speaker_script`**（口播稿要点、预期听众疑问、
   停顿/互动指令、预计用时；最终进入 PPTX notes；语言纪律——短句口语/第二人称/
   禁套话/数字与母版一致——见「派发前合同校验」的确定性检测小节，
   `check_deck_prose.py` 机检 WARN）与 **`engineering`**（工程细则与
   失败路径；留在 run 工件，不上版面不进 notes）。两段不得混写。

页面级元信息置于页首，在既有字段（角色分类、事实来源、衔接、预计用时）之上新增：

- **`page_id`（稳定页身份，dashi 集成 K1）**：页首 `page_id: pg-<8-16 位十六进制>`
  行是跨 revision 保留的稳定身份，deck 内唯一；插入、删除或换序不得给未变化页
  重新编号，展示顺序仍由页块顺序（`S<N>`/`附` 标签）表达。身份**一次性写入**
  （legacy 母版先经 `runtime` `content_pack.propose_page_id_stamping` 提案补齐
  形成新的合法母版并确认），编译器不在每次运行时重发 ID；部分页携带身份即
  损坏母版（`check_master_contract` ⑬ FAIL）。`page-content-pack`（
  `<run>/input/page-content-pack.json`）是母版的单向派生物：绑定母版 revision、
  SHA256、编译器版本与内容摘要，同输入重编译摘要一致，手改内容包在校验时被拒；
  修改内容必须回母版。投影、来源 manifest、影响计算与升级 baseline 均使用
  同一 page_id 映射，文件名中的 slide/page 序号只是产物定位信息。
- **`argument_role`**：本页在论证模式中的角色（词表按所选模式取,如金字塔的
  结论/论据/数据;与页面角色「开场/问题/证据…」分列,前者管论证,后者管叙事位）。
- **`beat`**：叙事节拍（情境 / 张力 / 转折 / 回报 / 新常态,兼记「密 / 呼吸」）——
  说服型 deck 用它采样波形：what-is 与 what-could-be 应交替,连续 3 页同侧视为 P2,
  终点应是「新常态」页而非普通总结。
- **`audience_takeaway`**：一句话——听众此刻应获得/感受什么（受众是英雄,页面服务
  旅程）。
- **`rst_relation`（可选，advisory）**：本页与前页的 RST 关系码，取 8 关系封闭词表之一
  （`elaboration/explanation/context/purpose/evaluation/organization/joint/same-unit`，
  见 [`rst-paging.md`](rst-paging.md)）。仅作分页依据参考，**不进母版硬校验**；标
  `same-unit` 的内容必须整体一页，容量不足走降级顺序而非拆单元。确认摘要中呈现
  "分页依据"一句。

**deck 级合同块（deck-contract）**：学术场景（合同含论文/答辩/组会/文献汇报信号,
或选用科研答辩风格）的母版必须在文档头部（第一页之前）携带与内容合同一致的
deck 级合同锚点块,三字段为后续视觉审查的 rubric 锚点：

```text
deck-contract:
  math_load: medium
  figure_orientation: figure-first
  section_priority:
    | 节 | H/M/L | 页数 |
    | --- | --- | --- |
    | 方法 | H | 2 |
```

`math_load` 取值 light/medium/heavy（公式密度与推导深度,heavy = 页均含公式或含
推导链）;`figure_orientation` 取值 figure-first/balanced/text-first（图表取向,
驱动版式与页数倾向）;`section_priority` 为节级优先级页数表,高优先节多页、低优先
节压缩或并入,各节 Σ建议页数须与内容页数对账（不等即 WARN）。学术场景缺任一
字段即校验失败;通用 deck 可省略本块（不阻断）。学术场景按请求确定
交付档位：组会简报（minimal）还是答辩证据密集（dense-defense,见
`template-library/canonical/styles/research-defense/brief.json` 双档）——档位决定要点禅档位上限与版式密度,
无法可靠推断时再问，不得无依据默认取密集档。

## 数字登记表（数字元数据单源）

- 母版文档末尾附 `## 数字登记表`，每数字一行
  `| 数值 | 页 | 来源 | 口径 | 期间 | 单位 | 证据等级 | verified? | as-of |`（v2
  九列契约）；行业必填字段由该行业 `_content_rules.md` 声明（医疗加试验阶段/n/CI，
  政务加发布机关+年份，金融加基准期间）。
- **verified?** 封闭枚举：`yes`＝已对照来源原文核验；`no`＝来源在但核验未过
  （不得上稿,除非降级示意并经确认）；`open`＝待核验（上稿前必须闭环或降级）。
  **as-of**＝来源数据的截止日期或版本（ISO `YYYY-MM-DD` / `YYYY-MM` 或来源
  版本号）。`verified?=no` 且 `证据等级=引用` 直接 FAIL;校验器
  `check_number_ledger.py` 默认按 v2 九列校验,`--schema v1` 兼容旧七列并输出
  WARN（迁移期）。
- 要点内联标注四级短标：**引用 / 估算 / 示意 / 用户确认**（第四级 = 用户在
  合同或澄清轮口述的数据——原本只能错误挂「引用」或降 unknown，现可标注并
  溯源到会话轮）；完整元数据唯一落在登记表——"每条 ≤2 行"纪律不破坏。
- **引用级必须携带 source_ref**（要点可点验，不止"有出处"）：语法
  `【引用|src:材料锚点】`（材料段落锚点或 research-pack learning id），
  或等价的要点行尾 `[src:锚点]`；裸 `（引用）` 无 source_ref 由
  `check_master_contract.py` 判 FAIL。**用户确认级**不要求 source_ref，但行内
  必须带会话轮标记 `round:N`（如 `【用户确认|round:3】`）或说明字段
  （`note:一句说明`），否则 FAIL；估算/示意两级豁免；无标注要点不触发本判据
  （向后兼容）。数字登记表的证据等级枚举（引用/估算/示意）由
  `check_number_ledger.py` 独立治理，用户确认级数字在登记表「来源」列记
  「用户口述 round:N」。
- **执行者**：agent 从用户材料提取预填并自核对完备性；用户确认面只呈现缺字段/
  unknown **例外清单**，不审全表。
- 对比断言必带基准期间，无基准按编造阻断；统计图缺样本量/误差标注降级示意
  版式；单位制由合同声明，同一物理量全 deck 单位与量级一致。
- **请求金额测算行**：收束页/行动请求中出现的金额（预算、分期、gate 余额、
  分配额）必须有对应测算行——数值拆到可核参数或引用报价口径；无测算时显式
  标 `unknown` 并附补齐时限与 owner。裸估算金额进入请求页按内容层缺口处理，
  确认摘要必须披露并给补齐计划（与 image-deck-workflow 第 1 步金额测算纪律
  呼应；`check_master_contract` ⑫ 判据为机器子集）。

## 目录承诺表（deck-promises，可选）

- 含目录页 / agenda / 章节承诺的 deck，母版头部（第一页之前）可携带顶层
  `deck-promises:` 块（学术 deck 也可挂在 deck-contract 块内同名缩进子表），
  四列契约：`| 承诺 | 锚页 | 兑现页 | 状态 |`。
- **状态**封闭枚举：`open`＝已声明待兑现（组装前必须闭环）；`fulfilled`＝
  已在兑现页落地；`closed`＝经确认关闭，豁免锚页/兑现页核对。
- 校验器 `check_master_contract.py` 对每条 open/fulfilled 承诺核对：锚页与
  兑现页非空且在 deck 页集合内存在（接受 `S<N>`、页序数字或「附」）；目录
  多宣称一章（兑现页指向不存在的页）即 FAIL。无承诺表的旧母版本判据静默
  跳过（向后兼容）；有表且全过时校验器输出「承诺表 N 条核对通过」。
- 组装复验（image-deck-workflow 步骤 7）经本判据核对未兑现承诺，非 0 退出
  阻断交付。

```text
deck-promises:
  | 承诺 | 锚页 | 兑现页 | 状态 |
  | --- | --- | --- | --- |
  | 方法章将给出消融实验 | S2 | S5 | open |
  | 附录给出数据字典 | S2 | 附 | fulfilled |
  | 原计划的竞品对比已裁剪 | S2 | — | closed |
```

## 证据密度 advisory（大纲工件，可选）

- 大纲（`outline-v<N>.md`）每节可标注 `evidence_count`：材料中支撑该节的证据
  条数（材料段计数或 research-pack learnings 计数，agent 制作大纲时估算），
  与 `rst:` 分页标注同工件（见 [`rst-paging.md`](rst-paging.md)）。
- 密度判读：`evidence_count > 6` 提示该节**拆页或升台账版式**（证据量已超
  要点禅档位 ≤6 的容量）；`< 2` 提示**并入邻节**（证据不足，独立成节立不住）。
- 与禅档位（容量）、RST 关系（结构）构成页数分配的第三判据，让"这节给几页"
  从拍脑袋变成可解释决策。
- 本节为 advisory：寄生大纲确认回合——确认摘要呈现"证据密度"一句（如
  "方法节 evidence_count=9，拆 2 页"），不新增确认门，不进
  `check_master_contract.py` 硬校验。

## 节级验收标准与两段式大纲（大纲工件，advisory 可选）

- **节级 verify_standard（R-11）**：高保障档位制作大纲时，每节可标注
  `verify_standard:`——该节讲完听众应能回答的问题一行（如
  `verify_standard:听众能说出消融实验剔除了哪一路`）。母版完成后逐节
  自检：母版要点能否支撑该节问题的答案；答不上的节回母版补证据或并节。
  寄生大纲与母版确认回合呈现"节级验收"结论一句，不新增确认门。
- **两段式大纲留档（R-12）**：材料充足且制作大纲时，可先落「结构先验版」
  （同类 deck 常见骨架，来源记「结构先例」），再落「证据精炼版」（按
  材料证据修正）；两版与大纲同工件留在 `<project-root>/content/`，确认
  摘要附两版差异一句（如"结构先验 5 节，证据精炼并入 1 节：对比实验
  材料不足"），让大纲结构决策可解释，不新增确认门。

## 派发前合同校验（check_master_contract）

- 母版 confirmed 后、`image prepare` 前必须运行
  `python3 scripts/check_master_contract.py <母版文档>` 并附输出结论：
  四段完备 / 落位闭合（无点无家、悬空引用）/ 登记表在场 / argument_role /
  交叉引用页码存在；失败项回母版修复后重跑。
- 校验器同时输出**标题连读稿**（TITLE-READTHROUGH：全部结论句标题连读）与
  **要点连读稿**（TAKEAWAY-READTHROUGH：全部内容页第一条要点连读,功能页与
  零要点页不进连读）——连读不成故事线即打回母版，不在成品图上修补。
- 图行校验（模式/状态枚举合法、figure_id deck 内唯一、承载/服务/避免误读三段
  齐备、非 vision-reviewed 图行不得带位置性标注）与学术 deck-contract 块校验
  （三字段必填、section_priority Σ页数与内容页数对账）同为校验项;输出首行
  `MASTER-SCHEMA: v2` 标识母版机读语法版本（退出码 0 通过 / 1 FAIL / 2 仅 WARN）。
- 要点级标注校验（R-08/R-09）：引用级要点缺 source_ref、用户确认级缺会话轮
  标记即 FAIL（语法见「数字登记表」节）;估算/示意豁免，无标注要点不检查
  （向后兼容，旧母版零影响）。高保障档位另在母版冻结后、派发前跑
  `python3 scripts/check_content_facts.py <母版> <材料...>` 做数字断言与材料
  回读比对（内容核查官，见 [`image-deck-workflow.md`](image-deck-workflow.md)
  步骤 3c）。
- 连读稿复核时同步过一遍**标题与要点去模板味清单**（来源：human-writing
  `check_prose.py` + avoid-ai-writing `detector/patterns.js` 子集，快照 2026-08-30）：
  1. 标题禁翻案腔：「不是 X，而是 Y」「不在于 X 而在于 Y」式结论句标题，改为正面
     陈述（作者样本明确采用该风格时豁免）；
  2. 标题禁翻案腔变形：「X 不重要，重要的是 Y」「真正的 X 是 Y」「看似 X，其实 Y」；
  3. 标题禁三连同构排比：连读稿中连续三页标题同构句式（同一开头、同一节奏）即
     命中，留两项或第三项换写法；
  4. 标题禁名词化：「实现了效率的提升」→「效率提升了」，还原为直接的动词句；
  5. 标题禁黑话抬价：赋能 / 抓手 / 底层逻辑 / 全链路 / 闭环 / 降本增效 / 组合拳等，
     行业或品牌既定词除外；
  6. 标题禁空洞路标：「值得注意的是」「需要指出的是」「更微妙的是」类提示语
     不入标题；
  7. 要点禁裸名词短语堆叠：连续 ≥5 条无动词短语的 bullet（「稳定的挖矿效率 /
     可靠的矿池连接 / …」形状），合并成句或补动词；
  8. 要点禁抒情词装饰：安放 / 抵达 / 微光 / 滚烫类词给抽象概念穿衣服时删除；
  9. 要点连词密度：每千字连词（因为 / 所以 / 但是 / 同时 / 因此等）>7 处时删掉
     一半，小句靠语序与事理相接；
  10. 英文 deck：Title Case 标题滥用（非技术文档却每个实词大写）、em-dash 密度
      （每千词 >1 处且非列表分隔位）、AI 高频词（delve / leverage / seamless /
      robust / comprehensive / pivotal）；
  11. 句式均一：标题与要点长度过于接近、缺少长短差时，放开几句、压短几句；
  12. 豁免与级别：作者样本或品牌词表优先于本清单；命中项仅作 🟡 级修改建议随
      连读稿一并给出，不作为确认门阻断条件。
- runtime 侧 `image prepare` 不经手母版 markdown（slides.json 为其输入），
  校验归属 agent 合同层；`check_number_ledger` 的行级核对由本校验器触发。

### 确定性检测（check_deck_prose，R-15 / R-16）

- **调用时机**：母版落盘后、提交用户确认呈现前运行
  `python3 scripts/check_deck_prose.py <母版文档>`（与连读稿复核同轮；可加
  `--json` 机读、`--allow 词表` 豁免行业既定词、`--style-sample 样本文件`
  让用户文风高频词豁免词表类检测）。检测九族：翻案腔及变体 /
  黑话词表 / 名词化信号 / 三连同构开头 / 连词密度 / 格式子集（中英空格、
  全角标点、数字单位写法），外加 speaker_script 讲稿纪律。
- **判读规则**：WARN 项随确认摘要一并呈现并说明取舍，不阻断；**FAIL**
  （唯一硬项：翻案腔 deck 级计 ≥2 处）回母版改为正面陈述后重跑，不在成品
  图上修补。退出码 0 干净 / 1 翻案腔超限 / 2 用法或解析错误。
- **密度/豁免框架**（聚集才定罪，防误杀）：单处孤立命中在要点 ≤3 的页不计；
  黑话同页 ≥3 次或 `--allow` 命中按行业既定词豁免；唯一翻案腔命中须为真实
  论证骨架并在该行尾注明 `（豁免：论证骨架）`。
- **讲稿纪律**（speaker_script 段，讲稿导出 `export_speaker_notes.py
  --prose-check` 同源检测，WARN 不阻断导出）：① 短句口语，>40 字拆句；
  ② 第二人称直说，「你」优先，禁「大家」通知腔（「大家好」问候除外）；
  ③ 禁「接下来我将 / 值得注意的是 / 综上所述」式开场收尾套话；
  ④ 数字与结论与母版一致，不得口头加码。
- **措辞纪律族（h，R-17）**：WARN——要点以「这说明 / 这意味着 / 由此可见 /
  不难看出」开头、要点含「大家」通知腔（金句 / 氛围页加重）、非常 / 十分 /
  极其 + 形容词同页 ≥2 处；回母版把要点改回断言句后重跑，不阻断。
- **标题兑现族（i，R-18）**：标题数字不在本页数字登记表数值集合 → WARN，
  回母版对账（标题改口或补登记行）后重跑；母版无数字登记表时该族跳过。
- **论证媒介族（j，R-21）**：连续 3 个内容页同为纯数据论证（argument_role
  声明数据/证据，或数字要点占比 ≥60%）或纯定性论证（零数字要点）→ WARN，
  提示换媒介（类比/案例/反例）；混合型不触发。
- **金句判据族（k，R-22）**：金句/氛围页要点为口号模式（无数字、无证据
  短标、词表命中的抽象短语）→ WARN，重写为具体洞见；「A 即是 B」式反向
  克制型金句 deck 级 >1 → WARN（「脱离上下文独立成立」的语义判断归评测
  judge，本族只做确定性子集）。
- **要点模糊词族（l，R-23）**：学术母版（deck-contract 块在场）要点含
  显著/先进/有效/鲁棒 且同行无量化条件（数字/百分比/对照基线）→ WARN，
  替换为测量条件；引号内、示意级标注、`--style-sample` 文风样本高频词
  豁免；非学术母版该族 INFO 跳过（交付档案 `style_sample` 字段即
  `--style-sample` 的样本来源，R-20）。
- **AI 腔英文套话族（m，R-27）**：标题/要点整短语命中 dive into /
  explore / let's / journey 词边界（词表来源 baoyu-slide-deck base-prompt
  禁用清单，MIT 快照 6b7a2e4 2026-07-03）→ WARN，换回具体动作或直陈句；引号内专名
  （如「Customer Journey Map」）、`--allow`、`--style-sample` 高频词豁免；
  不阻断，随确认摘要说明取舍。
- **登记表 diff 判读（R-19）**：TF-1 减法重生成后跑
  `python3 scripts/check_number_ledger.py --diff <旧母版> <新母版>`——exit 1
  （verified?=yes 行按 数值×页×口径 键消失）即数字性证据静默丢失，须显式
  降级示意或经用户确认后重跑通过；INFO 行（新增 / 数值变化）随修订摘要
  如实呈现。

## 交付档位（加固 WS4，可选字段）

母版头部可声明 `delivery_tier: minimal | standard | assured`（缺省 standard，
非法值 FAIL）：

- `minimal`（≤8 页/内部）：五层质量门与诚实红线不减，确认点允许合并
  （合同+大纲同轮呈现）；样张以 user-delegated 为默认决策来源。
- `standard`：现行全部门禁。
- `assured`（融资/合规/答辩）：现行门禁 + 双评审官档 + 逐页 QA 留忍。

档位只做减法到 minimal 的确认交互；任何档位的门禁集合变更须引用
backend_stats/缺陷账本数据（证据驱动减门）。

## 母版纪律

- 母版确认发生在视觉方向确认之前或同时；未确认母版不得进入样张与批量生成。
- 确认对象为文档本体：四段完整性以 `<project-root>/content/` 下的母版文档
  （`deck-master-v<N>.md`）为判定载体，聊天仅引用路径与变更摘要，不整篇复述。
- **候选过期（R-45）**：基线 confirmed 后，低于该版本的候选工件（大纲/母版旧版，及头部记 `baseline: vM` 的风格候选与双样张落选方向）经 `scripts/expire_candidates.py` 登记 `content/expired-candidates.json` 标 expired，防误引。
- **决策账本（R-44）**：风格/版式/结构决策发生时当场
  `python3 scripts/decision_log.py add "决策" --reason … --risk … --alt …` 记档于
  项目 content/decision-log.md（风险必填）；多轮改稿回复用
  `decision_log.py cite D-00N` 引用既有决策，不重新论证。
- **减法审计**：母版提交确认前逐页过一遍「删掉哪一条这页仍成立?」——答案非空即必
  删;deck 级问「哪几页可合并为一张大图 + 一句断言?」。**第二问——不读原材料,
  只看这页成品,听众能否获得本页声称的结论?** 若这页拿掉原文就立不住,说明它只是
  原文的截图而非论证,回母版重写或降为附录用图。两问均为 agent 自检与确认摘要
  呈现项,不做确定性校验（语义判断归评测 judge）。减法发生在母版层,不在成品图上。
- **反方与边界承载**：内容合同的 `strongest_objection` 与
  `invalidation_triggers` 必须在母版中有显式承载——独立边界页（页面角色
  「边界」或 `argument_role`「反方」）或收束页前的显式要点；确无反方时写
  「无已知反方+检索依据」。受众为评审机构/委员会时，承载须含一条程序性
  反方（决策权归属/委员会角色/被架空的感知）及其处置（会前对齐、决议模板
  双签等）。仅有支持性证据链、无任何反方承载的 deck 在确认摘要中按内容层
  缺口披露（`check_master_contract` ⑪ 判据为机器子集，标题/口播提及不计）。
- **护栏最小完备**：收束页与认错/失效线的每个动作项（请求、验证、监控）
  必须携带 owner 与时限；验证类动作必须附交付物定义（可核实输出物）及其
  验收标准（样本量/覆盖率/阈值类可核条件）与验收人；共享执行资源的动作项
  须核对并行冲突；每条失效触发附一句分支预案（触发后的替代路线）。无交付
  物的「持续加强/保持关注」表述不得充当动作项。压缩/引用场景下 owner、
  时限与验收标准随内容同行，不得只存在于合同。
- **跨工件引用与移位自包含**：标题或要点引用其他 deck/评审/报告的结论时，
  同行附一行推导或原文路径（工件名+节名）；内容因分级、压缩或改版而移位
  （进登记表/备注/另一版本）时，目标工件须自包含该内容或附路径+节名+一句
  内容摘要——只引用结论不附依据、移位后在本工件不可见，均视为证据断链。
- **故事/组织证据边界**：创业故事、至暗时刻等叙事证据只承载动机与团队
  信任，不支撑市场判断——判断句标题与市场结论不得建立在故事证据上；
  二者的分界（组织证据 vs 市场证据）在母版备注声明一句。
- 数字与断言按三级标注（引用/估算/示意，见 workflow 第 1 步）；示意项不得声明使用
  图表版式;估算项进量化图形必须带形状语法。
- 若合同约定版面固定件（页码/页脚/署名位），母版视觉行必须写明其位置与字号。
- **结构页纪律**：封面页与收尾页在母版中以显式页面存在（页面角色「开场/收束」）;
  合同按卡片口径（≤2 页）执行时,唯一卡片兼任开场、不设独立结构页;
  合同口径为去尾页时,末页备注须声明其承担收束职能（回扣 `one_thing`）,
  结构页可省、叙事闭环不可省。
- 页内文本引用（「见第 X 页」「见附录」）必须在母版中与实际页码核对存在。
- **与 slide-worker 分镜合同对接**：母版一旦确认即锁定全 deck 风格锚定（视觉
  方向 + 样张 + 母版视觉行，逐页不得漂移）与图上文字量模式（detailed / slides，
  母版未声明时默认 slides 精简档）；母版页数即分镜页数，与内容合同口径完全一致
  （「恰好 N 页」语义），派生的 slide job 不得增页、并页或漏页。

## 修复回路

- 视觉门或内容门打回后，**先修母版、再重建受影响页**；只在 worker prompt 层打补丁
  而不改母版，视为绕过母版真值。
- 母版文档自提交确认前即存在于 `<project-root>/content/`（`deck-master-v<N>.md`），
  run 创建时随冻结输入归档并参与 artifact revision：母版变更即触发受影响页重验。
  确认后的修订（3a 写回、QA 修复）在文档层产出新版本并登记
  `revision_kind: post-confirm`；页数或结构变化退回 pending 重新确认。
- 重做后再检必须覆盖「目标判据 + 波及面」（见
  [`visual-qa.md`](visual-qa.md) 流程第 4 步）。
